# v1.3.2 Ubuntu Docker deployment

Source: `v1.3.2`, commit `9596b25eda507ef708a327feb5271f238cdfdc0b`.
Worktree: `/home/quant/repos/market-watch-deploy-v1.3.2`.
Branch: `deploy/v1.3.2`.

Deployed on 2026-10-02 to the existing Ubuntu Compose project
`market-watch-dual-acceptance`. Main entry: **https://localhost:15453**;
isolated chart origin: **https://127.0.0.1:15454**. API, all three chart workers,
web and chart-origin use newly built v1.3.2 images. The existing TLS base image
is retained. Exact image IDs and checks are in [the deployment manifest](v1.3.2-local.json).

The existing `market_watch_dual` PostgreSQL 16 database was backed up after
stopping this project's API and workers. The backup was actually restored into
a temporary database and checked: n15 schema, 120,035 published bars and 550
advanced workspaces. The temporary database was removed. The private backup is
in this worktree's ignored `backups/` directory, with permissions 0600.

The new image migrated the database from `n15_provider_revisions` to
`o16_managed_revisions`; published row count was preserved and 120,035 bounded
reconciliation jobs were seeded. API readiness passed. Real-browser verification
passed HTTPS login, Binance/OANDA provider charts, persistent provider cache,
managed charts and historical reload with unchanged spacing and viewport.
The managed endpoint returns revision fingerprints. There were no browser
errors or credentials sent to the chart origin. Test-created workspaces were
removed. All 38 installed Python runtime modules match the fixed source.

This is deployment verification, not renewed performance acceptance: the two
provider page-to-ready measurements were 6.517s and 4.354s. No new sub-3s claim
or full performance A/B is made. Notification delivery remains disabled; other
Ubuntu experiment projects and Unraid production remain on their existing versions.

The build configuration creates new versioned images with source labels.
Set `VITE_ADVANCED_CHART_ORIGIN` to the target chart origin, then run from
this worktree:

```bash
docker compose --project-directory . -f deploy/releases/v1.3.2-build.yaml config --quiet
docker compose --project-directory . -f deploy/releases/v1.3.2-build.yaml build
```

Start the fixed local version from this worktree (use `sg docker -c '...'`
if the current shell has not refreshed its Docker group):

```bash
docker compose --env-file deploy/releases/v1.3.2-local.env \
  -p market-watch-dual-acceptance \
  -f compose.acceptance.yaml -f compose.dual-acceptance.yaml \
  -f deploy/releases/v1.3.2-local.yaml up -d --no-build --wait
```

API and worker pools each retain one database connection and zero overflow.
The local overlay corrects the old fixture's public URL to port 15453 and
disables registry pulls. web/TLS were restarted after recreation to refresh
upstream addresses. `/tmp/mw-dual-acceptance/compose.env` also selects the new
images; ongoing operations should use the worktree command above.

Rollback image selection and the previous runtime inventory are retained.
Old v1.3.0 images require schema alignment: stop writers and review the o16
downgrade or an explicitly approved data restore before rollback. A database
restore would discard changes after the backup; it is not a routine restart.

Private credentials and self-signed TLS fixtures remain in
`/tmp/mw-dual-acceptance`; preserve or regenerate them after temporary-directory
cleanup. No production credentials or private database contents are committed.

Licensed chart assets are copied from the existing advanced worktree into
the ignored `advanced-host/charting_library/` directory for local builds;
they are not committed to Git.
