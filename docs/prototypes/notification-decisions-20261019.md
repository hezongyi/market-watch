# 通知调整：已确认与待确认项

这些是后续统一实施的输入；用户明确要求确认后统一接入。当前实现分支与验收实例的通知业务没有应用本轮变更。用户随后要求先提供可直接接入的预览页：已在独立分支开发共享展示组件，使用内存样例数据，仍未接入正式业务。

## 用户已确认：消息优先级与确认规则

- 系统消息和交易告警共用顶部居中一个原生外壳；不自动抢焦点、无背景遮罩、不改变图表尺寸，浮窗本身覆盖区域接收交互。
- 系统消息按现有 8 秒显示规则消失，悬停或操作时暂停；交易告警持续显示，必须主动点击“确定”。查看图表、查看告警记录不算确认，不停止手机提醒。
- 交易告警 A 未确认时，新交易告警 B 排队；A 不被替换，显示另外待确认数。每次确认仅处理当前条目。
- 交易告警等待期间的系统消息正常进入系统通知中心并更新未读数，不替换告警，不延后集中补弹。
- 系统消息显示期间来交易告警，立即切换为交易告警；原系统消息保留在中心，不再补弹。
- 待确认告警需持久恢复，不因旧队列 30 秒过期、容量限制或页面刷新而遗漏；同一事件去重，不同触发保留。
- 系统消息查询只在通知中心；交易告警查询只在现有右侧告警/日志模块。

## 用户已确认：右上角系统消息入口方案 A

用户选定 A 角标型：使用先前生成的同一系统消息 SVG，右上角叠加红色数字角标；常态不显示“系统消息”文字，悬停提示和可访问名称提供含义及完整数量。沿用现有工具栏位置、行高和图标风格，不新增工具栏行。

数字仅为系统消息未读数，不包含交易告警。0 隐藏数字，超过 99 显示 99+；入口预留固定宽度（预览为 52px），避免数字变化引起工具栏跳动。点击后打开既有系统消息通知中心，关闭后仍遵守非模态焦点规则。

用户再次明确“先写入方案，先不实施”。A 已进入本轮共享组件预览，但尚未替换当前验收界面；B / C 保留为历史比较材料，不进入实施范围。

已完成当前实现与复用接缝分析，见 [面板原生组件分析](system-message-panel-native-analysis-20261019.md)。推荐原生底层 Dialog + DialogSearch + NavButton，继续使用已接入的原生 Select、Checkbox、Button 和 PopupMenu；业务消息行与详情保留应用渲染。

用户要求“先做预览页，查看后确认；后续能直接接入，预览与实现一致”。据此提供[共享组件预览与接入说明](system-message-panel-20261019/README.md)。待用户确认的是实际界面与交互；展示组件已经开发，正式传输、通知调度、持久化和生产部署均未接入或改变。

用户随后补充：搜索框打开时不自动聚焦；使用图表原生细滚动条；不用分页栏，改成滚动加载。上述要求已进入同一份共享展示组件与预览，仍等待用户确认整个界面后统一接入。
