# A07 看图打磨记录

本轮沿用 A06，不开展新的方向选择。使用本机 Node Playwright + 已有 Chromium 截图；没有启动服务或部署实例。

## 原稿检查

亲自查看 `a06-watch.png`、`a04-create.png`、`a06-center.png`，对照原始 CSS/JS。

最影响观感的三处：

1. 自选启动告警浮层盖住首条行情；价格/代码字重层级偏弱。
2. 数据卡片重复说明占高，代码和名称挤在同一强度。
3. 表单选择框、模式按钮、开关、错误反馈的外观不统一。

## 第一轮（`evidence/round1-*.png`）

已看：自选、图表、告警、数据、更多、新建告警、浅色表单、提交失败、空列表。

最伤三处与修正：

1. 选择器当前值继承旧 `.field span` 次级文字颜色/边距，像禁用项。为实际选值独立设置颜色、字号与行高。
2. 数据卡片仍有过多纵向占用，首屏仅三条。名称改为同行的次级信息，缩短重复间隔；最终 412px 视口可见四条完整目录记录。
3. 图表 SVG 在加入报价后依旧用旧可用高度，形成多余边距和小轴字。调整示意图可用高度、绘制比例与轴字号。

同时收紧错误反馈布局，把详情说明与主操作分清。

## 第二轮（`evidence/round2-*.png`）

已看：新建告警、数据、图表、失败反馈，并检查第一轮其它屏。

最伤三处与修正：

1. 弹层自动聚焦关闭按钮/标题产生突兀焦点框。入口聚焦标题供读屏宣告，仅隐藏非交互标题焦点框；可操作控件保留键盘焦点样式。
2. 浅色来源文字叠加 0.85 透明度，对比度约 4.3。去掉透明度；表单说明恢复 14px 正文，处理旧 rem 舍入使标签达到 12px。
3. 375px 下旧容器查询把双字段过早拆成两行。让普通小屏保留双列，150% 字号时才重排；通知出现时为第一条行情预留空间。

## 最终复核

查看最终主屏、浅色表单、大字号六屏，以及搜索、分组、管理、详情、事件、来源、指标、离线、首次加载、无缓存、失败、冲突、能力限制、放弃编辑、会话过期、浮动通知。

- `evidence/browser-proof.json`：18 项真实交互断言、60 组布局检查、27 个弹窗/状态截图；0 页面异常、0 HTTP(S) 请求。
- 布局：375×812、412×892、892×412、375×540，均测深浅主题；375px 的 150% 字号另测六屏双主题。
- 在 375×480 的缩小可视区完成输入和提交，用于检查键盘占用空间时主操作可达；这不替代 Android 真机软键盘验收。
- `evidence/design-lint-node.json`：18 个深浅主题主屏/表单/状态的文字和对比度采集，最终无小字号/正文过小/对比度失败。原脚本会误扫模态遮罩后的页面和关闭的 details，Node 采集只检查活动模态与可见节点。
- 原 skill 的 `design_lint.py check` 与 `ledger add` 均调用过，但因缺 Python Playwright 跳过。改用相同 `COLLECT_JS` 的 Node 执行及原脚本的色板/指纹函数，已记录本机外观账本。`learn.py harvest` 已执行；不把自己的判断记为用户认可。
- 中点分隔用于继承的来源/系列/状态元信息，系统字体为既有冻结规范，均按项目约束保留。

对照：`evidence/before-after.png` 是相同视口中的 A06/A07；`evidence/polish-first-last.png` 是第一轮/最终表单。`baseline.html` 只为同视口对照添加外壳，不修改原冻结目录。
