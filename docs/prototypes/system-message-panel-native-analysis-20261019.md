# 系统消息面板：当前组件与原生替换分析

状态：面板替换建议已有[共享组件预览](system-message-panel-20261019/README.md)，等待用户查看确认。入口 A 已确认。预览使用后续接入的同一份展示源码和内存样例数据；当前验收应用及通知业务未切换。

## 当前实现

实际面板不是图表库提供的一整套通知中心。`web/src/notifications/native.tsx` 以 `createPortal` 把 `<div class="nc-popup" role="dialog" aria-modal="false">` 和 `NoticePanel` 挂到图表 iframe 的 document.body；通过原生工具栏入口位置计算右上角定位、可用高度和视口边距。没有注册 widgetbar page，不参与图表排版。`notifications.css` 中 `.nc-popup` 宽约 400px，高度上限 590px。

`web/src/notifications/Panel.tsx` 管理列表、搜索、筛选、详情、设置和已读等业务状态。标题栏、返回/关闭/设置图标按钮、消息行、日期分组、详情布局和分页外观由应用渲染；图标来自 lucide-react。搜索是自定义 Search 图标搭配 AlertInput，不是 DialogSearch。

已有真实原生控件复用：

| 界面部分 | 当前组件与接缝 |
| --- | --- |
| 搜索输入与其他输入 | AlertInput → NativeControl → 图表 InputControl |
| 来源/级别筛选 | AlertSelect → 图表 Select |
| 系统提示设置开关 | AlertCheckbox → 图表 Checkbox |
| 主要操作与分页按钮 | AlertButton → 图表 Button |
| 更多操作/筛选菜单 | AlertMenu → 图表 PopupMenu、PopupMenuItem、PopupMenuSeparator |

上述通过 `NativeControls.Provider` 和 `native-alert-shell.js` 的固定版本 control 工厂挂载，属于内部原生组件复用。原生适配不可用时会使用应用 HTML 控件回退。

**当前焦点行为须区分场景：**被动即时通知不自动聚焦；主动打开系统消息中心时，NoticePanel 有 `closeButton.current?.focus()`，会把焦点放到关闭按钮。它没有完整模态焦点陷阱，不能把当前行为表述为“整个通知中心从不移动焦点”。数据刷新本身不应反复执行该初始化焦点动作。

## 可替换范围与推荐

| 部分 | 建议 | 依据与边界 |
| --- | --- | --- |
| 右上角面板外壳 | 用原生底层 Dialog 替换自定义表面 | 前轮即时通知原型已实际挂载 Dialog（491617），验证无背景遮罩、无自动聚焦、无图表尺寸变化；本面板完整组合仍需专项预览和验证 |
| 关闭、返回、设置、更多触发图标按钮 | 使用原生 NavButton 或相应原生图标按钮 | 前轮已验证 NavButton；按钮图标和行为由应用传入，保持单一标题栏，不叠加原生标题栏与自定义标题栏 |
| 搜索 | 使用原生 DialogSearch | `advanced-host/native-ui.js` 已对接，早期研究有实际独立挂载和受控输入验证；通知专用接缝应最小化加载依赖，不为一个搜索框初始化整套品种搜索或数据中心 |
| 下拉筛选、设置项、动作按钮和更多菜单 | 保留现有真实原生 Select、Checkbox、Button、PopupMenu | 已有复用，无需重新实现；校正外壳颜色和布局后保持原生状态样式 |
| 消息列表、日期分组、未读点、重复次数、恢复状态、详情和证据 | 保留应用业务渲染，统一原生主题与间距 | 尚未发现/验证一个能直接承载本项目消息语义的完整原生消息中心组件。原生品种结果行、菜单项和告警日志有各自的选择、导航与数据上下文，不能因长得像列表就套用 |
| 定位、内滚动、点击外部关闭和 Escape 返回层级 | 保留薄的业务控制层 | 原生底层 Dialog 不是完整锚定通知面板，需要自己管理入口锚点、视口边界、层级、焦点返回及菜单例外 |

建议结构：

```text
工具栏 A：系统消息 SVG + 未读角标
  └─ 右上角原生 Dialog（非模态、无背景遮罩）
      ├─ 标题、未读数量、原生图标按钮
      ├─ 原生 DialogSearch + 筛选菜单
      └─ 应用消息列表 / 同一面板内的详情 / 设置
```

推荐保留当前位置和面板内切换，不打开新的中央窗口，不新增右侧栏，不替换或收起自选表、不调整图表画布。

## 不建议直接使用的候选

- **公开 showNoticeDialog / 内部 SimpleDialog：**适用于标题、正文和确认动作。当前构建的 SimpleDialog 使用 autofocus:true、fixedBody:true，公开参数也不能表达带搜索/分页/详情的通知中心。不能直接改正文 DOM 就称为公开 API 支持。
- **PopupDialog / AdaptivePopupDialog 的默认包装：**适合主动模态编辑。当前构建存在默认 Portal 焦点约束、聚焦和页面固定行为，窄屏自适应也可能转全屏。仅设置 backdrop:false 或 autofocus:false 不足以证明它满足现有非模态合同；推荐直接用已验证的底层 Dialog，避免依赖这些默认策略。
- **PopupMenu 承载整个中心：**保留给“更多”和筛选等短操作菜单；搜索、滚动消息、详情和分页不应全部变成菜单项。底层是否能配置其他角色不是整套通知中心语义和交互已验证的证据。
- **原生 widgetbar 侧栏页面：**会影响自选表和图表可用区域，与用户已确认的不改变布局要求冲突。

## 焦点与关闭建议（待确认）

- 新系统消息到达：只更新数据/角标，不自动打开中心，不移动焦点。
- 鼠标点击 A 打开：不自动跳到搜索框；可以让焦点留在入口。键盘打开：有意识地把焦点送入面板首个合适控件，支持完整键盘操作；没有焦点陷阱。
- 点击面板外图表/自选表：关闭中心且不吞掉这次点击，不将焦点抢回入口。显式关闭/Escape 返回时，按打开方式和当前焦点位置恢复焦点；不拦截卡片外的键盘事件。
- 已打开中心中的列表更新：保留滚动、详情选择和正在输入的搜索文字。交易告警即时浮窗与通知中心的视觉层级仍需预览确认，避免互相覆盖。

## 实施边界与验证要求

这里只建议组件替换，不重写可靠接收、投影、分页、事故聚合、阅读水位、手机投递或告警日志。原生组件属于固定 v31.1.0 内部接口，不是公开稳定的组件 SDK；继续集中到适配器、核对构建标识并保留失效回退，不修改许可库字节。

本轮按用户新指令完成消息中心的真实图表预览，再按用户统一实施指令接入。Playwriter 检查范围与实际结果见共享组件预览说明；正式接入时仍需验证回退互斥、多工作区生命周期、真实传输与即时浮窗共存。本轮只在 Ubuntu 本任务图表容器增加独立静态目录，没有更换当前验收应用或通知业务。

依据：当前 `native.tsx`、`Panel.tsx`、`notifications.css`、`NativeAlertControls.tsx`、`native-alert-shell.js`、`native-ui.js`；既有 `native-chart-ui-reuse-plan-20261009.md` 及其 probe/results；前轮 `native-instant-notice-20261019/browser-proof.json`。结论区分已有验证与拟组合方案，未把底层外壳验证当作完整面板验收。
