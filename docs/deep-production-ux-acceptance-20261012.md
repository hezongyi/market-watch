## 结论与优先级

P1表示当前关键操作受阻、应先处理；P2表示影响识别、判断或连续操作；P3表示低影响的信息表达问题。这里是使用验收优先级，不是漏洞评级。

| 编号 | 优先级 | 已确认问题 | 用户影响 |
| --- | --- | --- | --- |
| UX-06 | P1 | 手机首页被长行情 ID 撑宽，预警弹窗与提交按钮越界 | 手机上难以完成或取消预警操作 |
| UX-01 | P2 | 首页直接展示内部行情 ID，黄金／欧元使用比特币图标 | 同名行情身份不清，卡片难读 |
| UX-02 | P2 | 设置页将旧补数心跳泛化为历史后台故障 | 用户无法判断现行历史服务是否需要处理 |
| UX-04 | P2 | Dukascopy 苹果品种被归为“其他”，股票筛选隐藏结果 | 按类别检索时漏掉已有品种 |

## 已确认问题及修复验收条件

### UX-06：手机预警弹窗右侧和底部超出屏幕

**P1，响应式布局／关键功能可操作性。**

复现：390×844触摸浏览器登录，等待行情卡片载入，点击“新建预警”，再把弹窗滚动到最底部。独立375×812会话重复操作也出现相同问题。

首页 `MD:…:XAUUSD` 标题延伸至x=509，使布局 `innerWidth` 变为509，可视宽度仍是390。弹窗按扩大的布局居中，边界为x=73.5—435.5、y=171.2—930.8，超过390×844屏幕；关闭按钮右侧在x=406.5。弹窗滚到底后，“取消”和“开启监控”均在y=856—902，可视底部为844，提交按钮右侧也超过屏幕。

375px独立会话的可视区域准确为375×812，布局宽499，弹窗右侧423、底部905.9，排除了旋转／旧缩放状态的影响。只比较 `scrollWidth <= innerWidth` 会漏掉此问题，必须比较 `visualViewport`。

期望：行情文字在卡片内换行或省略；页面布局保持可视宽度，关闭按钮始终可见，弹窗内部滚动到底能触及全部提交操作。

修复验收：375、390、横屏分别使用真实长来源标识；断言弹窗和关闭／提交按钮在可视区域内，触摸完成一条草稿的编辑与取消；产品写入验证在Ubuntu隔离实例完成。

证据：[390px弹窗](verification/deep-production-ux-20261012/screenshots/phone-watch-390.png)、[滚到底后的裁切](verification/deep-production-ux-20261012/screenshots/phone-watch-footer-390.png)、[375px独立复验](verification/deep-production-ux-20261012/screenshots/phone-watch-375.png)、[测量数据](verification/deep-production-ux-20261012/measurements.json)。

### UX-01：首页行情名称使用内部 ID，图标与品种不符

**P2，行情身份与信息表达。**

复现：登录“行情与监控”，对比普通XAUUSD／EURUSD卡片与OANDA practice卡片；进入“提醒与设置”也能看到相同内部ID。桌面与手机均出现。

实际：OANDA卡片主标题是 `MD:…:XAUUSD`／`MD:…:EURUSD`，两者均显示 `₿`；普通卡片分别显示 `Au`／`€`。同名行情同时存在、价格略有差异，但内部标识占据主标题，手机还隐藏了部分来源说明。专业告警列表也存在以组合内部标识开头的旧默认名称。

期望：可读品种名为标题，来源、账户环境、Bid／Last等价格基准为次级信息；内部标识移到详情与复制功能。不要简单合并同名品种，它们可能有不同价格身份。

实现线索：`web/src/main.tsx` 直接展示 `i.id`，图标仅按 `EURUSD`／`XAUUSD` 与其他ID三分支选择。长标识也触发UX-06。

修复验收：普通、平台、自建与组合品种均能读出价格身份；黄金／外汇图标正确；375px长名称不撑宽页面；原行情绑定不改变。

证据：[桌面卡片](verification/deep-production-ux-20261012/screenshots/dashboard-identities.png)、[手机首页](verification/deep-production-ux-20261012/screenshots/phone-dashboard.png)。桌面截图中间的内部标识已遮盖，保留前缀、品种后缀与错误图标。

### UX-02：设置页用旧补数心跳提示当前历史后台故障

**P2，运行状态表达。**

复现：“提醒与设置” → “后台运行状态”。显示“历史补数后台状态：心跳过期，请检查服务”，最后心跳是2026/10/3；行情和通知心跳新鲜。

核对：页面读取 `/api/health` 的 `import_heartbeat`，写入方为 `backend/alerts/market.py` 的旧补数循环。正式历史相关容器实际运行 `alerts.history_versions --without-composite-aggregates`、`alerts.chart_history_worker` 与 `alerts.native_history_loads`，三者均running、零重启；数据中心能读取当日已发布历史任务。**容器运行不能证明所有历史链路健康，旧心跳也不能代表这些现行服务的健康。**

期望：明确区分兼容补数与现行历史发布／图表加载服务；未启用链路显示“未启用”或“兼容链路”，故障说明影响范围和可采取的操作。

修复验收：按现行worker身份展示心跳和任务进展；分别模拟停止现行／旧服务，页面准确对应；保留“状态接口可读”与“数据已就绪”的区别。

证据：[状态截图](verification/deep-production-ux-20261012/screenshots/legacy-heartbeat.png)。实现线索：`backend/alerts/api.py:395`、`backend/alerts/market.py:882`、`compose.production.yaml`。

### UX-04：Dukascopy 苹果品种无法通过股票分类找到

**P2，搜索与分类。**

复现：专业图表搜索或数据中心“平台行情”搜索 `AAPL`。全部结果有Yahoo AAPL、Dukascopy `AAPL.US/USD`、Yahoo `XAAPL=F`；点击“股票”后仅剩Yahoo AAPL。

实际：Dukascopy条目显示“其他”／`other`，在证券类检索中漏掉；默认目录多个港股／日股代码也落入“其他”。不能把股票、CFD与期货混为同一价格身份，应明确标注来源的具体产品类型。

期望：来源股票类品种有明确、可检索的证券分类，必要时标注股票CFD；分类不会隐藏用户合理期待的结果，来源、基准仍可区分。

实现线索：`backend/alerts/history_catalog.py:17` 的 `asset_class()` 只处理金属、外汇、加密、指数，其他返回 `other`；`backend/alerts/provider_dukascopy.py` 复用该分类。

修复验收：AAPL及代表性港股／日股的类别与来源元数据一致；类别、关键词、来源组合筛选正确，不影响期货等类别。

证据：[全部来源搜索](verification/deep-production-ux-20261012/screenshots/aapl-source-classes.png)、[股票筛选](verification/deep-production-ux-20261012/screenshots/aapl-stock-filter.png)。

### UX-05：交易日历出现无法区分的重复规则

**P2，适用范围与审核工作量表达。**

复现：数据中心 → “交易日历” → 搜索 `BTCUSDT`，展开两条规则。

实际：两条的品种、来源、版本、状态、环境／通道／价格基准、说明与官方依据完全相同，底部显示“待核实2”。后台 `row_id` 唯一，分别来自已登记品种与provider目录身份；界面没有显示这层区别。重复搜索和展开均如此。

期望：不同适用对象清楚标出“已登记”／“来源目录”及用途；语义相同的规则按适用身份合并显示，避免用户重复理解。

修复验收：BTCUSDT及同类OANDA品种能区分条目或合理分组；待核实数量与实际独立审核对象一致；保持身份匹配安全，不能为消除重复直接删除规则或把未核实改为已核实。

证据：[重复列表](verification/deep-production-ux-20261012/screenshots/calendar-duplicates.png)、[裁剪后的身份比对](verification/deep-production-ux-20261012/measurements.json)。实现线索：`web/src/market-data/CalendarView.tsx` 只渲染共同字段。

### UX-07：首页预警关闭后丢失键盘焦点

**P2，键盘可操作性。**

复现：键盘聚焦“新建预警”，Enter打开，Tab在表单内移动，然后Esc关闭；再用“取消”关闭重复检查。

实际：Tab保持在弹窗内，但两种关闭方式后 `document.activeElement` 都是 `BODY`，没有返回“新建预警”。专业告警通知子页和数据中心详情的Esc返回焦点正常。

期望：关闭后回到触发按钮；用户继续Tab能从原位置操作。关闭按钮、取消、Esc均一致。

实现线索：`web/src/main.tsx` 的 `WatchDialog` 调用 `showModal()`，关闭时由React直接移除，没有恢复触发控件焦点。

修复验收：鼠标、Enter、Space打开后分别Esc／取消／关闭，返回原按钮；屏幕阅读器保留明确对话框名称，连续打开两次也正确。

证据：[键盘测量](verification/deep-production-ux-20261012/measurements.json)。

### UX-03：指标和告警参数直接展示内部键名

**P3，参数可理解性。**

复现：添加MACD → “当前图表已添加”；再建“指标输出 → MACD”告警草稿。

实际：指标摘要是 `内置 · in_0=12 · in_1=26 · in_2=9`；告警草稿使用 `fast`、`slow`、`signal` 和输出值 `macd`。原生参数／样式窗口能打开并取消，问题是概览与核对表达不清。

期望：显示“快线周期12／慢线周期26／信号周期9”等可读标签，输出名称也可读；技术键名可留在高级详情。

修复验收：内置与Python指标用元数据标签显示参数；明确告警所用快照与图表参数是否一致，不能仅翻译文字而改变实际值。

证据：[指标参数截图](verification/deep-production-ux-20261012/screenshots/indicator-parameters.png)。实现线索：`advanced-host/native-indicator-dialog.js` 连接 `input.id=value`；`web/src/advanced/ChartAlertDialog.tsx` 直接显示参数对象键。
