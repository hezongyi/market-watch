执行入口：[统一标识与来源展示实施方案](../plans/pending/mobile-market-identification-20261115.md)。该方案汇总最新认可规则并优先于下文历史讨论；当前 App 待实施。

## 第四版分类规则（最新）

第四版补齐完整分类：股票市场、外汇、贵金属、股指、指数、期货、加密、ETF、基金、债券、期权、商品和待分类。代码旁仅一个彩色主标签，右侧以普通文字显示现货、永续、交割日期、主力连续、合约月份或 CFD。同族共用低饱和色系，未知类别使用中性标签。

创建表单结构与自选主列表保持第三版约束。展示分类与后端资产分组分开：不能将 FUND 一律显示 ETF，也不能将股指期货、指数 CFD 混作现金指数。完整长代码在详情保留；交割合约日期须在列表可辨。

## 第三版最新要求（优先于下文历史规则）

第三版按最新反馈：深A、沪A、外汇等市场使用轻量彩色标签；来源完整显示新浪财经、腾讯财经。创建设置沿用当前 App 表单结构，仅顶部品种信息同步添加自建的两行左右布局；自选主列表保持原样。

创建设置保留历史起点、维护周期、自动更新及折叠更多设置；第二版的顶层设置行不再采用。仅市场标签着色，供应商与价格口径保留普通文字。

## 最新反馈与第二版（覆盖下文冲突的初稿规则）

用户查看首版后要求两行、左右分层，指出标签密集、缺少阅读重点，并明确“添加后的自选页希望保持之前的，不修改”。第二版预览为 `mobile-market-identification-20261115/index.html`，首版保存在同目录 `preview-v1.html`。

- 添加自选：左上代码及轻量市场、左下中文名；右上供应商、右下价格口径及必要能力限制。取消标签底色，添加动作独占固定触摸区域。仅日线限制仍可见。同名自建在右侧补必要身份区别。
- 添加自建：相同两行布局，右侧供应商与必要环境；选来源时不预先显示复权、维护模式或实时承诺。空余位置不填冗余信息。
- 创建设置：顶部使用两行选中品种，删除配置标签串；历史模式、价格口径和日线划分改成字段名与当前值对齐的设置行，不能生成分时的限制就近说明。
- 数据列表：代码/市场一行，中文名/供应商一行，右侧实时开关及其状态。取消重复自建标签和规则标签；只有同名同源配置冲突时追加必要短差异，如 NY17 / UTC0。完整规则进入详情按字段核对。
- 自选主列表：撤销初稿的紧凑来源口径补充和身份排布改造，现有代码/中文/供应商三行、价格和 sparkline 全部不在本轮修改范围。预览仅保留现状示意。
- 下文原“统一三行”“自选来源行加口径”“创建顶部配置标签”是初稿历史，以上新版要求优先。身份、防重、真实性与搜索语义仍适用。

## 目标与边界

让添加自选、添加自建、创建设置、数据列表和详情对同一价格系列使用一致身份；用户在执行添加前能看出市场、来源、价格口径及重要能力限制。

保留单列表、模糊搜索、自动分页、添加到当前分组和成功后原位显示勾。不给用户增加常驻筛选、额外确认页或逐项技术配置。保留自选行高、固定左右列宽、sparkline 几何和采样。暂缓的自选实时状态装饰继续暂缓。

不合并不同来源、复权、账户环境、维护规则的价格系列；不自动替换现有自选。手机端展示字段可增补，网页端展示和获取策略不在本方案范围。

## 已核查的事实

- 当前工作树 `feat/managed-live-rollover-20261113`，HEAD `17af8e25`，有其他任务未提交修改，实施时保留。
- 真实 Ubuntu 实例搜索宁德时代返回六个不同 ticker：A 股新浪前复权/不复权、腾讯前复权/不复权，港股新浪前复权/腾讯不复权。
- 实际 DOM 有两对完全相同的文字：`300750 / 宁德时代 / 新浪（AKShare）`、腾讯同理。
- `instrument_directory.py` 按来源、代码和变体保留这些独立价格系列；并非同一个 ticker 被分页追加两次。
- 自选搜索响应已有 `price_basis_display`、`adjustment` 和 `capabilities.native_periods`，但 `DataPage.tsx` 只把代码、名称、来源传给 `SymbolInfo`。
- 添加自建走 `history-catalog/search`，选中的是来源产品；进入表单后才选择复权/维护模式。它与已确定口径的原生价格系列不一一对应。
- 自建目录已有 `source_display`，手机 `DataCatalogSheet.tsx` 却使用 `item.source`，创建头部也只用通用来源名，因此丢失新浪/腾讯等上游信息。
- 来源支持周期、按口径探测成功的周期、已发布的可用周期、实时接续能力和实时开关状态是不同事实，不能互推。

## 一、统一词汇：每种标识只回答一个问题

| 维度 | 回答的问题 | 简短显示 | 规则 |
| --- | --- | --- | --- |
| 品种 | 是什么 | 300750 / 宁德时代、EURUSD / 欧元美元 | 代码与简明名称分行，不从名称生成身份 |
| 市场与产品 | 在哪里、是什么合约 | 深A、沪A、港股、美股、现货、永续、主力连续、具体合约月 | 只按可靠元数据；CFD 不伪装成交易所现货；连续合约与到期合约必须区分 |
| 供应商 | 用谁的价格 | 新浪、腾讯、Yahoo、OANDA、Dukas、Binance、FXCM | AKShare 是采集通道，上游可知时列表显示新浪/腾讯，详情保留“新浪（AKShare）” |
| 环境 | 模拟还是实盘来源 | 模拟、实盘 | 账户来源在选择列表保留；账户标识只在详情用脱敏别名 |
| 价格口径 | 价格怎样定义 | 不复权、前复权、后复权、来源复权；bid、ask、mid、成交价 | 复权与买卖价是两个维度，不能互相覆盖；未知不猜成不复权 |
| 自建规则 | 这份自建怎样形成 | 自建、M1派生、D1派生、原生周期；NY17、UTC0、来源交易日 | “原生周期”是维护方式，与“原生行情”类型不同 |
| 数据能力/状态 | 能看什么、现在怎样 | 仅日线、日周月、待核实、尚无历史；实时开关与状态 | 能力不表示已获取，已开启不表示正在推送 |

股票币种在详情直接显示；多币种同代码或价格单位存在歧义时，选择行补充 USD/HKD 等。期货、外汇、金属、指数/指数CFD、加密现货/衍生品均沿用同一套语义，不能靠代码形状推断产品类型。日界按真实规则显示，不等同于交易会话。

## 二、选择列表：保留三行，关键差异直接可见

固定位置：

1. 第一行：**代码**，紧接低强调市场/产品标签；自建另有既有轻量自建标识。
2. 第二行：简明中文名；有明确能力限制时在余下空间放短标签。
3. 第三行：真实上游供应商，再放价格口径标签；账户环境紧随来源。

价格口径在添加自选的股票结果中始终显示，不根据当前加载了多少行决定显示与否。无须等两条都出现在视口中才能辨别。其他资产按对价格有意义的口径显示，例如外汇 bid、中间价；只有存在可靠字段才显示。

例子（方括号表示独立轻量标签，不是实际按钮）：

```text
300750  [深A]                        ＋
宁德时代
新浪  [不复权]

300750  [深A]                        ＋
宁德时代  [仅日线]
新浪  [前复权]

03750  [港股]                        ＋
宁德时代  [日周月]
腾讯  [不复权]

EURUSD  [外汇]                       ＋
欧元美元
OANDA  [模拟]  [bid]
```

分钟能力默认不额外堆一个“支持分钟线”标签；明确无分钟产物时必须说明限制。仅 D1 用“仅日线”；D1/W1/MN 用“日周月”；缺证据用“周期待核实”。存在 M5 但没有 M1 时不可称“仅日线”，详情列实际支持周期。

标签不带勾选态，不仿筛选控件，不可点击；中性文字、轻底色、无重边框，不用涨跌红绿区分身份。主要视觉仍是代码和名称，右侧保持单一添加/进入动作。限制标签只说明能力，不能代替请求错误。

长名称允许自然增长；窄屏/150%字号时标签换行，不截断关键差异，不强行把六个标签压入一行。三行是默认层次，不是禁止无障碍换行的硬高度。

## 三、添加自建：先选来源，再清楚展示目标配置

来源目录：代码＋市场、中文名、真实供应商/环境，与自选共用字段和位置；不标成“自建”，也不将默认表单口径冒充所选来源产品的固定口径。

只有目录明确提供且覆盖各可选口径的限制才在目录展示；否则在进入设置、完成探测后按当前模式与口径说明。不能把某个不复权接口支持分钟线推导成所有复权接口均支持分钟线。

创建设置顶部保留同一品种信息，下面显示当前将创建的独立标签，例如：

```text
300750  [深A]
宁德时代
新浪

[D1派生]  [不复权]  [来源交易日]
```

这些标签随设置更新，始终是当前提交配置，不另加确认页。详细控件仍可放高级设置，但影响价格身份的结果不能藏在高级设置里。股票 `none` 显示“不复权”，不再含混称“原始价格”。

数据验证后就地说明“日线派生，不能生成分时”等必要限制。只根据实际证据展示：D1基础派生不能生成分钟数据；有分钟历史也不能承诺支持实时接续。不提供当前后端不支持的复权/周期组合。

创建后的数据列表采用相同品种三行和自建标识；维护规则在详情的既有标签区展示。同代码同源有多个自建配置时，列表必须展示实际不同的短规则（例如 M1派生/NY17、D1派生/前复权），不能让用户逐个进详情比对。

## 四、自选主列表与详情

自选主列表仍固定三行和列宽。来源行使用规范短名，在股票上附口径短名，例如 `新浪·不复`、`新浪·前复`；已有自建标记保留。选择列表和详情用完整“不复权/前复权”。FX 等显示必要的 bid/ask/mid；环境差异不能被“统一叫 OANDA”抹掉。

若源名＋必要差异超过现有固定列宽，不能仅缩成不可读小字。优先在中文说明行补充最短差异、第三行保留来源；仅在真实同名多配置冲突时增加简短显示别名。实施前对真实冲突夹具截图确定最终排布，不扩大代码列或压缩 sparkline。用真实 id 保留稳定别名映射，不随搜索词、滚动或排序变化。

行情详情顶部展示选择时同一身份；下方用独立标签显示完整价格口径和自建规则，必要事实按“市场／报价币种／来源环境／可用周期／历史范围”列出，已有覆盖信息保持。

自建接续明确分开“历史来源”和“实时来源”，不能把实时来源冒充整条历史的供应商；版本切换不改变自建标签。完整 ticker、规则版本、账户范围留在可复制技术信息里，不充斥主屏。

实时状态沿用数据页 Switch：已开启、未开启；准备中、闭市、异常在状态区域如实说明。自选不新增闪电、色点或背景；sparkline 的红绿/蓝色继续只表达价格与展示会话，不承担配置开关语义。

## 五、去重、排序与搜索

- 重复记录按真实价格系列身份去重；同代码不同来源/复权不折叠、不自动换源。来源产品、自建数据集、固定版本和接续 ticker 分别沿用现有身份映射。
- 保留此前的加入防重、所有分组排除、当次添加后原位显示勾和重开后排除；创建防重沿用现有同源产品及归档处理，不把展示改造当成放宽创建规则的授权。
- 按相关性、代码/市场、来源、价格口径稳定排序；不使用“推荐”标记暗示某来源质量更好。同代码同来源的分钟型不复权入口可排在仅日线入口前；不擅自让 A 股总高于港股或自建总高于原生。分页必须由服务端稳定排序，不能只重排当前已加载页。
- 中文/代码＋供应商/市场/复权/维护规则可用空格组合搜索，例如 `宁德 新浪 不复权`、`宁德 港股`、`eurusd bid`。按已有词间 AND、词内跨字段 OR，先过滤再分页。
- 新浪/腾讯属于同一通道的不同上游，供应商词必须准确匹配变体，而不是把“新浪”简单映射成所有 AKShare；不得破坏现有 `xau oa` 简写、中文与短词性能。
- 保留查询防抖、取消和独立 cursor；不新增逐行 metadata/能力探测请求。需要区分的信息通过现有批量列表响应补齐。

1. 固定红灯复现：宁德时代六个价格系列，验证相同文字不可区分；保存当前运行环境的只读结果作为证据。夹具不写真实自选。
2. 后端规范化展示数据：优先扩展既有 `market_presentation.py` 与 `history_catalog.creation_entry`，提供可靠市场/产品、来源上游、环境、复权、买卖价和能力证据。分别处理 provider / catalog / managed，不通过 description 字符串反向拼身份。字段缺失显示待核实，不补造。
3. 手机类型和映射：扩展 `MarketRow`、`CatalogItem`、`Dataset` 的必要只读字段；提炼一个有明确上下文的标识映射，输出代码、名称、市场、来源和独立短标签。列表身份与业务操作仍使用 ticker/catalog_id/dataset_id。
4. 共用 `SymbolInfo.tsx` 或其邻近展示组件承接标签；迁移 `DataPage.tsx`、`DataCatalogSheet.tsx`、`DataCreateSheet.tsx`、`DataManagedPage.tsx` 和详情。创建表单摘要读取当前 state，不读取初始目录默认值。
5. 单独处理 `WatchPage.tsx` 的紧凑标识，保留几何与 sparkline；必要时补 `market.ts` 批量报价中的身份字段，不能靠悬浮 title 作为手机唯一辨识方式。
6. 实现明确上游/口径/规则的搜索匹配和分页前稳定排序，更新现有测试；避免当前 `_statement` 在变体展开前过滤时丢失“腾讯”等变体匹配。
7. 本地检查、真实 Ubuntu 只读搜索和截图对照；本轮不触碰 PR/CI/正式发布。未来实施的部署仍走仓库 mw-docker 与任务隔离要求。

本变更预判 F0：增补兼容的展示/API 字段、手机渲染和搜索资格/排序；最小检查为针对性单测、构建、浏览器交互与 Ubuntu R1。若实施需要改变数据集持久身份或 schema，停止扩大范围，先说明必要性；本方案不要求这些变化。

## 七、验收与停止条件

- 宁德时代完整六种结果均能仅凭可见文字辨认；相同代码/上游的复权差异明确，A/H市场明确。仅D1与日周月限制正确，无分钟数据不伪装成请求暂慢。
- 覆盖 bid/ask/mid、模拟/实盘、同代码不同交易所/币种、现货/永续、连续/交割合约、同源同代码不同自建模式/日界。
- 未核实字段不造值；目录支持与探测成功、历史可用、实时开启保持区分；自建选来源阶段不把未选的复权状态显示成定论。
- 添加自选选中的 ticker 与可见口径严格对应；快速改词/分页/返回不串行、不错选，重名不错误合并；并发防重和当次成功留行行为不回退。
- `npm run build`；按实际改动运行 `node tests/mobile-symbol-search.browser.cjs`、`node tests/mobile-data-workflow.browser.cjs` 与自选身份/布局相关现有检查；后端运行 instrument directory/mobile search/creation 的针对性测试，补充真实多变体夹具。
- 截图覆盖375/412px、深浅主题、150%字号、长源名、缺字段和同名配置；不能仅靠 title、颜色或长串说明区分。自选固定列宽和 sparkline 宽高保持原值。
- 对支持“不复权/仅日线/模拟”等词的搜索验证分页前匹配，并实测中文多词与短词延迟，不能靠逐行网络查询换取标签。
- 只有上述识别、身份和交互验证通过才可交付“已实施”；Android 真机文字可读性、触摸与输入法仍单独列明。无可靠元数据、性能明显回退或紧凑布局必须压缩 sparkline 才能辨识时，保留证据并报告具体冲突，不编造标签解决。
