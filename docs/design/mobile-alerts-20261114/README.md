## 推荐设计

沿用已经认可的手机端蓝色、轻边界、shadcn/Base UI 控件语言。页面围绕两个任务组织：**规则**（现在守着什么）、**记录**（发生过什么）。不再做监控统计仪表盘。

- 标题右上仅一个无底无框的 `+`，始终能打开品种选择；离线时可浏览缓存，提交不可用并说明原因。
- 主视图只有「规则 / 记录」。规则默认「当前」，包含启用、暂停和到期结算中的规则；通过一个轻量筛选入口查看需处理、已结束、已归档及搜索。正常服务信息不常驻占位。
- 每条规则以品种和触发条件为主体。左侧沿用 `SymbolInfo` 三行身份，右侧显示条件、周期/判定方式、触发次数，独立开关控制启用意图。行底仅显示实际执行状态，异常加一句原因及一个对应动作。
- 列表不显示内部 ID、修订号、接管时间、输入游标、每次检查时间、长通知说明；这些放在详情末尾的「排查信息」。不显示空白统计数字或正常成功提示框。
- 暂停/恢复原位反馈；保存后回到列表并定位规则。普通成功与后台重试写入「更多 → 日志」。字段错误和必须由用户处理的阻断留在当前操作附近。

设计形态来自内容：**以“条件”作为列表视觉中心，以“状态 + 下一步”承接异常，而不是以服务运行统计作为主角。**

## 完整操作路径

### 1. 新建：选品种 → 设条件 → 创建

品种选择采用共享搜索外观和三行身份，不另起来源、分类页签。查询支持代码、中文名、供应商及空格分词。默认展示自建行情，可用项优先；选中后才调用 capabilities 核验所选周期和模式，不能对每一行并发做能力探测。

此入口不能直接复用添加自选的请求参数：自选搜索排除已添加项，而告警允许同一品种创建多条不同规则。它需要独立 search adapter，复用展示、取消、分页、去抖机制。可复用 dataset-summaries 分页与 `continuation.composite_ids`，但必须保留完整来源身份，多个接续不能随意取第一个。

- 已开启实时、能力可用：进入条件表单。
- 实时未开启：行内「去开启」，进入已有数据详情，由用户明确操作；返回后重验能力并续接流程，不在搜索时自动改开关。
- 没有自建行情：显示「添加自建行情」，带入现有数据页流程；维护/实时具备条件后可继续创建。
- 暂不可用：显示简短原因，允许进入数据详情；已有实时开关开着不等于当前模式可用。
- 从自选/图表带入品种时可跳过选择步骤，但仍核验能力。

默认价格表单首屏：品种、条件、价格、判定方式、手机推送、创建。常用条件上穿/下穿/高于/低于，其余放在同一个条件选择器，支持穿过、进入/离开区间、上破上沿、下破下沿。区间条件仅显示上下限。

保留当前默认 `M1 收盘确认`，不在 UI 重构中改成触价。选收盘确认时显示周期；选触价时以「按收到的报价判断」说明抽样语义，不能宣传逐笔不漏；底层周期保持明确且参与能力核验。切换到不支持的模式时保留输入并就地说明。

「更多设置」默认折叠：次数（1/2/3，默认1）、到期（不限/自选日期时间）、名称（自动生成可改，最多100字符）、备注、应用内提醒、补到数据的通知方式（默认仅记录）。展开入口旁简短显示「1次 · 不限期」，使默认值可见。日期按应用/设备时区显示，并写明时区，持久化仍为时间戳。

手机推送独立一行：沿用 `notify_ntfy`。默认仍关闭，不因视觉改版擅自启用；开启后才需验证服务器推送配置，并提供「更多 → 后台通知」路径。未配置时明确显示「未配置」，不只给无法解释的灰开关。现有更多页主要检查设备与状态，不把它宣称成完整服务器配置向导。

创建成功显示「准备中」，等服务器真正接管后才为「监控中」。已越过目标的首次观察不冒充穿越。重复点按、网络超时继续用原 request_id 核查，不创建重复规则。

### 2. 查看与维护

点规则打开统一 Drawer。上部是品种与条件，中部只回答：当前状态、原因/动作、判定方式、已触发次数、到期、通知方式、最近触发。按需进入该规则记录、查看对应品种图表。

- 启用意图开关与执行状态分开：开关开着的规则可以处于准备、休市、恢复或需处理，不能把开关当作健康指示。
- 编辑价格/区间条件保留已发生次数、既有暂停状态等后端语义。保存不承诺自动恢复或清零。
- 触发用完：提供「再次启用」，复用 `restart`，明确清零次数、保留历史、从新基准开始；到期时先处理到期时间。
- 已到期：进入编辑更新到期时间，再明确恢复；编辑和恢复是两个服务器动作，部分成功必须可识别和续接。不能用一次按钮掩盖中间失败。
- 停止使用：详情末尾「归档」，确认后执行 archive。文案明确停止执行、保留历史、不能恢复，不提供“撤销归档”。
- 排查信息按需展开：检测/输入时间、最近缺口、接续修订、判定证据、通知状态。没有缺口/异常时不渲染空字段。

### 3. 异常处理

| 状态/原因 | 列表呈现 | 详情主动作 |
| --- | --- | --- |
| 准备中 | 准备中 | 等待；超时转服务检查 |
| 监控中 | 监控中 | 查看条件 |
| 有依据的休市 | 休市 | 无需处理 |
| 供源短暂不可用、恢复基准中 | 等待数据 | 查看情况；自动恢复不要求反复开关 |
| 实时关闭 | 需处理；实时已关闭 | 去数据详情开启 |
| 绑定冻结/变化/失效 | 需处理；来源需更新 | 核对后编辑绑定，不静默换来源 |
| worker 未接管/卡住 | 需处理；检测服务异常 | 查看服务状态与日志 |
| 判定中断且无法补判 | 曾中断，部分时段无法判断 | 查看影响区间；恢复后也保留事实 |
| 到期结算中 | 结算中 | 查看记录；不说已全部完成 |
| 推送失败、规则仍正常 | 监控中；推送失败 | 检查通知配置/对应记录 |
| 手机离线或状态过旧 | 顶部一行“离线，只读”或“状态待确认” | 重试连接；不推断服务器已停止或仍正常 |

仅 `status=active` 不能判定正在监控；复杂规则可能没有 `execution`，需结合 health 并保留“待确认”，不能套价格规则准备中状态。筛选“需处理”涵盖阻断、执行错误、长时间无进展和推送问题；暂时等待与休市不一律计为故障。

### 4. 触发记录与处理

列表以「品种 / 触发条件 / 发生时间 / 触发价 / 处理状态」呈现。首层只提供全部/未处理的轻量筛选；异常恢复可从记录筛选进入，系统杂项仍在更多页。事件详情再展示推送接受、设备回执、检测时间、迟到/缺口等证据。

一次「处理本次提醒」可以编排现有两项操作，但必须区分事实：通知 ack 停止本次提醒，notice handled 标记已处理。先 ack，再 handled；只成功一部分时保留剩余动作与就地错误，重试不得反复创建通知。不存在 notification_id 的事件只处理 notice；不存在 notice 的旧事件只 ack，并显示“已确认”而不虚构 handled。操作后回读两种状态。

处理提醒不暂停规则，不删除记录；再次触发按原次数限制执行。“推送服务已接受”不改写为“手机已收到”。现有触发列表未携带实收字段，需明确“设备实收未核验”，不能只凭规则上的 execution_notification 推断这一条触发事件已送达。

触发事件接口当前只有 limit、没有 before 游标；不得用前端数组截取伪装无限历史。设计采用上滑加载，落地时需为 events 增加 `(occurred_at, created_at, id)` 稳定游标和 has_more，保持旧接口调用兼容。通知中心异常记录已有分页，直接复用。归档规则需要显式 `status=archived` 请求，默认列表不包含它们。规则接口最多500条，也必须标清有无下一页，不能假设取回即全量。

## 价格之外的能力边界

后台已有 SMA/EMA/RSI/MACD/ROLLING_RANGE_SQUEEZE、价格区间、画线与 ATR 偏移等能力；不是任意 Python 指标都能自动作为告警。

此次设计主路径覆盖价格/区间告警的创建、执行、维护、触发处理及结束。已有指标/画线规则必须可读、可暂停/恢复（仅可执行来源）、可归档，并保留来源/参数快照。不能只在价格列表里把它们藏掉。

**手机创建完整的指标/画线告警目前缺少真实入口：**`MobileChart.tsx` 的 `alerts: unavailable`，`runtime/alerts.ts` 也显式限制 mobile 写操作；手机图表仅保存本机单图文档，画线关联依赖服务器 workspace/chart/object 验证。不能只解除 unavailable 或指向桌面 URL 就声称打通。

建议分清两项：

1. 本次告警页落地时可增加按需「指标条件」分支，读取 capabilities 的目录和参数 schema，在表单内创建独立指标规则；参数必须显式可见，允许比较兼容单位的常量/指标，不暗示随图表参数同步。价格仍是默认，避免首屏先选一堆类型。
2. 画线告警从图表对象上下文创建才简洁。完整接入需设计手机 workspace 持久化、图表对象关联、权限范围和删除联动，作为独立功能项；当前原型不提供假的“从手机图表创建”按钮。若将画线新建纳入这次实现，须先补完这些约束再验收，不能宣称价格流程等于全部类型全流程。

## 落地文件与顺序

1. `alerts.ts` 提炼纯展示模型：状态归类、可执行动作、条件简述和通知处理状态；不把领域语义写进CSS。
2. 拆分 `AlertsPage` 为列表/规则详情/条件编辑/品种选择/记录；新增 `alerts-controls.css`，页面挂 `.mobile-controls` + `MobileOverlaysProvider`，复用 Button、Switch、Tabs、Select、Field、Input、Collapsible、AlertDialog，替换原生 confirm。按受控open保留退场，未保存修改统一处理。
3. `MobileApp` 接入选品种、跳数据详情、查看图表、通知设置的明确导航回调；保留草稿与返回来源。重新打开能力变化必须重验，不能沿用旧caps。
4. 接通价格/区间表单、到期编辑/恢复、restart和事件处理；保留请求幂等、版本冲突、离线只读、未知结果核查。指标表单复用能力schema，不直接搬桌面表单布局。
5. `RecordsSheet` 提炼可嵌入告警页的记录主体，更多页继续复用；按实际需要兼容扩展 events 分页接口，归档明确查询；前端缓存携带查询身份，切筛选/关闭时取消旧请求。
6. 截图/交互验收后再交付APK环境。价格/判定/通知后台不因UI任务改变；不修改网页端样式或图表加载策略。

风险分类：纯设计P0；UI/API兼容实现F0。若画线持久化或核心执行语义被纳入则升级F1并专项验证，不能夹带在视觉补丁中。

## 验收清单与停止条件

- 375/412宽、深浅主题、150%字号、键盘缩小可视区域：标题、三行身份、长条件、底部动作不重叠；抽屉关闭/返回/丢弃一致。
- 空页可独立新建，不依赖先去图表；不可用品种有原因与可达处理路径；查询不排除已在自选或已有告警的品种。
- 创建单价/区间、非法输入、能力变化、重复提交、超时核查、409冲突：保留输入，不重建规则。
- 暂停/恢复按服务器返回；恢复先显示准备中；休市/等待不误报故障；缺口和推送失败不被“监控中”吞掉。
- 编辑不擅自清零或开启；次数用完restart；到期修改后恢复；归档不能复活，归档列表确实能读到。
- 记录按真实历史分页；处理ack/handled成功和部分失败回读准确；不把服务接受当实收、不把处理提醒当暂停规则。
- 指标/画线旧规则、缺少execution、退役来源、离线缓存均可解释；未接通的创建能力不出假入口。
- 浏览器测试用独立夹具，真实环境只读；不启动真实告警或投递未经请求的通知。最后由用户核验Android返回、软键盘与真实后台通知，不能用浏览器截图代替。
- 生产切换、PR/CI/tag不属于本次交付。实现范围和实测结果以实施验收记录为准。
