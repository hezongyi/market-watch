# MWA 配置实时来源与系统消息图标调整方案

初版 2026-10-21；2026-10-22 修订。用户已认可并要求写入本方案，本次仅更新文档，下一轮实现尚未开始。

## 1. 状态与统一范围

原始基线 `v1.26.5` / `6f74951`。首轮简化已在 `feat/composite-mapping-native-20261021` 完成，Draft PR #93；mwa Web/Chart 使用干净提交 `1274f42` 构建，`a0785ac` 补充运行记录。首轮隔离 R1 和 mwa 真实页面验收见该分支 `docs/verification/composite-mapping-native-20261021/README.md`。

本次统一实施两项：

1. 配置实时来源参考“自建行情 → 添加行情”的两步流程、UI 风格和同款原生控件，自动填好可确定的配置，并允许人工修改。
2. 右上角“系统消息”图标与下方“自选表”图标的水平中心对齐。

本修订替代初版“单页对照、品种弹窗、必填补充说明、普遍复核勾选”的交互决定。旧原型 <https://192.168.7.232:18382/mapping-preview/> 和初版浏览器观察保留为历史证据，不代表本次两步流程已预览或验收。

## 2. 问题与目标

“补充说明”实际必填，保存时才要求展开；产品类型/关系、两条网址、至少 10 字说明及确认勾选使普通路径过重。网址只校验格式，不核实内容。仅折叠字段而保留原必填要求，不能解决问题。

目标：历史行情已确定，普通路径只需“选择实时品种 → 检查自动配置 → 创建”；特殊情况才增加补充或定向确认。代码一致和资产类别相同，不直接证明现货、CFD、期货等产品等价。

## 3. 第一步：选择实时品种

- 沿用添加行情的标题、两步条和底部操作栏：“① 选择实时品种 / ② 配置并创建”。
- 顶部只读显示已确定的历史来源、准确品种、Bid 和日线划分，不再次选择历史品种。
- 复用添加行情的页面内真实原生搜索框、分类、结果列表和选中状态；不另弹品种对话框，不保留重复下拉。
- 当前只支持 OANDA Practice，固定当前账户来源；查询及结果都需限制来源/账户，不仅隐藏来源切换控件。
- 默认按历史品种搜索并选择相关类别；准确匹配优先展示。已有唯一有效配置可预选，多条不同有效配置有歧义时明确选择，不能按排序暗选。
- 有缓存直接使用；当前账户目录缺失时自动尝试读取一次，显示进度，失败后用户重试，不持续自动重试。目录更新不创建组合或采集需求；有目录时保留次要刷新入口。
- 选择只修改草稿，底部显示已选品种，点击“配置实时 →”进入第二步；未选择时禁用。
- 不提供任意手工登记实时代码；准确品种来自当前账户可用目录。

## 4. 第二步：配置并创建

参照添加行情布局：顶部所选实时品种及“更换品种”，左侧配置、右侧创建摘要、固定底部操作栏。窄屏改单列，正文滚动、操作区可见。

| 内容 | 自动填写 | 人工修改边界 |
| --- | --- | --- |
| 历史来源、准确品种 | 当前历史数据集 | 只读，修改需退出本流程重新选择历史行情 |
| 实时来源、环境、账户范围、准确代码 | 第一步当前账户目录选择 | 通过“更换品种”修改，不手填身份或凭据 |
| 标的、报价币种 | 受支持的准确代码及来源元数据交叉核对；USDCAD→USD/CAD、XAUUSD→XAU/USD | 可以修改，服务端必须验证与真实身份一致，不以编辑字段绕过不匹配 |
| 历史/实时产品类型 | 优先采用已核实且适用的来源资料；仅资产类别推导明确为建议 | 可以修改，资料不足标记待确认，不能把类别推导直接当作已核实产品 |
| 产品关系 | 已核实的来源对及产品规则，显示结论或已知差异 | 可以修改；冲突或资料不足需解决，不能用通用“已核对”文字放行 |
| 实时精度 | 当前账户目录 | 来源属性只读，不新增价格舍入配置 |
| 价格口径 | 当前固定支持 Bid、原价接续 | 只读，不增加 Mid/Ask 或自动平移价格 |
| 日线划分 | 沿用历史行情规则 | 只读，不因配置实时源改变历史含义 |
| 匹配依据 | 附带真实适用的系统资料及其来源 | 在“匹配详情”查看、补充或更正，不强制每次输入两条网址 |
| 备注 | 留空 | 选填，取消至少 10 字要求，备注不充当核验依据 |

尽可能填全已知信息；不能虚构官方链接、审核结论，不能仅去掉斜杠/下划线就断言产品等价。无法确定时显示具体待补充项，已知冲突不能靠更改分类消除。

原“补充说明”拆为正常配置中的产品类型/关系、默认折叠的匹配详情、选填备注。标准匹配无需额外复核勾选，明确点击创建即确认配置。已知产品差异才增加针对性确认并显示差异；未知关系不能伪装成已知差异，靠勾选放行。

右侧摘要显示历史/实时来源、准确品种、Bid 原价差异、沿用日界、匹配结论和当前检查状态。结论应区分“同标的同币种”与“相同产品”。状态为“正在核对 / 待补充具体项目 / 可以创建”，有效检查完成后才启用主操作。

## 5. 创建、结果与草稿

- 底部：返回选择品种、取消、仅保存配置、主按钮“创建并打开图表”。已有相同有效组合时显示“打开已有组合”，不能复用历史或规则不同的组合。
- 主操作保存准确映射，再建立/复用组合，应用到原目标图格；“仅保存配置”不建立组合、准备任务或采集需求。
- 创建成功但尾部未准备完时显示“接续准备中”；保存成功、图表 dataReady、覆盖完整和策略就绪分别表达。
- 历史数据集固定，但历史发布版本与接续点目前在首次使用时原子固定。页面展示的预计版本/接续点须标为预估，最终由服务端提交时核验；关键结果变化应反馈，不能将预估冒充已固定结果。
- 返回第一步再回来，未更换品种时保留草稿；更换后重算受影响字段，清除旧产品不再适用的关系、依据及确认。独立备注可保留，但不可将旧品种的匹配结论带入新产品。
- 自动预填不算用户修改；用户修改后有离开保护。轮询/刷新不静默覆盖人工编辑，成功保存仅清除对应草稿。
- 目录刷新重验准确品种；仅时间戳变化不重复要求确认，账户、可用性、精度或关键产品属性变化则重新校验并显示变化。
- 已有明确有效映射可复用，已有组合通常直接打开；多映射存在歧义时明确选择，旧账户配置不可当作当前有效配置。
- 备注变更不应无意义地产生新的运行映射/组合。实现前梳理决定接续行为的配置与说明记录的版本含义，兼容已有 ID 和引用，不重算或原位修改旧映射。
- 保留未知保存结果先核查、保存成功但打开失败复用已保存映射重试、幂等及卸载/工作区/目标图格变化后的迟到响应保护。

## 6. UI 与控件复用

直接参照 `DatasetCreate` / `CreationCatalog`：步骤、选中摘要、配置分组、右侧摘要、底部操作、返回与错误反馈同一风格；复用现有能力，不引入独立 UI 框架或重复搜索实现。

- 第一步使用 `CreationCatalog` 所用真实 `platformSearch` 选择模式，支持固定 OANDA、初始搜索/类别、预选及目录状态。
- 第二步沿用 `NativeInput`、`NativeSelect`、必要时的原生 Checkbox，按钮和备注复用真实原生 Button/Textarea 适配。
- 复用添加行情的布局，不照搬历史起点、维护计划、周期选择或手工登记等没有配置意义的字段。
- 保留原生窗口/导航、主题、字体、焦点、禁用、键盘与销毁行为，不复制许可库代码；沿用认证 API 与既有宿主管理通道。

## 7. 系统消息图标位置（纳入本次）

原待办 01 同批实施：右上角系统消息图标与下方自选表图标，水平中心一致，沿同一竖直线排列。

- 用实际页面测量按钮/图形/容器边界、尺寸和间距，定位偏移原因，优先按现有工具栏和侧栏布局对齐，不预设未知像素偏移。
- 保留真实原生图标按钮、命中区域、打开系统消息、悬停提示、键盘焦点及未读角标。
- 深浅主题、桌面/窄屏、侧栏开关、角标有无均检查。两个入口都显示时，在同一坐标系下中心偏差不超过 1 CSS px；既有响应式隐藏行为保留。

## 8. 服务端合同及规则边界

现有 `ProductMatch` 强制两条 HttpUrl、10–1000 字说明、产品类型/关系和 `reviewed=true`。本次需要同步调整前后端合同，不能仅隐藏字段、默认勾选、填假网址或套话绕过旧校验。

服务端重新核验当前账户、可用目录、准确代码、标的/币种、产品规则与 Bid，不信任前端的“已核实”标记。系统资料应保留适用范围和规则来源，人工改动含义明确。已有映射、组合和历史修订保持兼容，不静默替换正在运行的组合。

保持固定历史/日界接续点、原价、来源分段、按需采集、幂等和账户隔离。保存映射与首次使用继续分开，UI 主操作可串联；浏览、搜索、进入配置不产生使用需求。

## 9. 实施与验收

本轮文档为 P0。后续实施不能直接沿用首轮“兼容前端”的 F0 分类：先确定映射合同、说明与身份拆分设计，涉及持久格式或身份语义时按 F1 执行兼容验证及仓库要求的 review。

验收覆盖：

1. 两步页面、同款真实原生选品、固定来源、无重复弹窗；缺目录自动读取、失败重试与无结果分别呈现。
2. EURUSD/USDCAD/XAUUSD 自动信息正确；标准匹配无需手填网址/10 字说明/普遍勾选；未知、已知差异、冲突分别处理，人工修改经服务端校验。
3. 草稿不被自动覆盖，返回/更换品种、目录更新、账户切换、唯一/多配置复用及已有组合打开正确。
4. 仅保存无采集需求；创建/打开只影响目标图格；准备状态准确，失败恢复、结果核查、幂等和迟到响应保护通过。
5. 既有映射、组合、修订仍可用；备注变更不意外改变运行定义。
6. 深浅主题、390px、滚动与固定底栏、键盘、标签及离开保护。
7. 系统消息/自选表图标中心对齐，点击、悬停、焦点和未读角标正常。

实施及自动验证使用 Ubuntu 本机任务隔离环境。按用户本会话偏好，候选完成后先在 mwa 真实页面验收，不因等待 CI 延迟 mwa 验收，CI 继续运行并记录；mwa 保留真实数据、配置、端口及保护浏览器，不试验性清库/seed。合并、正式 tag、生产发布另行处理。
