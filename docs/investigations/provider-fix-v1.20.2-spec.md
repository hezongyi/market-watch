# v1.20.2 行情修复与发布要求

用户于 2026-10-11 授权修复已分析问题，验收通过后提交 PR、复审、合并并生产部署。
基线 `0cebcf5`，生产 v1.20.1；发布补丁 v1.20.2，不移动既有 tag。

1. 普通实时采集及普通历史任务入口不能处理组合或显式注册数据集；有效图表需求、
   实时计划、viewport 和强制品种参数均不能越过身份边界。正确的独立供源采集不受影响。
2. 保留组合图表、策略与告警需求及其固定修订/目标映射；精确清理普通采集器造成的
   `Unknown source: composite` 残留，保留历史审计和其他错误，不宣称收到新数据。
3. Binance 支持显式直连与原代理配置模式，所有实时、历史和原生图表入口统一解析。
   生产仅为 Binance 选择经验证的直连；Yahoo、OANDA、Dukascopy 的代理配置不变。
4. Binance 瞬时网络错误最多两个只读 GET 尝试，轮换失败的共享连接池，每次请求
   获得共享额度并服从同一时间预算。鉴权、限流及证书校验失败不盲目重试，保持 TLS 校验。
   错误保留安全分类、阶段与类型，避免空文本和凭据/账户 URL 泄漏。
5. OANDA REST 的瞬时连接失败退役故障池，保持并发读者与来源/世代保护，不新增
   第二个 production pricing stream。后续原有确认调度能取得新连接，不增加供应商重试。
6. 用重新核实的 SG 官方小时与假日资料启用有限、账户绑定的 operational session
   profile：2026-10-11T00:00Z 至 2026-10-18T00:00Z，仅 EUR_USD/XAU_USD。保留未知
   边界及到期 unknown；计划开市不证明报价、可交易或 M1 完整。禁止重写历史身份、
   拼接点或覆盖；只有已证实闭市才能用闭市调度并消除普通网络残留状态。
7. Ubuntu 独立 project/network/volume/数据库/端口验收，使用 mw-docker 专用 builder。
   必须验证真实 HTTPcore CONNECT 故障、共享额度/预算、组合需求与 PostgreSQL 回归。
8. 提交 PR，对固定 head 做 Standards/Spec 双轴复审并处理发现；通过后合并、推新 tag，
   从 clean tag 源码经 Ubuntu mw-docker 构建固定正式镜像。
9. 正式切换前保留配置/镜像回滚材料，生成最终数据库备份并在 Ubuntu 实际恢复校验。
   新版本保留 Yahoo 启用、通知配置、生产数据及用户配置；只更改已说明的供源配置。
10. 部署后验证真实 HTTPS 登录、组合行情/供源状态、BTCUSDT M1 接续、OANDA 当前
    会话与保护行为及 worker 健康；记录实际环境、网址、启动/停止及结果。
    按明确 task/project 退役本轮 Ubuntu 实例并恢复校验，保留正式备份及回滚资源。
