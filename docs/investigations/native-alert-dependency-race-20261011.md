# 专业图表原生告警与数据中心初始化失败

用户报告：在 `https://trade.kookvv.com:8443/advanced-charts` 登录后显示“原生告警接入失败”，随后点击数据中心显示“原生界面适配不可用”。要求真实浏览器登录排查并解决根因，保持原生告警和数据中心功能、图表库版本及工作区生命周期保护。

## 已确认的实现缺陷

Ubuntu Playwright 访问正式生产 v1.20.2，Chromium 124 未修改网络和服务端资源时，8 次登录有 5 次连续出现两个错误：

1. `原生告警接入失败：TypeError: Cannot read properties of undefined (reading 'call')`
2. `原生界面适配暂不可用，已打开数据中心兼容窗口：Cannot access 'w' before initialization`

定位探针仅替换本次浏览器收到的 runtime 响应，记录到缺少模块 `210754`；调用链为 `nativeAlertShell → Select (221339) → DOM IDs (210754)`。该共享模块来自已安装 v31.1.0 的 chunk `32171`。告警适配器等待其他控件 chunk，却没有等待此依赖。其他界面加载这个 chunk 的速度决定初始化成败，因此新的 Chromium 检查通过也不能证明所有客户端正常。

Webpack 在执行模块前缓存 exports。第一次 require 失败后留下部分初始化的 Select 模块；数据中心虽然会加载 `32171`，但随后读取这份缓存触发初始化顺序错误。刷新页面改变资源时序，不能解决实现缺陷。

修复：在读取原生控件前显式等待 `vendor.e(32171)` 和 `vendor.e(36145)`。后者提供 Select 导入的键盘导航模块 `409286`。保留固定版本检查、失败提示、回退窗口和会话归属保护；不改许可库字节，不通过吞异常隐藏故障。

## 回归验证

新增 `web/tests/native-alert-dependencies.integration.cjs`，使用真实私有图表库和提交的两个适配器、合成行情、独立浏览器路由。默认延迟成功返回的 `32171` 和 `36145`，先初始化告警再加载数据中心；`MW_DELAY_CHUNKS` 可指定多资源并发延迟。修复前能稳定触发上述两个错误，修复后两个原生界面初始化成功。测试不接触生产 API、用户配置或真实告警。

```bash
MW_PROBE_LIBRARY=/private/path/charting_library \
MW_CHROMIUM_EXECUTABLE=/path/to/chromium \
node web/tests/native-alert-dependencies.integration.cjs
```

在正式站点浏览器响应中仅补上依赖，Chromium 124 连续 5 次登录及打开数据中心通过。此为候选修复验证，生产服务器当时尚未更新。

## v1.20.3 生产复验失败及补齐

PR #42 和 v1.20.3 仅增加 `32171`。Ubuntu 单项延迟回归通过，但生产切换后的 Chromium 124 第四次登录仍出现上述两个错误，因此已回退至 v1.20.2，保留 v1.20.3 标签，不移动或改写为成功版本。

进一步延迟 `36145`，浏览器 runtime 探针捕获缺少模块 `409286`，调用链仍为 `nativeAlertShell → Select (221339)`。新增这一场景后，v1.20.3 回归准确失败，补齐等待后通过；也通过 `32171,36145,3854,29365,19504,25165,91947,10030` 多资源并发延迟场景。第一次测试只控制单一缺口，存在覆盖不足，生产循环复验发现了它。

## 证据范围

真实访问日志中 Safari 26.1 使用相同图表库和 host，相关静态资源返回 200，且打开了数据中心兼容窗口；HTTP 成功不能证明浏览器内模块初始化成功。尚未取得用户完整错误后缀，不能声称已直接捕获用户本人的异常堆栈。

另一个受控网络故障探针阻断 `34540` 可以触发相同两条提示，但没有证据证明它是用户实际故障。WebKit 本机运行受 EGL 环境限制，未作为 Safari 验收通过证据。
