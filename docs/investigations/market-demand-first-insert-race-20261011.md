# 图表需求首次登记并发竞态

状态：已定位根因，尚未修复；独立后续修复，不移动 v1.20.2 tag。

2026-10-11T05:28:41Z 起的首轮正式浏览器验收，在 `/api/charts/data` 观察到一次
HTTP 500，后端 `market_data_demand_pkey` UniqueViolation，图表就绪等待超时。
错误链中的两处错误文字属于同一次事故。第二、第三轮完整验收成功，仍不能证明并发
缺陷消失。原始日志与浏览器结果保留于本轮私密操作目录，没有新增生产调试实例。

## 根因

`backend/alerts/market_data.py` 的 `renew_demand` 通过
`client|instrument|composite_revision_id` 的确定性散列构造主键，随后先 `db.get`，
不存在则 `db.add`。两个独立事务同时首次登记相同 key 时，均可能读到不存在；
先提交者成功，后提交者违反主键唯一约束，异常传播为 500。
确定性主键本身是正确的幂等身份，缺少数据库级原子登记。

`market_data.py`、`series_access.py`、`chart_api.py` 在 `v1.20.1..v1.20.2` 无变化。
代码和错误约束指向既有并发竞态，本次切换后的首次图表访问暴露该问题；
回滚 v1.20.1 不会修复此逻辑。没有证据将它归因于本轮供源身份或连接池改动。

## 解决方案与验收

用 PostgreSQL 原子 `INSERT ... ON CONFLICT (id) DO UPDATE` 替代先查再插。
冲突只续租 `expires` 与 `updated_at`；保留 instrument、组合固定修订和主键身份，
先保留既有维护权限、组合归属校验，并在冲突更新条件中核对身份一致。
旧请求不能倒退租期/更新时间；身份不一致应明确失败，不能静默改写目标。
非 PG 适配遵循同一原子合同或明确限制，不能引入无边界重试。

真实 PostgreSQL 回归需要两个独立连接/事务，通过屏障同时首次登记相同 key，验证
两个请求都成功、仅一行且租期正确；同时检查既有行续租、同 key 并发续租、不同组合
修订互不覆盖、非法修订和未维护行情不生成需求。覆盖真实图表调用的提交/flush 边界，
避免只测试无法形成并发的顺序函数调用。
