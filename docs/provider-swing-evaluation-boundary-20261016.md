# 平台 Swing 的评估边界

2026-10-16。针对 REST 指标修复中“保留 worker 的未来行排除规则”的专项复核。

结论：保留同一评估快照的因果边界，修正使用显示日期判断未来的实现。不能仅为通过旧测试，把 worker 的时钟判断当成业务定义。

Swing 使用严格对称窗口；右侧 strength 根柱已经进入评估快照后，才能识别中心柱的极值。图上可以将标记回绘到中心柱，但 detected_bar_time 和 confirmed_at 仍分别是检测柱的起点和该柱结束时间。形成中右窗口可以产生 provisional 候选，不能写入确认状态。以上是算法确认延迟，不应删去右窗口或将其冒充中心柱当时已经知道的信号。

评估截止点与显示分页边界分开：

- 实时：以本次价格快照最后纳入的来源柱为评估末端，曲线、候选和累计统计使用相同输入与 revision。
- 普通历史分页：裁剪显示窗口，保留完整系列统计的固定起点与该快照的评估末端，不因翻页改变统计口径。它并不表示逐步历史回放。
- 逐步回放：以明确的回放游标为末端；游标之后的来源柱不能参与确认或统计。

`start` 是来源时间，`chart_time` 是图表标签。纽约 17:00 开始的日柱可标为下一交易日的 UTC 日期，月柱也有独立的月标签规则。标签晚于 UTC 当前时刻不代表观察来自未来；当前柱的 end 尚未到来同样不妨碍 provisional 预览。

本次 worker 先按来源 start 与观察时刻选出可纳入的最后一根，再按其 chart_time 读取页面。在同一个可重复读快照内冻结输入和价格凭据，Swing 的评估末端显式使用该页面最后来源柱；数值计算在释放数据库连接后进行。服务端快照凭据保存这个真实评估末端，避免指标重读时又采用更新的尾部。

回归包含：缓存确有未来来源行时排除；合法来源柱的显示标签晚于观察时刻仍纳入；Swing 展示同时返回正确的 as_of_bar_time 与 as_of_chart_time；历史分页保留完整统计；确认因果性与候选副本不变。新增标签回归在旧判断下为空页而失败，修正后应返回来源末柱与对应日标签，并纳入真实 PG14 检查。

依据：[Swing 既有验收](swing-sr-implementation-acceptance-20261012.md)、[指标方案](swing-support-resistance-indicator-plan-20261012.md)、`swing_sr.SwingState.step` 与 `native_series.chart_label`。本文件不改变 Swing 的 strength、回绘、统计或告警规则。
