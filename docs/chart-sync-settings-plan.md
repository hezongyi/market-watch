## 3. 柱宽同步的行为与来源

### 唯一来源

来源为 SHA 校验原生用户缩放入口携带的 **实际 chart/model 实例**。鼠标在未激活图表上滚动并实际改变其柱宽时，不需要先点击激活，它即可成为来源。按钮与快捷键以原生动作实际作用的模型为准，不把全局 activeChartIndex 当作准入条件。不将最后收到 spacing 回调的目标当作来源。

单纯焦点变化不触发同步，也不使仍在进行的真实用户缩放失去来源身份；新的实际用户缩放替代旧操作。关闭、布局/商品/周期更改、实例退出、workspace/load/reset/rebase/暂停继续取消旧动作。

### 触发与排除

监听每图 `getTimeScale().barSpacingChanged()`，但回调本身不能区分原因。只传播与已识别用户横向缩放操作关联的图表变化，包括：

- 滚轮缩放；实际支持的触控板缩放按同一输入合同验证。
- 原生缩放按钮、放大工具及框选、快捷键。
- 时间轴拖动缩放等直接用户输入，若确实改变柱宽。

不传播：

- 开启同步、单纯切换焦点、只产生平移的滚轮或拖动。
- 价格轴缩放、hover/行情更新、没有实际柱宽变化的输入。
- 启动/工作区恢复、商品/周期/布局/尺寸切换、历史 reset/rebase、自动拟合或其他程序恢复造成的变化。
- 模块自身设置目标柱宽所产生的回调。

Undo/Redo 的缩放传播属于后续可选探索，**不作为首版硬要求**；首版维持原生撤销语义，不把 Ctrl+Z、Ctrl+Y 或所有 keydown 都当作缩放输入。用户明确要求的滚轮、原生缩放按钮/工具与缩放快捷键必须覆盖。布局加载及其他程序恢复仍不作为来源。

### 调度与异步操作

每次用户缩放拥有操作 token，至少包含 `chart 实例身份、workspaceEpoch、layoutEpoch、operationId`。阶段 A 必须确定实际原生动作的开始、每步、正常结束和取消入口；不能只记录当前焦点或数组索引。

- `begin`：在原生确实接受用户缩放的入口创建 token；普通 keydown、菜单点击或 wheel 到达本身不代表已经开始缩放。
- `step`：每个实际柱宽变化携带其所属 token，检查来源仍是该实例及当前工作区/布局代次；按帧合并，同帧只应用最新值，每目标最多一次。
- `end`：原生动画真正结束时标记输入完成，把所属最后一步保留在同一 rAF 合并队列中；提交或取消后释放 token，不因 end 另开一次同步 setter。不是在按键松开后固定等待若干毫秒。
- `cancel`：关闭模式、来源实例退出、load/reset/rebase、暂停或另一操作替代时取消；已有 rAF 和动画闭包上的旧 token 都不能再传播。复位目标不就绪不得排队旧操作。
- `applyPeer`：目标 setter 的回调标记为本次内部应用，禁止反向创建用户操作或成为来源。

公开 `barSpacingChanged(newValue)` 不提供动作原因。当前快捷键探针已出现跨多帧的连续回调；单靠“近期有用户输入”、任意时间窗口或全局 last-action 都不满足正确性。阶段 A 输出必须选定以下入口之一：

1. **公开入口可证明关联**：给出所有首版输入的事件→原生动作→每一步回调→结束/取消关联，证明同期间程序 `setBarSpacing`、reset 和恢复不带用户 token。
2. **SHA 校验最小原生动作 Adapter**：公开入口无法证明时，在本版本实际用户缩放调用及异步闭包中传递 token，只在执行该 token 的一步时通知协调模块；程序调用没有 token。覆盖 `zoomIn/out` 动画、滚轮、放大工具和时间轴缩放的实际调用路径；未知入口不能一概当作用户动作。

适配层必须可安装、幂等、卸载并拒绝未知字节；当前已经安装的范围/保存 hook 组合迁移也要验证。阶段 A 需记录选择、锚点、探针及复现命令，未获得完整关联证据前不实施柱宽传播。用户缩放图表期间穿插后台恢复，必须能够只传播真实用户步骤。

### 目标与定位

默认覆盖当前布局其他时间 K线图，不受商品及周期相同限制；Renko/Range 等合成图首版排除。单图不执行目标更新；同值无需再次设置。目标临时不就绪时不保留待重放的旧缩放，待下一次用户缩放再跟随。

目标使用原生 `setBarSpacing()`，通常保留目标自身右侧时间定位基准，不主动跳回最新日期。原生 setter 会执行 `correctOffset()`，最左/最右边缘的合法 offset 范围也随柱宽变化，因此优先序为：原生合法视区与柱宽限制 → 尽量匹配来源柱宽 → 合法范围内保留目标原有右侧定位；不保证极限边缘同时等宽且完全不移动。柱宽变化会自然改变可见时间跨度，不承诺保持原可见 from/to。如果目标原生最小/最大柱宽限制与来源不同，采用原生有效值，并记录无法等宽的目标；不能通过放开图表限制保证相等。验收记录边缘缩放前后的 spacing、rightOffset 和右侧时间，区分必要边界修正与错误跳回最新。

缩小目标可能正常扩大可见 bar 数，触发现有历史加载/储备。这是用户缩放的正常需求，不套用范围映射 hover “零历史请求”预算；需验证未产生与视区无关的额外重复请求或整段远历史回填。

## 4. 日期范围互斥与生命周期

现有 `rangeSyncLoadingGuard` 保存 `desired()`，在加载期间暂时将原生 date toggle 置为 false，再恢复。保存视区时 `captureChartLayout()` 也暂时关闭 date/time 同步。

同步协调模块是 date/barWidth **用户期望模式的唯一所有者**，模式为 `none | date | barWidth`；保存时派生 `{date,barWidth}`。它也记录 timeSync 的用户期望值用于既有临时暂停，timeSync 功能仍独立，不与另外两项互斥。原生 watched values 只是有效执行状态，不能作为保存或禁用状态的权威。

实施必须迁移下列全部调用，不保留第二份 desired 或旧值 finally 恢复逻辑：

| 当前位置 | 迁移责任 |
| --- | --- |
| `range-sync.js` 的 `rangeSyncLoadingGuard` | 保留数据就绪跟踪；每次加载向协调模块申请暂停 token，移除自身 desired/set/restore 所有权 |
| `viewports.js` 的 `edgeRangeSync` | 保留边界对齐算法；删除独立 desiredRange/desiredTime 及自身 finally/dispose 恢复，改为借用暂停 token |
| `captureChartLayout` | 暂停前先读取协调 snapshot 保存逻辑期望；日期/时间临时关闭不能写入 `_mwSync`；完成释放 token |
| `restoreChartViewports` | 整个恢复期间禁止产生柱宽用户来源，所需 date/time 暂停经 token 请求，finally 只释放本次 token |
| `deferLegacyChartSynchronization` / `restoreChartSynchronization` | 将旧存档 native 值一次正规化为用户期望；恢复走协调 configure，不再直接恢复旧 bool |
| `bridge.js` 初始默认及 chart load/layout 生命周期 | 先确定工作区代次与模式再设置原生执行状态；载入取消旧操作和旧 token，不把退出旧实例的恢复写入新实例 |
| 原生菜单/键盘及宿主配置入口 | 用户选择走同一模式转换；禁用状态以 mode 判断，拦截被禁用动作，不能先造成双开再依赖 CSS |

### 可嵌套暂停合同

内部 `acquirePause(reason, mask)` 返回含工作区代次的 token 及幂等 `release()`；mask 可暂停 date、time、柱宽传播，不修改用户期望。暂停原因用 token 集合计数，不用单一 busy bool。

- 一项的有效值仅在用户期望启用、该项无暂停 token、当前工作区数据条件允许时启用；日期模式临时为 false，柱宽仍禁用。
- A+B 嵌套暂停，先释放任一项都不能越过仍生效的另一暂停；最后一次释放按**当前**用户期望恢复，不恢复 acquire 时捕获的旧值。
- release 二次调用无效果；旧 workspace token、旧布局动作和迟到 finally 不作用于新实例。失败、取消与 dispose 均结束各自资源且不能覆盖新模式。
- 用户修改模式或独立 timeSync 发生于暂停期间时，保存最新期望，有效状态等暂停结束再应用；非用户 watched-value 写入只能经协调模块，避免改写期望。
- 当前原生 date/time handler 在非 `_loadingContent` 时调用 `undoHistory.setWatchedValue`，保存服务监听 undoStack change 并标 dirty；仅有协调模块 internal 标志不能阻止该副作用。调用前做 no-op 检查；阶段 A 必须选定并实测不进入 Undo/Save dirty 的有效态写入口（必要时使用 SHA 验证的内部入口或窄 hook），记录实际 Undo 栈、native Save 可用性和 dirty 的 before/after。禁止用 `clearUndoHistory` 或全局 loading 标志掩盖污染，不改变用户操作的原生撤销语义。
- 内部暂停/恢复与用户修改选择必须区分：只有执行状态的临时写入走无 Undo 入口。既有日期/时间同步的有效用户改动，包括暂停期间通过菜单修改逻辑期望，保留原生可撤销合同；Undo/Redo 更新逻辑选择，执行状态仍受当前暂停及互斥约束。不得把用户选择也当作内部写入，或借临时启用同步制造 Undo。time 命令只保存 time 布尔值，撤销时合并当前 date/barWidth 模式；日期命令只保存模式，不能撤销独立 time 选择。新增柱宽开关首版不生成原生 UndoCommand，但正常标 dirty 并参与保存；缩放 Undo/Redo 传播仍非首版要求。
- 双开非法存档优先保留既有 date，barWidth 关闭；正常交互不得产生双开。恢复只恢复选择，不按恢复时焦点图统一柱宽。
- 单图保存选择，多图就绪后等待下一次有效用户缩放。目标未就绪不重放旧操作。

## 5. 高低价标签：不接触 K 线

硬约束：标签矩形与主 pane 行情绘图区相交面积为零，文字、底色、箭头均不得进入 K 线区。不改变价格自动缩放，不生成参与保存、对象树和 Undo 的用户绘图。

### 标签可见性的统一合同

填充与标签共用同一个目标投影结果，先检查来源有效及必要开关，再检查目标是同身份、更小周期的时间图、MN→W1 排除和与目标可见时间轴的真实交集。建议私有结果为 `{targetIdentity, generation, horizontalIntersection, priceProjection, hiddenReason}`，不要另起只凭 source 判断的标签路径。

只有有效目标的**横向交集宽度大于零**才允许标签和信息条显示。来源图、M1 无合格目标、不同商品/同周期/更大周期、横向时段完全在屏外、来源没有有效 K 线时均不显示；目标未来空白仍沿用原日历槽投影及可见交集合同。价格纵向在屏外可用信息条，时间横向无交集不可用信息条。必要开关关闭、leave/menu/load/reset 时清除全部标签文字、内容 DOM 及待更新任务；稳定占位容器按下述配置/布局合同保留或释放，迟到布局/行情回调不能复活旧价格。

### 首版位置：固定外部信息栏

阶段 A 已选定首版始终使用行情 pane 之外的固定 **36 CSS px** 信息栏，分两行显示实际高/低价格。栏为 chart slot 内的 sibling，原生图表内容高度扣除 36px，标签、背景、箭头与 K 线绘图区零交集。此选择适用于所有轴布局，不在 hover 时临时腾出空间；下述价格轴对位方案保留为后续设计，首版不实施其轴绘制/碰撞入口。

后续若取得可靠准入证据，可在目标主图右侧价格轴区域显示 `高 1.12560`、`低 1.12340`，纵向锚使用实际 high/low 的原生价格坐标。用商品价格 formatter，不自行固定小数位。标签文字及背景与主题适配，填充色变化不降低文字可读性。

- 按价格真实坐标放置，倒置轴仍按数值识别高/低，不按屏幕上下替换语义。
- 百分比、对数、Indexed 等轴模式采用原生投影；数字保持实际价格并明确标“高/低”。
- 标签不获取 focus、选择或拦截鼠标；来源失效/离开/菜单/load/reset 时与映射同时清除。

### 冲突与回退

首版所有合格目标统一采用外部栏；后续轴标签方案遇到以下情形时，也必须整组改为目标图外部保留区域的一行/两行信息条 `高 …  低 …`：

- 高低标签互相重叠，或与最新价/十字线/指标/画线原生轴标签冲突。
- 任一高低价不在当前价格视区；信息条注明“高价在屏外”/“低价在屏外”。
- 右轴隐藏、轴位于左侧、多个轴无法安全归属、轴宽不足以容纳文字。
- 八图窄窗口或原生轴占用未知，无法证明不覆盖原生标签。

外部信息条使用**目标 chart slot 内、行情 pane 之外的固定保留行**，不能只是 overlay 在 K线顶部。阶段 A 必须选定宿主和几何入口：布局分配时令 chart 内容拥有 `slot 高度−rail 高度`，rail 为 sibling/原生明确保留区域；若宿主无法在主 pane 外安全分配空间，标签实施继续阻塞，不改成图内 overlay。

首版 rail 固定高 **36 CSS px**，预留两行；当前只用一行也不收缩。已补八图窄窗、真实 BTC 长价格、DPR2、125% 等效布局尺寸与 16px 标签字体的候选验证；这些探针不代表操作系统全部字体缩放设置。值随明确设置/尺寸事件可调整，不随 hover、来源高低或碰撞变化调整。预留条件由配置和布局决定：范围映射及十字线同步启用、矩形样式、priceLabels 启用且该 chart 为时间图。对全部潜在目标统一预留，不依赖当前鼠标来源或动态周期允许关系，因此切换来源不重排 pane。

无有效映射时 rail 保留空间但内容为空；轴正常显示时 rail 也保留空间，避免碰撞回退时突然 resize。轴隐藏/左侧/多轴、副图、chart 最大化/恢复、2/4/8 布局和设备像素比变化都需验证真实 slot/pane/rail 的互不相交。只有配置、布局或必要开关状态事件可 reserve/release；hover 的 before/after 必须验证 pane 尺寸、视区、价格缩放和需求不变。

若右轴绘制/碰撞入口不能可靠验证，则首版始终采用外部信息条，仍显示准确高低价并满足不接触 K线；轴对位标签作为后续项。最终选择须以探针证据记录，不能静默换成图内标签。

## 6. 模块和保存合同

扩展既有范围映射模块负责外观与语义、数据代次、填充及标签统一清理。新增独立柱宽/日期协调模块负责来源操作、模式、订阅、互斥与缩放调度，菜单只读取/提交状态，不承担跨图循环逻辑。

建议协调模块保持小接口：`configure()` / `snapshot()` / `subscribe()` / `refreshCharts()` / `acquirePause()` / `dispose()`；pause token 的 release 管理临时暂停，模式和逻辑 timeSync 只由该模块保存。菜单、bridge、guard 与 viewports 不另存期望状态。

- `_mwBarRangeMapping` 升级为可迁移 v2：保留 enabled/style，增加颜色模式、自定义色、透明度模式/值、priceLabels。
- v1 启用/样式原值迁移，新增外观使用中性主题默认；字段逐项验证、alpha 有界，未知值安全回退。
- 柱宽模式在现有 `_mwSync` 中新增可选 `barWidth`，旧布局缺省 false；恢复 date/barWidth 后统一消除非法双开。
- 原生 saver 比较必须包含范围配置和协调模块的逻辑同步 snapshot，否则仅改配置会被 native `_prevChartState` 去重漏存。临时暂停期间的 native false 不能进入该比较或保存的 `_mwSync`；加载前仍移除自有字段。
- 用户改开关/确定设置、实际缩放视区依现有规则标 dirty；hover、标签绘制、临时 suspend/restore 不产生 dirty。配置改动使原生 Save 菜单可用。
- 开关、样式、颜色、透明度、标签和同步模式覆盖保存、另存、自动保存、加载、只读及并发保存。不保存来源鼠标或待执行缩放。弹窗打开时记录 workspace/config 代次；工作区切换即关闭旧草稿，迟到确定不能提交新工作区。确定 A 正在保存时再次确定 B，按 editRevision 保留 B 的 dirty，A 不得错误确认 B 已保存；只读不写服务器。
- A 的成功回调及原生 `chartSaved(true)` 清理完成后，B 仍须保持**宿主 dirty、原生未保存状态及 Save 可用**，直至 B 真正保存；只在宿主保留 dirty 不足以通过。使用实际原生 Save 菜单保存 B，并验证服务器最终配置为 B；旧工作区 A 的迟到完成不得改变新工作区任何保存状态。
- 保存失败保留当前配置 dirty 与本地恢复草稿，沿用既有 blocked/复制恢复/另存为合同，不默认允许同 ID 直接重试。“失败恢复后重新提交”指通过现有安全恢复路径提交独立副本；副本保留 v2 外观和逻辑同步模式，原工作区不被覆盖，只读不写服务器。验收不能为使同 ID 重试通过而关闭既有保护。
