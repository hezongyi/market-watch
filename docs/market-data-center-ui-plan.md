# 数据中心组织与UI设计

实施更新（2026-10-07）：完整A–E与Ubuntu真实环境实现验收已通过，
见[最终逐项核对](verification/three-layer/completion-audit.md)。长时间质量观察按用户最新决定暂缓。
本文原“待实施/待验收”叙述记录方案制定时的基线，具体交付以最终证据为准。

日期：2026-10-06。状态：三层方案的配套交互设计，待实现与浏览器验收；线框中的数据均为示意。
产品规则以[行情三层架构与实施方案](market-data-three-layer-plan.md)为准。本文补齐页面组织、
主流程、状态、桌面布局与验收；不表示现有页面已经具备这些功能。
用户最新范围调整：当前不要求移动端兼容适配，不安排手机/平板专用布局、移动线框或移动验收。
本阶段以桌面浏览器为交付对象，保留键盘、缩放、权限与其他可访问性要求。

## 1. 目标与现状

数据中心回答三个问题：有哪些行情可以用、当前可用到哪里、需要进行什么维护。
用户按品种与用途管理数据，默认视图不展示租约、世代、hash等实现细节。

当前`MarketDataPage.tsx`在一个长页面内展示OANDA实时、Dukascopy注册、日界配置和历史版本；
页面默认选择一个实时品种并续订需求。`MaintenanceDialog`和`HistoryPlansDialog`还沿用
“维护自建历史同时持续维护实时”及按屏幕根数判断可看的旧流程。这些都需要与三层模型对齐。

沿用现有React、React Router、CSS变量、Lucide图标与应用外壳；默认浅色米白/绿色风格、现有字体。
不引入另一套组件库、字体或单独交易终端皮肤。采用紧凑可读的列表，减少装饰性图表与重复状态卡。
UI/UX参考采用适合运营数据管理的Data-Dense Dashboard模式；实现仍以本项目现有视觉体系为准。

## 2. 导航与信息架构

应用侧栏将“行情接入”更名为“数据中心”，保留`/market-data`入口与旧链接兼容。
入口默认进入“自建行情”；用户主动选择的分区、筛选和排序保存在URL，返回列表恢复位置。

| 分区 | 管理对象 | 主操作 | 不承担的操作 |
| --- | --- | --- | --- |
| 自建行情（默认） | 用户维护的数据集与发布版本 | 添加自建行情 | 进入页面不触发实时采集 |
| 平台品种 | 来源目录与原生能力 | 搜索后打开平台图表 | 浏览目录不自动创建自建历史 |
| 组合行情 | 已生成组合及可建立候选、映射、使用需求 | 打开组合行情 | 不要求手工重复创建整条混合历史 |
| 任务与记录 | 下载、校验、派生、发布、恢复任务及结果 | 重试明确失败项 | 不把历史任务暂停当作实时停用 |

页头右侧提供次级“来源状态”，打开现有来源的连接、目录更新时间和能力详情。
连接配置入口复用既有设置及权限；不在页面展示账户原值、token、租约标识。
不新设只有汇总数字的独立首页；每个分区的状态统计都可点击过滤实际条目。

建议路由（实现时保持现有路由兼容）：

| 路径 | 内容 |
| --- | --- |
| `/market-data?tab=managed` | 自建行情列表，裸入口同义 |
| `/market-data?tab=platform` | 平台品种目录 |
| `/market-data?tab=composite` | 组合列表与候选 |
| `/market-data?tab=tasks` | 任务与记录 |
| `/market-data/datasets/new` | 添加自建行情 |
| `/market-data/datasets/:id?section=overview` | 自建详情及指定详情页签 |
| `/market-data/composites/:id?section=overview` | 已建立组合详情 |

任务从对象详情进入时携带对象筛选，返回恢复原处。列表预览可用侧面板，完整详情用可深链接页面；
不层叠多个模态框。首次访问列表、展开详情或查看健康均为读取，不自动建立行情需求。

## 3. 自建行情列表

从上至下：标题与“添加自建行情”按钮；“全部／可用／准备中／需处理／已暂停／已归档”筛选；
搜索框及来源、资产类别、日界筛选；数据列表；分页。类别统计可重叠，例如可用且维护失败，
不得让“需处理”筛选把旧发布从“可用”中移除。归档默认隐藏，但直接链接和引用仍可解析。

列表按数据集一行，不按每个发布版本一行，也不因同名品种合并不同来源或日界。

| 列 | 默认信息 | 展开或详情信息 |
| --- | --- | --- |
| 品种与口径 | EURUSD；Dukascopy · Bid · NY17 | 准确来源代码、通道、环境、精度、聚合规则 |
| 可用历史 | 已发布起止日期；“含未知区间”提示 | 按周期覆盖、缺口分布、固定版本 |
| 可用周期 | M1、H4、D1等文本标签与准备数量 | 每周期截止点和阻塞原因 |
| 维护 | 每日／已暂停；下次维护时间 | 计划时区、最近成功、最近尝试与失败 |
| 当前状态 | 可用／首次准备中；延迟或失败次级提示 | 下载、校验、派生、发布的真实状态 |
| 操作 | 查看；可用时“打开历史图表” | 立即更新、补数、暂停/恢复、归档 |

“可用历史”给出已发布内容；下载中的游标单独写“已查询至”，不能冒充可用范围。
列表可局部更新，排序不随每次心跳重排；保留焦点、展开状态、筛选和滚动位置。
默认排序稳定（例如品种、来源、日界），需处理内容通过筛选进入，不在用户操作时跳行。

## 4. 自建详情

标题显示品种、来源、价格口径、日界和维护状态；操作按上下文提供“打开历史图表”、
“用于回测”、“立即更新”，并在更多菜单放低频操作。回测按钮必须选择已发布版本和区间。

详情分为五个页签：

| 页签 | 内容 |
| --- | --- |
| 概览 | 当前可用范围、各周期状态、最近成功发布、维护延迟、待办原因 |
| 覆盖与质量 | 周期/版本/区间选择，观测、unknown、失败、已证实闭市的时间分布和可访问明细表 |
| 发布版本 | 发布时间、固定截止、可用周期、覆盖摘要；查看版本、用于回测、与前版差异 |
| 维护设置 | 目标起点、所需周期、日更计划、暂停/恢复、指定区间补数；高级项折叠 |
| 组合与引用 | 实时映射、已建立组合、引用的回测与策略；进入对应详情 |

概览线框：

```text
数据中心 / 自建行情 / EURUSD
Dukascopy · Bid · NY17          [打开历史图表] [用于回测] [更多]
可用到：完整日期时间及显示时区     维护：每日       最近更新失败，可继续用旧版本

概览 | 覆盖与质量 | 发布版本 | 维护设置 | 组合与引用
周期       已发布范围          可用性          当前处理
M1         起止时间            可查看          无
H4         起止时间            可查看          新版派生中
D1         起止时间            含未知区间      无
W1         尚未发布            准备中          等待派生

最近维护：失败原因及下次重试时间                  [重试失败范围]
实时映射：OANDA EUR_USD · Practice               [查看映射]
组合：尚未建立；首次实际使用时准备                [打开组合行情]
```

时间分布不能只用颜色：每类有名称、纹理或标记，并提供区间/分钟数明细。
无可信“完整性百分比”时只显示各类事实；成功查询比例不命名为历史完整率。
高周期不完整说明指向具体缺口；来源会话未核实不会阻止用户选择NY17。
更早日期有数据不等于中间连续；默认范围摘要始终附覆盖入口。

## 5. 添加、维护与改日界

添加采用独立页面的三个步骤，支持返回保留输入；取消不产生任务，提交成功后可离开页面。

| 步骤 | 必填与默认 | 反馈 |
| --- | --- | --- |
| 选择来源品种 | 选择来源，搜索准确品种；继承目录资产类别、精度与支持口径 | 标明M1能力和可获取范围；未知范围明确显示待查询 |
| 配置历史 | 历史起点、日界、需要的周期、维护频率及时区 | 外汇/金属NY17、加密UTC0；指数无默认，必须选择 |
| 核对并创建 | 汇总来源/品种/口径、区间、日界、维护计划 | 显示“创建并开始维护”；说明后台持续进行，组合在首次使用时建立 |

来源目录可用时不让用户手填可推导的精度或准确代码；目录不足时允许高级手工登记，
标明尚未验证，并由后端做真实能力校验。不能因手工登记成功就显示来源可用。
同语义数据集已存在时引导查看或调整维护范围，不重复创建；未回答的配置不以占位符提交。

日期输入显示其含义：NY17使用交易日期，说明对应前一天纽约17:00，并展示实际起始时刻；
UTC0使用当日00:00。结束日期转为明确排他边界供核对，日更任务显示固定截止时间。
展示时区沿用用户设置（无设置时UTC并标明）；显示时区不会改变聚合日界。

维护计划默认每日，具体时间取后端可用默认并显示时区及下次执行；“一次性维护”或暂停状态明确。
阶段状态为排队、下载、校验、派生、发布。只有分母已知时显示阶段进度，查询100%不表示发布完成。
无稳定速度样本时展示已处理范围、根数和当前阶段，不虚构剩余时间。

更新、补数、暂停分别命名：

- “立即更新”：补到固定当前截止时间并复查近期窗口，复用同范围进行中的任务。
- “指定区间补数”：展示所选区间及受影响周期，不重新下载整段十年历史。
- “暂停定时维护”：停止新的定时任务；运行中任务的暂停或取消另行显示。
- “暂停当前任务”：在安全检查点暂停，界面先显示正在暂停，收到确认后才显示已暂停。
- “恢复维护”与“重试失败范围”：显示实际调度结果，其他行仍可操作。

暂停历史维护时就地说明“已发布版本仍可使用；策略需要的实时行情继续运行”，不反复弹确认框。
修改日界入口命名为“按新日界创建数据集”，预填来源、目标日界及可复用的发布版本；
提交摘要说明旧回测与组合保留原口径。创建后跳转新数据集，原条目保留新旧关联。

## 6. 平台品种

显示来源筛选、搜索和目录更新时间；每行显示品种、准确来源代码、产品类型、可用原生周期与环境。
主操作“打开平台图表”，次操作“添加为自建行情”。第二个操作只在来源有确认M1历史能力时开放，
否则旁边显示原因；周期列表来自供应商能力，不显示本地合成周期为原生能力。

平台图表口径设置展示影响价格含义的参数，例如Bid、平滑、日/周对齐；采用默认值也可查看。
修改这些参数切换到对应平台系列，不覆盖原缓存身份。与第二层日界配置采用不同说明文字。
目录更新失败保留缓存条目并提示更新时间；授权异常、无搜索结果和来源无此品种分别处理。

## 7. 组合列表、映射与首次使用

组合页首先显示已建立条目，另有“可建立候选”筛选。候选由自建历史与映射状态计算，
不为搜索、筛选、状态轮询或打开详情创建组合/stream需求。

| 状态 | 默认操作 |
| --- | --- |
| 无可用自建历史 | “去维护”，说明所需周期或历史不足 |
| 有历史、缺映射 | “配置实时来源” |
| 有历史且映射有效、未建立 | “打开组合行情”，触发幂等准备并共享 |
| 已建立、无有效需求 | “打开组合行情”，按需恢复；标记未在采集，不标故障 |
| 准备/恢复中 | 查看阶段；历史可用时进入图表并保留准备提示 |
| 尾部陈旧或来源异常 | 可查看历史；显示确认截止、原因及策略分别受何影响 |

映射配置从“组合与引用”或候选行进入：展示历史产品；选择目标来源与准确品种；
展示产品类型、币种、价格口径、环境及匹配依据；保存映射版本。
明确默认映射可预填，来源不匹配或无法核实时不猜测。保存映射本身不启动持续采集。

首次打开时自动选择符合规则的历史发布基线和拼接点，异步展示“接续历史／确认近期M1／派生周期”。
正常首次打开不再让用户重复确认已保存的映射；创建策略时保存其输入及接缝政策，
需要用户理解接缝影响的选项在规则表单中明确说明，不以静默默认代替。

组合行显示：品种、历史来源→实时来源、日界、历史基线日期、尾部确认截止、当前需求数和主要状态。
报价新鲜度、确认M1、指标及每条策略就绪分别显示；“暂无策略”不显示为策略已就绪。
OANDA Practice保留环境标识，不能写成实盘执行已就绪。

详情页签为“概览／接续与修订／使用与健康”。接续视图用时间轴和等价表格展示历史段、T、确认尾部、
临时分钟；标明来源价差与量口径差异。使用页列出图表租约、启用策略/预警与常驻需求类别，
解释为什么关闭本页面后仍在采集，但不默认暴露内部用户或连接标识。

“更新历史基线”“更换实时来源”属于低频操作：先展示变化、受影响使用者和预热状态，
再显式启用新修订。已有策略默认保持绑定，迁移策略必须列明目标和启用结果。
历史新版本出现时只提示可建立新修订，不自动切换。

## 8. 任务、删除与异常状态

任务列表列出对象、任务类型、固定区间、阶段、已处理范围、错误及下次尝试、开始/更新时间。
默认显示运行及需处理，历史记录可过滤；状态文字为中文，技术错误详情折叠并脱敏。
列表、详情中的“查看任务”指向同一记录；重复点击提交在前后端均防重。
创建请求超时先查询提交结果再允许重试，避免用户以为失败而重复创建。

删除菜单分三项，并按权限开放：

| 操作 | 界面要求 |
| --- | --- |
| 停止维护 | 可恢复，展示仍然存在的版本和实时需求，不删除内容 |
| 归档条目 | 从默认列表隐藏，引用可访问；如仍有任务/需求，明确列明，不假称已停止全部采集 |
| 删除数据 | 独立危险操作，先加载引用影响；显示哪些能删除、哪些受保护；有引用时阻止删除并给出入口 |

物理删除的确认按钮明确写“删除所列数据”，展示准确品种、来源、版本及范围；
共享分块不把对象逻辑大小当作可释放空间。引用在提交时重新检查，变化则返回新的影响说明。
首版不提供全局批量删除；一般更新/重试无额外确认，操作反馈就地显示。

| 异常 | 页面反馈与恢复 |
| --- | --- |
| 空列表 | 说明用途，提供添加或选择来源；不显示假进度 |
| 筛选无结果 | 保留筛选并提供清除，不误称所有数据不存在 |
| 初次加载失败 | 错误说明与重试；不替换为正常空列表 |
| 刷新失败/浏览器离线 | 保留上次结果、显示快照时间；未知实时健康不沿用绿色正常 |
| 旧发布可用但本次任务失败 | 并列显示可用历史与维护失败，可继续打开 |
| 配置/授权错误 | 指向配置入口；区别于可自动重试的网络故障 |
| 提交字段错误 | 保留输入，字段旁说明；多个错误时聚焦可跳转摘要 |
| 并发配置变化 | 显示最新配置及差异，允许重新核对；不静默覆盖 |

## 9. 图表与回测搜索联动

同一搜索使用“平台／自建／组合”分组或分区，默认尊重当前上下文，显示所有同名的独立口径。
结果的第二行始终有来源、日界或原生口径、价格类型和状态，键盘选中不丢失这些信息。

| 发起位置 | 默认范围 | 选择效果 |
| --- | --- | --- |
| 普通图表 | 当前系列类型，可显式切换 | 平台打开原生；自建打开已发布；组合首次使用建立需求 |
| 回测 | 自建行情 | 下一步明确选择发布版本及区间，提交时固定版本 |
| 新建策略/预警 | 组合行情 | 选择明确组合及所需周期，保存后按有效规则需求准备 |

已存在旧策略和旧图表保留原绑定，迁移入口明确，不因新默认范围重新解释旧series。
尚未就绪项可见但主动作改为“查看进度／去维护／配置映射”，不以一个全局disabled掩盖原因。
自建普通图表可选择最新已发布版本，但每次读取固定快照并显示版本；刷新换版本有明确反馈，
回测与运行中的组合不跟随该选择变化。
取消搜索、悬停结果、查看候选详情不创建需求。打开图表成功或持久规则启用才形成有效需求；
已提交的后台准备可继续，但临时等待者消失后按需求生命周期释放实时采集。

## 10. 桌面视觉与可访问性

页面采用现有应用宽度和侧栏；桌面表格保持稳定表头，详情用摘要加页签。
内容间距以8px步进，面板16–24px；主文本桌面14–16px，表格避免小于14px；
日期、数量使用等宽数字。采用既有`--ink/--muted/--line/--card/--green/--danger`，
需要的warning/info定义语义变量。先检验实际文本对比度，再沿用颜色，不因现有变量就假定合格。

普通数据状态使用文字和图标：可用、准备中、已暂停、需处理、来源异常；
只有明确失败使用危险色，不把正常准备中或无需求当错误。状态不与涨跌颜色混用。
没有全页闪烁和自动滚动；低频数据变更局部更新，动态提示不抢焦点。

桌面以1024/1440/1920px视口验证列表和详情；较窄桌面窗口减少次要列或允许数据表局部横向滚动，
品种、状态与主操作保持可达。200%缩放时内容可换行，操作区不遮住焦点或正文；
关键原因可通过点击和键盘展开，不只在hover提示。本阶段不实现移动卡片、底部操作栏或手机导航。

继承现有只读/写入权限；无写权限时可查看原因及任务，
写入口明确说明限制。是否允许操作取决于既有授权，不能仅依靠隐藏按钮。
桌面指针目标至少24×24 CSS px或具备充分间距，主要按钮可更大；键盘可遍历、表格有表头、图标按钮有名称、焦点可见。
对话框关闭恢复触发点焦点；状态更新使用节制的status播报，不逐秒播报价价龄。
正常文本对比度至少4.5:1；200%缩放、长品种名和中文换行可读；支持减少动画设置。

## 11. 实施接线与UI验收

本轮只设计，不改现有页面行为。实施时：

- `main.tsx`增加详情路由并改侧栏文案，保留旧入口；列表、详情与任务可直接访问及返回。
- 拆分`MarketDataPage.tsx`为各分区及详情，移除浏览数据中心自动续订默认实时品种的行为。
- 原维护弹窗作为新建/维护页面的带上下文快捷入口；原历史任务弹窗接统一任务视图，兼容旧任务类型。
- 表格、筛选、状态、周期可用性与错误展示复用组件；请求取消与世代检查防止快速切换串写。
- 列表分页、服务端过滤和按需详情；保留上次成功快照，不在轮询时重置表单或所有loading。
- UI消费后端的可用范围、状态原因、允许动作和版本引用，MCP共享相同业务判断；不在浏览器计算策略就绪。

与总体实施阶段对应：B交付自建列表、创建、详情和任务；C交付映射、组合及搜索；
D交付策略输入、接缝选择与使用健康；E完成平台目录、桌面布局、旧入口兼容与整体体验。
页面结构在B建立，避免将数据中心全部留到最后阶段。

UI验收清单：

1. 从平台搜索→添加自建→后台准备→按周期发布→打开历史/固定版本回测，全流程有明确反馈。
2. 多个同名品种/不同日界可辨认；默认值正确，指数必须选择；改日界创建新身份并保留旧引用。
3. 首次准备、部分周期可用、维护失败但旧版可用、暂停、归档状态均可操作且不误导。
4. 查看数据中心/详情/搜索不创建实时需求；首次打开组合共享准备；关闭浏览器不终止启用策略。
5. 映射缺失、接续失败、恢复中、无需求及报价正常但M1迟到等状态区分；单个ready不替代依赖检查。
6. 快速切换、重复提交、请求超时、离线、重试和后台刷新不串数据、不清空表单或丢焦点。
7. 暂停定时、暂停任务、归档、物理删除语义不同；受保护引用阻止删除，竞态返回可理解提示。
8. 桌面1024/1440/1920px布局与200%缩放，内容和操作可达，必要横向滚动限于数据表；键盘、焦点、长标签、颜色对比与播报可用。不安排移动端验收。
9. 截图/fixture仅验证布局和交互；真实Ubuntu隔离API/数据库另验创建、发布、引用、需求副作用与权限。

验收证据标明构建版本、浏览器、视口和真实或fixture数据。当前已有浏览器证据只覆盖旧页面，
不算本设计验收。方案后续如需精细视觉稿，可据本文制作交互原型，不改变已确认业务规则。
