# 超容量图表定位到边界（2026-10-05）

基线 `664dc57`，独立 worktree/branch 保持 `market-watch-chart-sync` / `fix/native-chart-window-sync`。用户最新授权：“只要是超过限制的图表都只跳转到能到的最大极限位置，相关提示都放到右下角的历史加载提示”。新要求取代以前“超限保持原日期”的交互；配置、连续原生数据、无reset等约束保持。

- 对每个发生导航超限的图表，结束原超额导航，按剩余单源/工作区加权预算补齐实际K线，定位到最早可显示的真实bar。不把已加载缓存边缘当作尚未补齐的容量极限。
- 补齐是独立有界操作，不截断原大请求冒充成功；每次不超过20k，并遵守现有后端历史分页/PG/版本观察机制。多个来源共享工作区预算与并发预留，不能各自绕过加权总限。共享同源而未导航的 pane 不因另一 pane 的请求被强制跳转。
- 容量已耗尽时仍定位到已有最早可显示点。降低阈值后已有数据保留，不能删除已加载区域。指标预热导致原生可显示起点晚于底层cache起点，反馈报告真实可显示位置。
- 左对齐边界，防止居中时继续请求更老数据造成循环；不改变用户柱宽、指标和画线。不为容量反馈reset。无法到达的请求日期不能假装十字线已同步成功。
- 所有容量反馈并入右下角历史提示：补齐过程、请求日期、实际落点、单源或加权限制、已加载量、失败原因、调整容量入口。完成结果保留，用户可关闭；新导航或工作区切换清理旧结果。取消、错误与新目标不允许旧边界操作覆盖新视区。
- 如果上游失败、超时或数据不可用导致剩余容量未补齐，应明确说“现有数据边界，补齐未完成”，不得称容量极限。原非容量故障不自动触发边界策略。
- 取消边界填充释放native等待/预算/事件监听；缓存已经提交的数据保留。工作区epoch、source/cache生命周期和导航generation约束延迟结果。
- 当前普通加载提示仍按getBars排队→检查缓存→等待/补数→交付→原生回调后绘制帧收尾；用户后续指定5秒显示门槛、超限立即显示。并行按品种周期分组，真实新增缓存页数与预估总页数区分，无假百分比，内存内瞬时定位无提示。边界补齐显示整次累计量与持续计时，当前最多20k批次另行标注。

验收：原四周期 EURUSD W1 2025-07-14，80k时M5加载满80k并到实际最早bar；不同周期各自受限、加权预算、并发同源不相关pane、取消/新目标/卸载、错误不伪装容量极限、以后仍可导航、hover无额外走廊重建。只在Ubuntu独立Docker验收，无生产/Unraid操作。
