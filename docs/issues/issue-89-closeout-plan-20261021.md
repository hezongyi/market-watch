# Issue #89：OANDA 快照语义修复的收口方案

日期：2026-10-21。依据：[Issue #89](https://github.com/hezongyi/market-watch/issues/89)、[Draft PR #90](https://github.com/hezongyi/market-watch/pull/90)、[现有验收记录](../verification/issue89/verification.md)及本轮源码核对。

目标：完成现有补丁的最小必要修正和验收，证明等价观测不再使快照无谓失效，真实历史更正仍被隔离，图表能通过已有机制完成有界恢复。

本轮交付方案文档，尚未执行下列实施步骤。当前业务候选为 `86bef8aae34cfbe214bc2b5310c73c6304c5779e`，集成基线为 v1.26.3 / `767cd4275a3be1d3ce27880dab1ef6dded3e11dc`。原有两个未提交文件应保留并在其基础上核对，不覆盖此前工作。

**一、问题判断与实施范围**

| 对象 | 已知事实 | 决定 |
| --- | --- | --- |
| OANDA 双 writer 的等价表示 | 完成柱的缺省确认字段与 true、有效十进制文本差异曾造成无谓 epoch 轮转 | 保留现有修复：统一 writer，在提交边界比较规范化后的完整旧、新 payload |
| native generation 6→7 | 实际 adapter 的最小复现证明，重启可合法换代、保留显示并拒绝旧句柄；原浏览器运行的触发事件及最终接管尚缺证据 | 先修一致取样与观测；是否修改产品实现由新证据决定 |
| H4 fixture | `sorted(starts[-1800:])` 在部分时刻丢弃近期柱，已复核出 12 小时尾部落后 | 优先修复，避免污染后续判断 |
| 未完成的 native 场景 | forming、换柱、恢复预算耗尽和真实 UI 重试仍缺完整证据 | 按原 Issue 补齐，沿用已有恢复机制 |
| 回退基线 | 既有探针固定 v1.26.2；相关行情持久化模块与依赖锁文件在 v1.26.3 相同 | 补一次实际 v1.26.3 目标的定向读写兼容，不扩大为全库演练 |

整体补丁维持 F1：涉及持久行情比较、历史 epoch 与指标快照一致性；本方案文档本身为 P0。主要修改文件为 [fixture](../../scripts/issue89_acceptance_fixture.py)、[browser harness](../../web/tests/issue89-native-recovery.browser.cjs)、[回退探针](../../scripts/issue89_rollback_compatibility.py)及验收记录。仅在复现证明产品缺陷后，追加最小业务修复和相应回归。

现有公共 422、TTL、epoch 检查、显式 false、真实 OHLC/volume/标签/完整性变更保护继续作为约束。区间版本化、native 全面重构、指标数学实现重验和全库恢复不属于当前收口范围。

**二、先修测试输入，建立确定性反馈**

1. H4 改为先排序再取最新 1800 根，即 `sorted(starts)[-1800:]`。将时间生成提取为可传入时刻的局部函数，避免测试依赖数据库或真实当前时间。
2. 用固定时间验证：2026-10-21 03:50 UTC 的尾柱为 01:00，14:00 UTC 的尾柱为 13:00；补相邻日、周末及夏令时边界。检查数量、严格递增、唯一性、日历锚点及尾柱，不能只断言“有 1800 根”。先确认旧实现能在 14:00 用例失败，再应用修复。
3. seed、tail、rollover 采用同一日历规则。rollover 从合法的下一柱边界构造，避免简单加固定毫秒跨越休市边界。测试输入不得以未来柱冒充当前柱；可用最近已结束但尚未确认的尾柱模拟延后确认，再追加已经开始的下一柱，无需等待真实 H1/H4 换柱。
4. 保留离线 fixture 的 freshness 处理，但在结果中明确这是测试安排，只证明协议、缓存和显示行为，不证明真实供源新鲜度。

本阶段完成标准：确定性用例先红后绿；不访问供应商，不 seed 或清理现有数据库来运行这些局部检查。

**三、使 native 验收在同一状态下作判断**

当前 `acceptedSince()` 只等任意有效接受和两帧；`verifyNative()` 的 accepted、scope、异步参考请求和最终显示来自不同时刻。以如下有界取样替代跨时点直接相等判断。

1. 每个恢复/更新阶段从触发时设置一个固定截止时间，初始采用现有的 45 秒预算。等待接受、参考请求和重取样共用剩余预算，换代不延长截止时间。该数值是测试运行边界，不声明为产品延迟 SLA。
2. 在一次浏览器同步读取中取得图格/ study、主图数据指纹、视口与范围、当前 generation、最近匹配的有效接受、完整计算身份、凭据脱敏引用、revision 和 coverage。先确认图表 ready，接受属于当前 study、当前代及本阶段输入。
3. 使用该接受的准确凭据、参数和 calculation origin，独立请求完整当前范围的后端参考值。参考请求须受剩余时间限制，并与产品请求分开记账。
4. 参考返回后再次同步读取同一组信息。generation、计算身份、主图内容或范围等任一关联状态变化，保存此次尝试为“取样失效”，在同一截止时间内重新取样。
5. 状态一致时，比较全部主图时间点上的 native 值、null/断点和覆盖；不得只比较最后一个 append 批次。缺行、覆盖不足和确定性数值不一致均失败，不能被重取样静默吞掉。换代属于可重取样事件，正确性错误不属于重试理由。
6. 最终保留严格身份检查：接受的 generation 等于稳定取样的当前 generation，凭据、revision、origin 和覆盖对应。默认等待当前代实际接受，尽量复用生产协调器现有事件唤醒；测试不得主动反复 retry 来掩盖生产侧不能收敛。

generation 的含义是隔离句柄与在途结果。当前代重新接受是本方案选用的保守验收方式；如果实际产品合法地只继承已有结果而无需新批次，应先用 start/attach/保留来源事件证明完整继承关系，再调整该项判定，不能仅改为 `generation >= accepted.generation`。

观测只加在任务 harness：包装并继续调用真实 `start/attach/applyBatch/detach`，记录阶段、事件序号、study、前后 generation、身份、revision、范围及保留来源；包装不得更改原函数的参数、返回值或异常语义。对关键句柄保留旧代批次被拒绝的定向回归。

每个 checkpoint 在断言前先保存候选状态和 comparison；失败时同样保存完整脱敏 scope、最近迁移、拒绝 attempt、参考请求摘要和失败原因。补记脚本 SHA256、Git dirty 状态和实际运行组件来源，避免仅有 HEAD 却无法追溯未提交脚本。

本阶段完成标准：实际 adapter 的局部用例能证明合法重启不被误判、旧 handle 仍被拒绝；harness 的取样用例能检测期间换代、同代换价、永久不收敛及真实错值，并在固定截止时间内结束。

**四、在现有实例补齐最小 native 场景**

复用 Ubuntu `quant-server` 的 `mw-issue89-20261021`，入口为 `https://localhost:18389`，chart origin 为 `https://localhost:18390`；保留现有 PostgreSQL volume 和其他任务实例。运行前只读核对项目、端口、资源及 API/web/chart-origin 的实际来源。

| 场景 | 操作与必须取得的证据 |
| --- | --- |
| 初始显示 | H1 Supertrend、H4 Swing 实际 native 接受；主图和指标完整范围匹配后端参考，目标层可见 |
| 等价观测 | 两周期分别提交完成柱缺省/true 与十进制等价表示；changed=0、epoch 保持，原未到期凭据仍可用，主图及无关图格不 reset；双 writer 双向切换和存量格式由既有 SQLite/PG 回归证明 |
| TTL 到期、价格未变 | 真实过期产生结构化 422；同消费者完成凭据续取及正确接受，主图不 reload、价格指纹和 generation 保持；内容寻址凭据允许续租后 hash 相同 |
| 真实早期更正 | H1、H4 分别覆盖一次；真实旧凭据 422 → 新价格读取 → 正确计算 → 同 study 的最终接受 → 实际目标层恢复。记录换代原因及完整范围，不将初次部分接受当作完成；另一图格保持 |
| forming 尾部更新 | 两周期分别更新尚未确认的尾柱；旧价格凭据仍绑定其原接受值，新价格和指标通过应用现有价格更新入口前进，覆盖及实际显示正确 |
| 完成与换柱 | 两周期分别确认尾柱并增加下一柱；时间标签、完成状态、旧快照绑定、新快照推进及 native 全范围正确，无非预期整图重置 |
| 恢复预算耗尽 | 一次 H1 场景先取得真实过期 422，再对该数据集的无凭据价格续读/历史重读定向制造网络失败；现有恢复有限结束，UI 出现明确错误和“重试指标”入口 |
| 停止自动请求及手动恢复 | 失败后让已发出的请求结束，再观察至少 10 秒；该失败的自动恢复请求不再增加。解除故障后点击 React 中真实“重试指标”按钮，经 bridge 完成恢复和最终 native 检查，无关图格不重置 |

tail/rollover 必须记录 fixture 提交到实际价格更新入口的路径。优先使用现有订阅或轮询；离线实例若需由测试驱动现有 bridge 事件入口，事件数据应来自真实 API，并单独标注这个接缝，不声称验证了真实供应商或采集 worker。只改数据库后用旧凭据调用指标 retry，不能证明新价格已进入图表。

故障只作用于本任务、本阶段和 H1 请求，finally 中移除拦截；不得伪造成功指标响应。分别记录凭据比较读取、逻辑 reload 尝试、指标请求及底层 HTTP 次数，不把所有请求错误地合并成“三次”。真实 UI 重试验收不使用内部 `indicatorCoordinator.retry()` 代替按钮点击。

绘制证据采用阶段前后截图和恢复期间的短录屏或帧序列，核对 Supertrend 曲线/填充/有数据时的信号，以及 Swing 目标层。记录期间缺层及恢复时点；单张截图不宣称全过程无闪烁。成功后继续观察至少两个协调器轮询周期，不得持续空白或反复丢层。主图行数因重载变化时，应记录视口并确认原可见区间仍覆盖，不能通过缩小范围让 coverage 断言过关。

先单独完成真实更正场景，固定工具版本后定向重复三次；任一次失败均保留且解释，不挑选成功轮次。确认稳定后运行完整矩阵一次。重复次数只用于核实已知竞态，不扩展成长时间压力或性能验收。

**六、失败分流与完成条件**

| 发现 | 下一步 |
| --- | --- |
| 仅取样期间换代，截止前当前代正确接管 | 记录正常生命周期，继续验收 |
| 输入已固定，当前代持续不接受或反复重启 | 保留完整迁移链，建立真实产品路径的失败复现，针对 adapter/coordinator/重载入口作最小修复；不继续加等待时间 |
| 稳定身份下值或覆盖错误、错误继承、旧句柄被接受 | 作为产品一致性缺陷修复并增加对应反例；修复后重跑相关 native 及后端用例 |
| fixture 日期、日历、seed 或故障注入错误 | 先修工具，原失败保留并标注，修复工具后重跑，不修改业务去适配错误输入 |
| 隔离/资源归属无法证明、需要永久数据删除或生产操作 | 保留现场，遵循 AGENTS.md 对应检查点，不扩大任务环境 |

完成必须同时满足：等价观测保持快照；真实历史变更保护不退化；上表 native 场景全部有对应最终源码的通过证据；失败预算和真实 UI 重试闭环；v1.26.3 定向回退兼容通过；F1 review 无未处理问题且最终 CI 通过。

达到上述条件后交付可审阅候选和证据，进入合并检查点。合并、正式 tag 和生产发布仍按仓库要求单独授权。本方案形成不等于恢复此前已暂停的修复执行。
