# 手机告警页简化与打磨

基线 `5038fd1e`，分支 `feat/mobile-alert-ui-20261116`。

用户目标：保留必要项目，界面简洁实用，覆盖创建、监控、触发处理、维护及结束全过程。

分类 **P0**：仅手机界面布局、CSS 与验证脚本。无 API、后台、数据库或持久格式变化。保留执行、启用意图、通知实收和已处理四种独立语义；沿用既有幂等保存与生命周期接口。

实现：突出规则执行状态与次级最近检查时间；分离详情和开关的触摸区；详情将判定方式、次数、到期合并成摘要；搜索规则抽屉去掉重复刷新；修复告警表单未选中切换项被共享主按钮样式覆盖的问题。保持高级设置、错误、投递/判定排查按需展开。

最小检查：完整前端构建、现有告警流程/触摸/尺寸主题矩阵、只读开发实例 smoke、差异自审与 PR CI。浏览器业务写仅使用夹具，持久开发实例只读。实际结果见 [验收记录](../verification/mobile-alert-ui-20261116/README.md)。

## 追加：正常收盘等待不改变监控状态

用户确认：已进入监控、无须处理的细微阶段变化不展示，避免误以为登录才启用。保持 P0：只调整手机状态展示，后台判定、期限、审计和数据契约不变。

以当前运行的接管/判定记录为依据，将 `preparing` 的 `observed_minute_unconfirmed`、`confirmation_aggregation_pending`、`confirmation_window_pending` 显示为监控中。尚无本次有效基准、仍需恢复基准、有未恢复事件时不归一化；后台超时后进入 blocked，真实恢复、停滞、服务中断、离线及投递问题仍显示。正常等待的技术文案和区间放入排查信息，不在主要详情中形成误导性缺口提示；不可补判的真实历史缺口继续可见。

追加最小检查：状态单元回归、完整前端构建、浅深主题/大字号状态浏览器夹具、开发实例只读及严格 HTTPS 核对。
