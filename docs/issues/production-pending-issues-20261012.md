## 问题 1：宽屏下绘图可见范围的周期滑动条缺失

- 记录日期：2026-10-12。
- 状态：已复现并定位；待决定是否恢复范围入口。
- 环境：Market Watch v1.23.0 生产部署网页，专业图表的原生绘图工具；1900px 宽屏已核实。原记录中的 v1.18.0 为旧本地基线，已纠正。
- 入口：选中绘图对象 → 设置 → 可见范围。

### 用户反馈

此前“可见范围”中各周期有滑动条，当前版本不再显示。用户进一步确认：是在正常、很宽的页面中观察到，并非在窄屏页面中发现。

### 预期行为与影响

宽屏下应显示各周期范围的滑动条，可通过两端设置画线显示的最小、最大周期。例如分钟范围设为 5～30，可在支持的 M5、M15、M30 周期显示，M1 不显示。

目前已确认：新版将滑动条替换为九个支持周期的独立复选框。

### 已有线索与证据边界

- 已只读核对生产图表静态资源：原生库仍保留周期范围控件及滑动条实现。
- 原生库存在窗口宽度 ≤460px 时以横线替代滑动条的适配规则，但这不能直接解释用户反馈的正常宽屏场景，不作为本问题的根因结论。
- 已通过生产浏览器复现：可见范围有九项复选框，滑动条为 0；窄屏规则未命中。`drawing-visibility.js` 主动替换了原生属性定义。
- 用户实际浏览器及首次出现版本尚未确认；技术变更引入提交为 `3f14266`。

### 后续排查与验收

如果恢复范围选择，需要统一范围与九周期掩码的保存语义。后续实现验收覆盖周期可见性、旧图恢复、保存刷新、撤销重做及窄屏操作。

- 状态：已定位当前阻塞条件；待来源缺口分类与处理。

- 当前现象：告警处于 `stale`，提示“判定柱的时间结束、来源确认或覆盖依赖不完整”。
- 原始反馈：组合日线当时仅 3 根。最新核实：活动修订返回 300 根、旧告警修订返回 30 根，均可继续分页；原数量不能代表当前总历史。
- 待处理事项：组合行情的监控链路仍需处理，尚不能据此确认告警判定链路已恢复正常。

### 证据边界与后续核对

已重新读取生产状态。旧告警最后已结束日线时间结束、来源确认均为 true，但覆盖不完整，缺 10 个分钟，集中在纽约时间 17:00–17:19；目标数据集的日历 profile 为空。这解释当前 stale，具体缺分钟属于来源缺数还是已证实休市仍需证据。

优先核实并修复覆盖，明确告警版本绑定，细化判定柱及缺口提示。本告警没有指标预热依赖。验收需以连续有效样本和真实判定证明链路恢复，不强制 ready 或静默更换版本。

## 问题 5：Python 指标加载、计算偏慢，且拖动图表时频繁闪烁

- 记录日期：2026-10-12。
- 状态：已复现闪烁并定位加载／刷新路径；CPU 计算瓶颈仍待分段测量，尚未实施优化。
- 用户反馈：感觉 Python 指标的加载速度和计算速度比内置指标慢很多。
- 补充现象：Python 指标还频繁闪烁，用户描述“一拖图表就闪”；拖动图表是明确的触发操作。
- 用户需求：评估是否存在优化空间，并提出可行方案。
- 核实证据：同图、周期 20 的 Python LWMA 与内置 WMA 对比，两次有效采样均出现 Python 整条短暂消失、内置线持续显示；等待与独立历史分页吻合。后台 `indicator_progress/indicator_ready` 还会触发整图重载。
- 证据边界：约 142–375ms 的分页回调包含网络、准备及计算，不能当作 Python CPU 耗时；实际算法瓶颈尚未确认。真实覆盖缺口导致的空值应保留。

### 后续分析与验收

优先保留分页期间已接受的曲线、协调主图和指标范围，并按受影响依赖合并、缩小重载。后端已有共享结果和检查点，应在其基础上优化。随后测量首次添加、工作区恢复、切换和实时更新，区分准备、排队、计算、传输及绘制。

验收覆盖连续拖动、历史分页和实时更新，确认有效区间已有图形稳定显示，真实历史更正仍可重新验证。

优化需保留计算正确性、历史预热、缺口处理及实时修订语义，不能仅靠截短计算历史提速。验收应提供优化前后相同场景的耗时对比，并覆盖多指标、多图并发场景。

## 问题 6：频繁弹出图表提示 TypeError: Load failed

- 记录日期：2026-10-12。
- 状态：真实网络触发待定位；已确认并模拟验证重复弹窗机制。
- 用户反馈：生产网页频繁弹出“图表提示”，错误内容为 `TypeError: Load failed`（用户原文：`typeerror：load failed`）。
- 影响：重复错误提示打断图表使用；是否同时影响行情加载、指标或实时更新尚未确认。
- 证据边界：Chromium 未自然复现；本机 WebKit 检查环境未完成 HTTPS 加载，不能用于生产归因。用户实际浏览器与真实失败请求仍待确认，与问题 5 是否同源尚不明确。
- 已核实：错误恢复会清除提示去重记录，同一错误再次出现便重弹；模拟消息仅验证提示链路，不证明网络起因。
- 后续核对：捕获提示出现时对应的失败请求和错误堆栈，核对请求发起、取消、超时及恢复流程；验收需确认实际加载恢复正常，并消除重复弹出，不以单纯屏蔽错误提示作为修复。
