# 数据中心「自建行情管理」UI 与任务导航改版方案

日期：2026-10-10。
状态：设计方向已获用户认可；本文件为实施与验收依据。

## 1. 目标与范围

针对入口「数据中心 → 自建行情 → 查看详情 → 管理行情」，统一分类布局、周期与证据列表、滚动条、按钮、下拉框、输入框和详情面板，并补齐「概览 → 查看维护任务 → 返回行情管理」的导航闭环。

视觉基准为当前图表原生窗口及商品代码搜索列表。沿用原生侧栏和已有可用的原生控件，支持原生与兼容窗口的同等业务操作。

本轮实施范围：

- 行情管理顶部摘要和五个分类的布局。
- 概览周期列表、覆盖与质量、发布版本、维护设置、组合与引用的展示层级。
- 上述页面的滚动、表单、详情展开和操作反馈。
- 进入任务页时的品种筛选、上下文展示、返回入口及位置恢复。

采集、历史维护、固定版本、覆盖完整性、未知区间、已证实闭市和引用保护继续采用现有业务契约。UI 验收必须同时核对这些契约，防止展示整理改变数据含义或操作目标。

生产发布为后续独立交付步骤。

## 2. 现状与设计依据

当前源码中的实现特征：

- `DatasetDetail.tsx` 的五个分类为：概览、覆盖与质量、发布版本、维护设置、组合与引用。
- 概览使用普通 HTML 表格；通用 `.dc-table` 最小宽度及逐列最小宽度使「周期」等短字段占据过多空间，并在小窗口产生横向滚动。
- 已接入的原生适配包含窗口、侧栏、搜索、输入、勾选、下拉和平台品种搜索，尚未接入通用原生表格组件。因此以原生列表的视觉与交互规范实现业务列表，不预设存在可直接替换的通用原生表格。
- 现有滚动区域主要采用浏览器默认滚动条；管理页面存在页面、表格及详情分别滚动的情况。
- 「查看维护任务」仅携带 `dataset_id`，任务页实际进行了精确筛选，但搜索框为空、上下文没有具体品种，且默认「当前任务」会隐藏已完成和已取消记录。
- 任务页缺少返回来源详情的入口；内部路由没有完整的返回栈。既有 `return_to` 校验仅允许数据中心列表地址，不能直接承接行情详情地址。

以上为源码分析结论；实施时仍需在独立验收实例中确认交互表现。

## 3. 页面骨架与操作层级

### 3.1 顶部

固定显示紧凑的行情摘要：商品代码、来源、数据口径／日界、维护状态和可用时间。

- 主要快捷操作：打开图表。
- 次要快捷操作：更多操作，承接用于回测、立即更新等适用动作。
- 删除历史数据在更多菜单中单独分组，仍进入引用检查及删除确认流程。
- 当前分类内部的主要操作直接显示，例如维护表单的「保存维护设置」。
- 已执行操作的结果、错误及进行中状态显示在对应区域，不能仅靠菜单内图标表达。

### 3.2 分类

保留五个分类名称及地址语义；分类切换恢复各自的位置与必要筛选。顶部摘要和分类导航保持可访问，正文滚动不能遮挡当前焦点。

| 分类 | 展示方式 |
| --- | --- |
| 概览 | 按周期分组的原生风格列表，底部展示最近维护时间与该行情的任务入口 |
| 覆盖与质量 | 「覆盖分区」「历史读取记录」两个子页，固定版本选择放在共同工具区 |
| 发布版本 | 紧凑版本列表，单个版本的完整信息与差异进入详情面板 |
| 维护设置 | 维护计划、指定区间维护、高级设置三组，按任务提供相应操作 |
| 组合与引用 | 按组合引用、其他引用分组，清楚说明对删除的影响 |

## 4. 各分类设计

### 4.1 概览

采用按周期分组的列表，保留可比较的数据列：周期、状态、观测柱、覆盖完整柱。

- 分组顺序：分钟（M1、M5、M15、M30）、小时（H1、H4）、日周月（D1、W1、MN）。
- 展示后台实际返回的周期；不将缺少产物的周期显示为已有数据。
- 表头与正文使用相同底色，小字号、弱化颜色，下方一条细分隔线。
- 周期列和状态列紧凑；计数列右对齐，使用等宽数字，列名与内容严格对齐。
- 组标题使用轻量分隔，不添加大面积背景或层层边框。
- 旧发布仍可用、派生中等说明放在对应行第二行；状态和计数必须保持原本对应的产物与版本含义。
- 如提供行详情，展开内容应对应所选周期，列出实际产物与可用版本；点击行不能隐式启动维护或改变图表。
- 窄屏改为每周期两行：首行周期与状态，次行带明确标签的两个计数；支持屏幕阅读器识别字段。
- 周期数量有限，不为该列表另设固定高度的纵向滚动容器。

结构示意，省略实际计数：

```text
周期        状态          观测柱    覆盖完整柱
─────────────────────────────────────────
分钟
1分钟       已发布        ……          ……
5分钟       已发布        ……          ……
15分钟      派生中        ……          ……

小时
1小时       已发布        ……          ……
4小时       已发布        ……          ……
```

底部入口文字使用「查看此行情的维护任务与记录」。

### 4.2 覆盖与质量

- 共用固定版本选择与范围摘要，版本选择仍仅允许适用的实际发布版本。
- 「覆盖分区」默认展示范围及观测、未知、已证实闭市、冲突计数；完整区间和来源依据在点击后进入详情面板。
- 「历史读取记录」展示请求范围、读取方式、结果、实际接纳及记录时间，保留分页和失败统计。
- 未知、闭市和冲突使用明确文字区分，不能仅用颜色，也不能将请求失败次数计入未知分钟。
- 较长的解释移入相关详情或说明区，关键数据口径保持可见。
- 切换固定版本时同步清理两类记录的分页，并取消上一版本读取；迟到响应不能替换当前版本。

### 4.3 发布版本

- 列表突出发布时间、固定范围、状态和观测／未知分钟。
- 每行保留一个详情入口；完整版本身份、周期产物、回测与图表操作在详情中展示。
- 「与前版差异」打开对应版本的比较面板，避免在列表下重复铺开大表。
- 回收后的版本明确展示「价格已回收，清单保留」，仍允许查看合法的清单与差异信息。
- 打开图表和回测必须使用选中的固定版本；不能自动替换成最新版本。

### 4.4 维护设置

- 维护计划：目标起始交易日期、维护周期、更新频率；每日计划显示维护时间和时区。
- 指定区间维护：任务类型、开始与结束日期、提交操作，明确结束日不包含。
- 高级设置：重叠复查窗口等，默认折叠。
- 暂停／恢复、归档／取消归档放入维护状态区域，说明对应影响。
- 不同时铺开多个同等强调的保存或提交按钮；每组操作有明确作用范围。
- 保留提交锁、重复请求保护、未保存提示和配置冲突处理；重新排布不得导致输入丢失。

### 4.5 组合与引用

- 以接口实际提供的引用类型和计数分组，不补造无法查询的分类或引用。
- 列表重点展示引用对象、类型和使用的版本；长身份进入详情。
- 明确说明哪些引用阻止当前删除操作，删除确认显示实际删除范围。
- 与现有引用保护及回收权限一致，禁止用按钮隐藏代替后端保护。

## 5. 控件、详情与滚动规范

### 5.1 控件

- 已支持的输入、勾选、下拉和搜索使用现有原生适配。
- 按钮统一高度、字号、图标、间距、悬停、禁用、忙碌和焦点反馈。
- 日期、时间及数字字段按实际适配能力实现，统一外观与验证反馈；不把使用浏览器输入能力的控件宣称为库原生控件。
- 每个字段有明确标签，辅助文字紧邻字段；选项、错误提示及提交范围可由键盘和屏幕阅读器识别。
- 列表筛选放在对应列表的工具区；表单选项与字段对齐，避免满宽下拉挤压无关内容。

### 5.2 详情

- 桌面在右侧展示一个详情面板；切换行替换该面板内容。
- 窄屏展示完整详情页式面板，提供明确返回／关闭入口。
- 关闭恢复触发项焦点与列表位置；键盘焦点不能进入被遮挡的正文。
- 详情中的长列表可独立滚动，主列表和详情各自保持位置，避免同一区域层层嵌套滚动。

### 5.3 滚动

- 正文采用一个主要纵向滚动区；行情摘要和分类导航使用固定布局或吸顶布局，避免重复占用高度。
- 表头在相应滚动区保持可见，吸顶位置不能与分类导航重叠。
- 概览通过响应式重排消除横向滚动；复杂证据表仅在确有必要时提供局部横向滚动，不使整页横向溢出。
- 使用浏览器正常滚动机制，并对齐图表原生窗口的滚动条宽度、轨道、滑块及悬停样式，匹配明暗主题。
- 不修改许可库资源；实施前从当前固定版本确认可复用的原生滚动样式。
- 不强制隐藏滚动条，保留触摸板、鼠标、触屏和键盘滚动能力。

## 6. 「查看维护任务」导航闭环

### 6.1 从概览进入

进入「任务与记录」时：

1. 使用当前 `dataset_id` 精确限定行情，避免同代码、不同来源或日界混查。
2. 默认 `status=all`，展示该行情的任务及历史记录；允许用户再切换当前、需处理、暂停或历史。
3. 搜索框预填接口能够识别的品种查询代码；展示名称与查询代码不一致时，从数据集的权威字段确定查询代码，不能直接拼装展示名称。
4. 显示品种代码、来源和日界。元信息由数据集详情取得，列表为空时也能说明当前查询对象。
5. 保存完整来源位置：行情详情、分类、版本等查询参数，以及已有返回列表上下文。

### 6.2 任务页

- 来源于行情管理时，顶部提供「← 返回 {商品代码} 行情管理」。
- 显示可识别的精确查询范围，不能仅显示「当前仅查看此行情的任务」。
- 搜索框主动改为其他品种时，明确解除原数据集精确限定，进入普通品种查询，避免隐藏的 `dataset_id` 与新文本同时过滤出空结果；解除后显示实际生效的筛选。
- 「查看全部对象」清除此次入口带来的数据集、品种文本与来源限定；任务状态切换仍由用户控制。
- 通过左侧导航直接进入任务页时保持常规任务浏览，不虚构来源详情或返回入口。
- 无记录时区分「该行情暂无维护任务与记录」和「当前筛选下没有任务记录」，保留修改筛选及返回入口。

### 6.3 返回与进一步跳转

- 返回原行情管理页时恢复原分类、固定版本、滚动位置和触发链接焦点。
- 再返回自建行情列表时恢复进入该行情前的筛选、列表位置及选中行。
- 任务详情的「查看行情管理」能够返回对应任务列表及任务行，不覆盖最初的来源上下文。
- 浏览任务、改变筛选或关闭窗口不创建任务、不启动采集，也不改变行情或维护配置。
- 导航上下文限定于当前窗口／工作区，防止其他工作区或旧会话的来源位置混入。
- 来源路径使用受校验的内部位置；为详情路径扩展返回能力时仍只允许已知的数据中心路径、合法对象身份及有界参数。采用有界上下文记录或导航栈，避免递归嵌套 `return_to`。
- 用户主动转入其他数据集时，返回按钮文字仍应准确指向实际来源，不将初始品种当作当前查询品种。

## 8. 实施顺序

1. 固定远端 main 基线，建立独立 worktree／分支，记录现有入口与操作行为。
2. 完成管理页骨架和概览周期列表，确定表头、分组、列宽和滚动规范。
3. 依次整理覆盖与质量、发布版本、维护设置、组合与引用，复用同一控件与详情规范。
4. 实现任务入口的完整上下文、默认全部状态、查询展示、返回与筛选解除。
5. 在 Ubuntu 独立 Docker project 运行原生与兼容窗口验收，修复问题并留存结果。
6. 完成交付文档、源码差异和验收资源精确退役。

## 9. 验收标准

### 9.1 布局与控件

- 五个分类可进入、关闭并恢复位置；顶部与导航不遮挡内容或键盘焦点。
- 概览周期正确分组，表头与数据对齐，状态、计数和版本说明一致。
- 深浅主题、375px／768px／1440px，原生与兼容窗口均可操作；整页无横向溢出。
- 使用真实浏览器 200% 缩放验证表头、分类导航、滚动条、控件与详情；不以单纯缩小 viewport 冒充真实缩放。
- 正文滚动顺畅，表头吸顶无叠盖；复杂表的横向滚动范围明确。
- 更多菜单、下拉、高级折叠和详情支持键盘操作，关闭后恢复焦点。
- 首次加载、读取失败、空结果、提交中、提交失败及成功反馈清晰，旧结果与表单输入按现有契约保留。

### 9.2 导航与查询

- 从某行情概览进入任务页：品种预填、来源／日界展示准确，默认全部状态且只查询该数据集。
- 同商品代码、不同来源或日界的数据集不会混入结果。
- 没有任务时仍展示查询对象与返回入口；切换状态的空结果说明准确。
- 编辑品种查询能够解除旧数据集限定；「查看全部对象」清除入口产生的筛选。
- 返回行情详情恢复原分类、版本、滚动位置与焦点；再返回列表恢复筛选和原行。
- 任务详情打开行情管理再返回，恢复对应任务列表与行；导航不形成循环或丢失来源。
- 左侧直接进入任务页及其他工作区的任务页，不出现错误的来源返回入口。
- 浏览与筛选只产生必要读取；不提交维护、采集需求或控制命令。离开／关闭取消所属轮询和请求，迟到结果不覆盖新页面。

### 9.3 业务回归

- 打开图表／回测指向实际选择的固定版本。
- 覆盖、未知、已证实闭市、冲突和历史请求失败的含义不混淆。
- 维护计划保存、指定区间补数／复查、暂停／恢复与归档操作目标正确。
- 重复提交防护、未保存离开保护、配置冲突处理与引用保护有效。

## 10. 环境与交付

开发、验证和验收仅在 Ubuntu 本机独立 Docker project、网络、数据库、volume 和端口执行；使用 `mw-docker build` 或 `compose-build`，明确 task、project 和用途。

交付包含：实现差异、实际访问地址、启动／停止命令、原生与兼容窗口截图、验收用例及实际结果、模拟数据与真实业务验证边界。

验收完成后以 `mw-docker retire --task TASK --project PROJECT` 查看精确清单，再执行 `--apply`；如包含数据库或数据卷，先备份并实际恢复校验。凭据、私钥、许可资源与完整浏览器状态不提交仓库。
