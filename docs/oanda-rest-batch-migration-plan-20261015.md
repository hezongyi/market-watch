# OANDA 批量 REST 替代报价流实施方案

日期：2026-10-15。状态：主要路径已实现，r5 定向与 REST 系统验收证据已形成；原生 chart-origin 端到端验收因缺少私有供应商包待补，PR 尚未提交，生产切换未完成。
依据：用户认可默认每 2 秒批量 candle 替代 OANDA 实时流，以当前未闭合柱 close 接替看盘最新价
和采样式盘中告警；本次不接入 pricing，不获取独立 Bid/Ask 报价对。
代码分析基线：`v1.25.6` / `ee5b885626104577244f4fc40342d60b1a52c664`。
当前工作树为独立验证分支；定向测试和 Ubuntu preview 证据不等于发布候选或生产验收。

## 已确定的方向与行为

1. OANDA 日常看盘、组合实时尾部、最新价和告警由后端共享批量 candle 采集。
   默认每 2 秒一轮为正常目标；不承诺所有网络条件下每 2 秒完成。
   周期可配置，1 秒仅保留为后续可选值，不作为本次默认或已完成的系统能力。
2. 保留采样式盘中价格告警、盘中指标告警、收盘告警、组合输入确认、启动恢复、
   缺口补齐、闭市调度、鉴权维护与数据中心健康状态。盘中价格告警使用每次取得的当前
   未闭合 M1 close；不是等待分钟闭合。可能遗漏两次采样之间的短暂触价或无法还原先后
   次序，用户已接受此取舍；证据记录真实观察间隔和价格类型。
3. 正常模式仅使用批量 `candles/latest`，不接入 `pricing` 或新的报价流。
   一个参数组每轮一批进入统一所有权、需求和发布机制，前端继续一个主 SSE。
   保留原蜡烛价格口径（例如 BID OHLC），无需同时获取独立 Bid/Ask 对或显示价差。
4. 固定历史、组合修订、来源账户、BID/ASK/MID、非平滑口径、NY17/UTC0/DST、
   成交量语义与既有策略证据保持原有归属。协议切换有新的采集世代和证据标签。
5. 确认柱使用供应商 `complete=true`，未完成柱保持 provisional；不伪造 complete、
   成交量、报价时间、可交易状态或覆盖证据。固定确认数据不会被形成中柱回退覆盖。
6. 前端继续 HTTP `getBars` 获取首次和历史数据，`subscribeBars` 消费共享 SSE。
   本次不新增前端供应商直连、不新增 SSE 出口、不改自动下单能力。
7. 默认按现有图表、自选、告警、策略、修复和 resident 需求取数；不是无限全目录轮询。
   浏览器关闭不能终止活动告警的需求。Yahoo/Binance/Dukascopy 的采集模式不随此改动。

本方案没有必须先由用户回答的阻塞问题。“每 2 秒 candle close 采样、无 pricing、接替验收
后暂停流”是已认可方向。历史告警证据保留；存量 tick/intrabar 规则在新采集世代下建立
close 采样基准，并明确新的观察方法。后续交易报价按下述 MT4 边界另行设计。

### 后续 MT4 交易报价边界

未来接入 MT4 交易时，执行报价取自实际交易的 MT4 经纪商，包括 Bid/Ask、来源时间、
价差与交易状态；届时按该交易端的能力确定接口和更新机制。OANDA candle close 继续作为
看盘和信号输入，不作为 MT4 可成交报价，也不因未来接入交易而提前引入 OANDA pricing。

信号保留 OANDA 或组合行情的完整来源身份；执行前另外校验 MT4 品种映射、报价新鲜度、
价差及信号参考价与执行报价的偏离。两端存在价格差异，不能按同名品种直接混用。
本次只明确来源与接口边界，不实现 MT4 接入、交易风控或预建交易框架。

## 实测依据与边界

见[完整验证报告](verification/oanda-rest-1s-20261015.md)。Ubuntu 单品种最近 3 根 M1
持续 5 分钟：299/299 成功，中位数 302 ms、P95 457 ms。
12 品种每秒批量最新蜡烛持续 2 分钟：120/120 成功，中位数 295 ms、P95 416 ms，
每批约 3.7 KB 正文，网络获取及解析 CPU 约占一核 0.14%。本次首次取得 M1 确认值
在闭合后约 1.3～2.3 秒；批量接口返回每品种两根最新柱。

以上不是完整系统负载或长期供应商 SLA。全部存量订阅、指标计算、close 采样告警和图表
绘制属于实施验收，不能用当前网络探针结果代替。
已有缓存/调度设为 1 秒后实际可能约 2 秒刷新；携带 `to=本机当前时间` 时还出现供应商
未来时间拒绝。仅回退 HTTP 时间而不统一读取边界，会造成重复补取。正式实现必须消除
这些问题，不把实验保护代码直接搬入生产。

用户后续认可将默认周期从 1 秒调整为 2 秒。单参数组全天持续运行的请求量从约 86,400
降至 43,200 次，按实测批量正文估算约 160 MB/天（不含协议开销）。此为按周期估算，
不是新的 2 秒真实负载测量。既有 1 秒样本降频模拟提示闭合确认仍有望控制在数秒内；
正式验收需以真实 2 秒调度复测，不能将原探针或旧缓存偶然约 2 秒刷新视为验收。

|---|---|---|
| OANDA 当前柱 / 专业图表 | 批量 `candles/latest` | 供应商 OHLCV；当前柱 `complete=false` |
| 平台原生周期 | 同一批中登记原生周期规格 | 保留供应商周期参数，不能统一换成内部 M1 聚合 |
| 组合行情实时尾部 | 批量 M1 加固定历史与规则聚合 | 保留接缝、日历、来源分段、确认和覆盖状态 |
| 组合固定确认输入 | 已确认 M1 经规范化、不可变修订和输入日志提交 | 复用 `confirmed_minutes` / `composite_inputs` 契约 |
| 数据集旧 Bar / 历史消费者 | 规范化确认结果进入原有 ingest 与修订逻辑 | 不覆盖无关 Instrument、来源或发布历史 |
| 自选表、最新价 | 当前未闭合 M1 close | 标明 candle close；无当前柱时展示确认收盘但标为 stored，不能伪装即时值 |
| 原即时价格预警 | 连续有效的未闭合 M1 close 观察 | close 采样穿越、去重、实际观察间隔、断线恢复基准；接受短暂触价遗漏 |
| 组合盘中告警与指标 | 同一 REST 未完成 M1 快照 | 价格操作数与指标同快照；未确认前缀仍受覆盖门禁约束 |
| M1 及高周期收盘告警 | 已确认输入、聚合水位与既有证据规则 | 不以 HTTP 成功代替依赖准备完成，不补发旧穿越 |
| 启动 / 短断线 / 长断线恢复 | checkpoint 起点的有界历史 REST 补齐 | 最新两根不能证明中间缺口已修复 |
| 来源健康 / 数据中心状态 | 实际 REST 请求、柱所属时间、完整性和连续确认水位 | 替换心跳/Bid/Ask/tradeable 门禁；区分采集健康和当前价格有效 |
| 日线原生确认 | 保留 ADR 0003 的独立原生 D1 证据获取 | 不放宽分钟覆盖或成交量完整性 |

### 批量最新蜡烛与历史 API

- `GET /v3/accounts/{accountID}/candles/latest`：同账户、同一组日历/平滑/单位等
  请求参数下，将需要的 `instrument:granularity:price` 合并为一个规格集合。
  如 `EUR_USD:M1:B`、`EUR_USD:H1:B` 可进入同一批；不同口径的请求分组，响应分别校验。
  按完整身份共享，一个用户或一个图表不能另起一套同源采集。
- 最新价和盘中告警使用该响应的当前未闭合 M1 close。只有自选表或盘中告警需求时也登记
  M1 规格。平台 H1 等原生图表可另外登记对应原生周期，但不能用 H1 close 的更新时间
  替代 M1 当前价格观察。close 不提供逐笔发生时间，记录为蜡烛快照观察。
- 历史接口：需要历史时按品种和明确区间调用；供 `getBars`、预热、拖动、断线补齐、
  旧柱修订核对使用。取数边界使用有界的来源时间规则，避免请求未来 `to`。

candles/latest 的 `units`、BID/MID、平滑和日历参数需与当前单品种确认通路逐项对照；
必须以闭合柱 Decimal 数值、量口径和账户证据验证等价，不因显示代码相同合并。

## 后端所有权、调度与缓存

实现一套 OANDA 采集所有者，使用现有账户范围租约、续租与世代隔离。
采集模式使用明确 `stream` / `rest_batch` 配置，REST 为验收后切换的目标模式。
旧流代码短期保留以便回滚；不同模式不能同时拥有同一账户的写入权。
切换模式、账户或租约持有者时，旧模式在途结果必须在提交前失效。

接收结果和业务处理分开：所有 HTTP 在数据库事务外；提交前验证所有权、模式世代、
需求版本、请求参数和响应身份。每个批量响应拥有采集序号与接收时间，单品种再有独立
蜡烛快照序列、水位与健康状态。不是每次成功 HTTP 都发布新的 input revision。
仅数据内容变化时产生修订，未变化结果只更新有限健康信息。

调度规则：

1. 以 monotonic 时间按配置周期启动一轮，默认每 2 秒；不采用“请求完成再 sleep 2 秒”。
   每个批量请求只有一个在途操作；超时或慢响应错过时刻就跳过，不能排队追赶。
2. 同一参数组正常一轮为 1 次 candles，默认约 0.5 请求/秒；在现有预算内给历史修复留余量。
   多参数组共享额度，每组有独立截止时间与取消条件，不把多组响应伪造为同一快照。
3. 复用连接、批量去重、需求租约合并；同源平台/组合能共享的规格只发一次。
   不重复运行旧 provider 15 秒取数和新采集器来获取相同最新规格。
4. 一轮取得的新数据直接进入共享缓存；消费者读最新已提交版本，不各自向供应商请求。
   刷新调度由采集器维护，不再由消费者 TTL 触发每隔 2 秒取数；缓存仍保留数据新鲜度门禁。
5. 对 OANDA 实时、交互和修复预算统一登记。当前实时通道 2 请求/秒不是可随意超用的额度。
   多参数组、更多品种拆批或额外修复需提前预算、验证供应商批量上限，必要时有界配置额度。
   超预算时优先活动图表和告警，报告实际周期与积压，不能静默宣称全部按 2 秒刷新。
6. 401/403、429、供应商维护、网络超时分别处理；用共享退避/冷却，避免每秒错误风暴。
   单品种缺失或没有当前柱单独标记，不用一条坏品种把其他品种的健康状态一并清空。
   开闭市和休市探测沿用独立来源会话证据，日界线不能代替闭市证据。

REST 模式的启动/鉴权探测用账户目录和真实蜡烛请求证明访问能力；当前
`validate_access` 内的 pricing 探测不能作为新模式的必要步骤。自选表首读、旧
`quote_page`、状态轮询及降级路径也必须读取共享 candle 快照，不能暗中继续拉 pricing、
启动流或为每个消费者增加一套最新蜡烛请求。

长期健康不以旧 streaming heartbeat 是否存在判断。区分最近尝试、最近成功响应、
柱 start/end、请求/接收/提交时间、连续确认水位、恢复状态和业务依赖就绪。
close 未变化不意味着断线；成功响应中存在本分钟的有效未闭合柱，可作为当前价格观察，
但无法证明最后一次价格变化的准确时刻。HTTP 成功而只返回旧分钟，不得刷新当前价格
新鲜度。无 tradeable 字段时保持未知，用独立来源会话规则调度，不以缺柱或静止价格证明闭市。

## 蜡烛快照、固定输入与图表交接

### 替换当前 provisional 的来源

当前 `display_observations.accept` 以报价累积 OHLC、volume=null。
新 REST 路径需存储供应商未完成 M1 的完整快照：OHLCV、complete、source identity、
采集模式/世代/序号、request/receive time；不会继续由 `publish_event` 累积形成中 OHLC。
REST 更新是整根快照替换，不是只扩大旧 high/low；供应商可能修订形成中数据。
相同柱的旧响应不能回滚新响应，确认后的柱不能被 provisional 覆盖。
`LiveState.forming` 如为兼容保留，改为同一 REST 快照的投影；最新价也引用该快照，
不能另行维护一套 OHLC 或伪造 QuoteEvent。
`provisional_input`、display snapshot、current bucket 缓存都要识别 REST 快照来源；
不能让 snapshot token 继续引用已变化的可变行。

`complete=true` 且时间已闭合的 M1，进入原有来源不可变修订、固定组合输入和确认水位。
本次移除正常实时批量确认的固定 5 秒等待；使用供应商 complete、实际时间边界和来源契约。
历史补齐仍使用明确查询区间与 checkpoint。latest 仅返回有限的柱，不能把中间未查询区间
写成全覆盖；最大 confirmed_end 与连续恢复水位分别维护。

### 保证原生图表可接受的顺序

`subscribeBars` 当前只接受最新柱或新柱；`bridge.js` 还过滤 `bar.time < sub.last`。
因此不能先画新柱，再把上一根最终值塞进同一回调期待它修改旧柱。

新柱交付前：

1. 规范化整批数据并提交上一根确认输入，更新组合聚合依赖。
2. 生成同一已提交快照下的上一根最终柱与新柱。
3. 按时间升序先回调上一根最终值，成功接受后再回调新柱。
4. 前端按实际成功回调记录接受凭据；后端推进该订阅的接受边界，不能只因发送就认为接受。
5. 同快照协调主系列、Python 指标与最新价展示，保留世代 fencing 和迟到结果拒绝。

latest 的返回和供应商确认仍可能出现边界缺柱或异常顺序，实施不能只依赖本次正常样本。
上一根未确认或不在返回范围时，暂缓该图表新柱交付，按来源时间补取所需分钟；
自选表最新价可展示有效新分钟 close，并说明图表等待确认，不将其写入旧柱。
水平价格采样告警仅在已满足恢复/输入门禁时处理新观察；依赖主柱及指标的盘中告警
等待同快照交接就绪，不绕过未知前缀或重建未观察价格路径。
等待超过看盘新鲜度窗口（沿用现有 15 秒门禁为首版基准）时标记“等待柱确认/恢复”，
保留已画数据，不伪造确认、不把新柱和旧数据混在同一接受凭据中。对应 M1、跨高周期边界、
无交易分钟和数据撤回分别测试，不保证任何缺口都能延迟几秒解决。

正常尾部完成、确认标志或 volume 补齐，不应触发整图 reset；必须先把真实最终值送到图表，
并更新依赖它的指标。已交付最终值的历史柱后来价格/volume 真正变化、旧柱撤回、实际缺口、
版本/账户切换仍保留受控恢复。不能通过忽略 volume 或关闭全部 reset 获得“无闪”。
固定历史窗口没有尾部回调，仍需按其接受快照判断历史修订。

## 当前价格与告警接替

新增明确的 candle close 观察契约：完整来源身份、柱 start/end、close、complete、
采集模式/世代/序号、请求/接收/提交时间、快照版本、恢复状态及实际采样间隔。
接收时间是观察时间，不是成交或逐笔报价发生时间；柱 start 也不能用作每次采样时间。
响应属于旧柱、当前柱缺失、lease 过期、恢复未完成或数据不合法时，停止新的盘中判定，
展示保存值并明确其状态。成功且值未变化时仍记录有界健康信息，但不重复通知或重算指标。

存量 tick 价格规则和组合 intrabar 规则接替为 close 采样判断；建立明确的观察处理入口，
可复用 `crossed` 的数学判断与现有通知去重，不直接调用必须有 Bid/Ask 的 `evaluate_quote`
并捏造 ask=bid。去掉消费者对 quote.source_time、quote.tradeable、价差和流心跳的必要
依赖，以合法快照、来源会话、采集新鲜度和确认/恢复水位替代。旧 Quote 数据与证据保留。
UI 对这类告警说明“当前价格采样”，保持方向、阈值、触碰/穿越配置；切换时重建基准。

穿越以两次有效 close 观察判断：99→101 跨越 100 可通知；99→101→99 若两次采样均为
99 则允许漏报。不能用累计 high/low 补发穿越，不能将告警创建前的本分钟极值视为新触价。
首个样本只建立基准，同快照重复/旧世代样本无效；同价有效观察不重复通知。
当前 M1 变更时，按顺序先处理已接受的上一分钟最终 close，再处理新分钟有效 close；
仅在同源连续恢复与门禁均满足时延续基准，异常缺口或迟到历史修订只恢复基准、不补发通知。

盘中价格操作数使用该告警快照的 close；依赖指标和画线的判断要求主柱、指标、时间坐标
与该快照版本一致，不能把下一分钟 close 写入上一分钟柱。收盘告警只使用完整确认输入
和相应固定指标水位。平台与组合价格身份各自明确，不让同名品种互相替代。
共享需求确保关闭页面后，活动 tick/intrabar 规则仍按默认 2 秒周期获得 M1 快照。
断线、身份/模式世代改变、真实观察缺口后重建基准；恢复历史不回放旧通知。
沿用 ADR 0003 的价格证明与覆盖要求，不借此次迁移放松策略判定。

## 实施顺序与交付边界

1. **接口和契约**：对照同账户 REST 闭合 M1；明确规范化、快照版本、close 观察、
   请求覆盖与完整身份。评估最大批量、多个参数组和资源预算。
2. **后台接替**：实现批量调度、所有权 fencing、规范化写入、蜡烛/当前价格健康和恢复。
   在 Ubuntu 独立项目测试；现有流与候选 REST 不同时写同一测试账户数据集。
3. **消费者接替**：组合/平台缓存、形成中柱、固定确认输入、主 SSE、自选表、指标和
   所有告警类型迁移；拆除流心跳作为必要条件，加入有序换柱和实际接受确认。
4. **隔离完整验收**：原生图表及数据一致性、12 品种负载、暂停/关闭图表后的后台告警、
   参数差异、网络与鉴权故障、重启/补齐/模式切换逐项验收。形成可 review 的 PR。
5. **正式切换**：review、测试通过后，按后续明确发布授权备份并发布；REST 取得新世代
   所有权，旧流停用，生产验证无旧流连接和重复采集。设置采集模式必须持久化到实际配置。
   本轮认可允许形成和执行开发方案，不自动代表现在停生产流或发布。
6. **回滚**：恢复旧模式配置、提升采集世代、让在途 REST 失效，流重新补齐并建立告警
   基准；固定历史、已确认输入与证据仍保留。旧代码是否删除另行在运行稳定后处理。

## 验收标准

### 数据与调度

- 12 品种、正常单参数组，candles 以 2 秒为目标节拍；正常稳定窗口请求
  起始间隔中位数在 1.9～2.1 秒，P95 不大于 2.5 秒，无意外重复请求。
  慢请求有界跳过，不补发追赶；每个图表、自选和告警消费者不得各自重启调度。
  实际完成时间、柱时间、快照 age 和门禁等待独立统计；不能用请求次数替代实际更新率。
- 未变化数据不反复写不可变修订或 input_revision；重复消费者不增加同源规格请求数。
  采集、PG、指标、SSE 与浏览器 CPU/内存/WAL 分别记录，比较当前基线；完整预算通过
  实测确定，不把网络探针的 0.14% CPU 当作系统预算。限流/超时率纳入报告。
- 比较相同账户、口径、参数、时间的闭合 REST 柱，Decimal 归一化后 OHLCV 一致。
  首版停止切换条件：未解释的不一致、实际中间缺口、观察身份错误或确认回退。
- 正常样本中 M1 闭合到首次供应商确认目标 P95 不超过 5 秒；未满足时明确分解来源、
  网络、调度、入库、聚合和投递耗时。异常供应商迟确认不被伪造或忽略。

### 图表与功能

- EURUSD / XAUUSD 的组合 M1 和平台 M1，带 Python Supertrend，至少各观察 15 分钟
  （可并行）。正常换柱无 `history_changed` / resetData，录屏检查蜡烛和指标无消失闪烁。
  有效真实历史修订仍修正数据；“0 reset”不作为掩盖修订的目标。
- 增加跨 M5/H1 等周期边界、NY17/UTC0、DST、固定历史窗口、比较系列、参数差异、
  高频切周期、拖动补历史、切换品种、页面暂停恢复验证。
- 只有自选表、只有后台告警、关闭全部图表后仍有活动告警的场景，按需求继续采集。
- 存量 tick / intrabar / close 告警建立有效新基准，正常事件只通知一次；验证 close
  静止、持续穿越、短暂触价漏采样、创建前 high/low、重复/乱序快照、分钟交接、
  当前柱缺失、短断线、长断线和旧事件恢复。记录观察方法，验收无虚假 Bid/Ask 或 tradeable。
- 缺形成中柱、上一根迟确认、部分品种缺失、过期/重复/乱序响应、两根范围之外的缺口、
  401/403/429、维护、网络超时、租约丢失、双实例抢占、账户/模式切换可自动化验证。
  网络 I/O 不持有数据库写锁；失效世代不能发布、改变业务状态或发送旧通知。
- REST 模式启动、正常更新、鉴权恢复、自选首读及降级期间均没有上游 streaming 连接或
  pricing 请求；旧 provider 取数不重复获取已由批量拥有者
  负责的规格。生产与开发的模式、请求类型和实际活动拥有者可从状态及日志核实。
