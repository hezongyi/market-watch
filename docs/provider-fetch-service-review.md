# 平台取数方案独立复核

日期：2026-10-01。评审模型：用户指定GPT-6.1-Sol，reasoning effort=max。独立agent `/root/provider_plan_review` 只读审查方案、现有接口/取数代码、原生公开类型声明及24次批量请求证据，没有运行供应商请求、数据库验证、故障注入或浏览器。本文由主agent整理完整返回报告；复核当时仅修订文档、暂不实现。后续已获实施授权并开始候选源码开发，当前状态见[实施记录](chart-dual-dataset-implementation.md)；下文是评审时的结论，不是新代码验收。

## 总体结论

**修正后可实施。** 后端集中取数、独立平台范围缓存、按需先返回的方向合理。datafeed会明显简化，全系统复杂度则取决于是否保持一个完整读取契约、一套共享任务状态、一种订阅传输。复核不是性能验收，不能据此宣布目标已经达成。

## 必改项与方案修正

1. **高：相互冲突的取数和预热规则。** 草案开头已确认首次按需，但原98/227行残留冷首屏4000建议，原129/131/137与后续168/186的两轮预热也冲突。已删除冷首屏整批选项，最新窗口/历史窗口改为引用两轮建议；最初的用户想法单独作为来源保留，不作为有效实施规则。

2. **高：后端读取契约还不能替代前端分页。** 当前`backend/alerts/chart_api.py:53`的DataQuery只有before/limit，最多2000；原生`advanced-host/charting_library/datafeed-api.d.ts:920`规定countBack优先from、to排他。若原生请求4500，不能删掉前端分页后只交付2000。方案已要求后端接收原生需求、内部供应商分页，一次返回所需数据或确认的真实边界；Python计算历史另外准备，原生指标需求不重复加算。资源拒绝明确报错，不静默截断或把分页放回桥接。

3. **高：已发出的4000请求无法靠提高优先级抢占。** 当前`backend/alerts/provider_chart.py:131`及`:170`包含较长HTTP/整体预算。方案已区分待启动任务提升/拆分与已发出单页共享；后者等待纳入前台耗时，前台不等其剩余页。每个等待者独立截止/取消，取消一个不能取消其他共享需求。每源后台最多一页在途，页间重新检查优先级并轮转。允许此类样本超目标并记录，不能同时承诺绝不重复和瞬间服务。

4. **高：覆盖证明和并发写入需要防回退。** 当前`provider_chart.py:239`仅按批次数量判断边界，尚无持久覆盖证明。方案已要求供应商返回实际查询覆盖、分页游标及边界依据，bars/覆盖同一短事务提交；不把未取得部分记为覆盖。租约有执行代次，失效执行者不能提交；同范围冲突复查串行，旧观测不能覆盖较新末根，complete不回退。首版同步落库，清理同步裁剪覆盖和失效内存版本。

5. **高：历史修订和断线不能全部用subscribeBars推送解决。** 原生`datafeed-api.d.ts:342`的onTick用于末根更新和追加，`:349`提供历史reset回调，`charting_library.d.ts:10894`提供resetData。方案已区分末根更新/顺序追加与已加载历史失效，后者用公开reset/reload并保视区；新预热缓存本身不reset。首轮历史响应与订阅注册需通过末根时间/修订游标衔接，避免注册间隙漏数。

6. **中：活动期限、订阅和多会话目标需要统一。** 一处说10分钟过期停止，一处又允许订阅完成预热；全局最新锚点也可能覆盖其他图表/用户。方案已规定目标按会话归属、数据/任务全局共享；有效订阅保留本轮有界目标，心跳仅续租不造新目标；只有失去全部有效兴趣时才停未启动任务。订阅标识包含会话、listenerGuid和代次，重连先恢复游标与缺口。

评审行号为agent读取时版本；部分冲突段在最终报告返回前已由主agent按初步反馈删除。新补充规则见[方案中的复核后规则](provider-fetch-service-proposal.md#复核后的完整读取与共享任务规则)。

## 首版范围与待定参数

建议分三步：完整读取入口＋独立缓存bars/覆盖＋同步短事务＋共享任务；再集中最新尾部更新和一种订阅传输；最后有界基本窗口及4000后台深度。可选方向预测、切回宽限、异步落库先不加入。共享开发DB连接总预算8保持不变。

实施设计必须给出默认值：最新数据允许年龄、传输方式、前台截止时间、后台共享额度、每会话目标上限、缓存总容量。600/1000基本窗口、左右缓冲、400–600触发阈值、活动/租约时长、15秒轮询、7天保留等属于可配置测试参数，不能把讨论数值冒称已获用户逐项确认。

## 性能证据与限制

已有24次对照是复用连接、有代理、无落库/浏览器、每组4次，支持批量吞吐比较，不能支持完整冷首屏或p95保证。H4/4000最大约2049ms。验收需固定缓存冷/热、连接冷/热、需求数量、指标和测量起止点，分别记录数据显示与工作区初始化；保存失败/超时，在八图及后台预热并存时检查自建实时/预警延迟。新方案未实施或验证。
