# 自建周期物化与快速读取验收

## 目标与范围

自建创建／维护时在后台连续完成所有配置周期的持久产物；维护成功以这些产物发布完毕为条件。查看直接读取已存产物，不依赖打开图表建立需求来唤醒旧历史。支持周期按模式决定：M1派生为九周期，D1派生为日／周／月，原生周期按该源实际支持的已选周期。

F1：重要后台调度和冻结数据读取行为变更；无 schema／持久格式迁移。验收使用 Ubuntu 隔离 PostgreSQL，部署只定向更新持久开发实例 `mw-dev` 的 api、data-worker、market-runtime。保留数据库、来源开关、真实规则、通知和下载配置。

## 实现

- 固定自建历史不再因为独立图表计划取消且无查看需求而暂停派生。明确关闭的实时映射兼容目标仍沿用原有控制，不自动开启采集。
- 旧历史价格任务最多七个聚合日／64条任务合批，跨周期共享M1输入；近期、成交量、新鲜度和重试仍使用小批次。覆盖发布按索引读取，内容修复优先于新鲜度刷新。
- 组合历史及确认尾部读取物化周期。只对临时观察所在的可见桶叠加；相邻桶合为不超过32天的读取，M1去重使用集合。普通读取与实时冷／暖缓存共用此规则；单桶保留增量缓存。
- 待确认观察容量提示进入非阻塞 `warnings`，真实未完成的历史／指标仍使用 `pending`。容量提示不再制造额外历史页。
- 实时暖缓存的确认增量显式绑定选定 input_revision，防止返回旧快照时混入新修订价格。
