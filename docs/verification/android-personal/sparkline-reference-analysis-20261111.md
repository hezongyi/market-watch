## A 结论

当前实现已有面积填充，但没有渐变。密集行情点、偏窄图幅和硬底边共同放大了生硬感。

此前迁移保留了走势功能，却没有把小图的视觉细节打磨完整。现有 SVG 足以实现参考图质感，无需引入 UI 库。

## C 原因与建议

| 维度 | 当前证据 | 建议 |
| --- | --- | --- |
| 面积填充 | 固定 8% 透明度，整块同色 | 上部有颜色，向下逐渐透明，消除硬底边 |
| 线条 | 1.4 CSS px，未设置圆角连接 | 初试 1.1–1.3 px，使用圆角连接与端点 |
| 点密度 | 后端最多返回 1600 点，前端逐点连线 | 按实际绘图区宽度简化显示点，保留峰谷、端点和缺口 |
| 图表宽度 | 原截图约占屏宽 35%，参考约 44% | 给图表多一点横向空间，同时保证代码和价格可读 |
| 参考线 | 当前是竖向时间分界；参考有横向虚线 | 二者含义不同，不直接互换；先减弱竖线视觉权重 |
| 终点 | 当前有突出圆点，参考未见突出圆点 | 弱化或去掉圆点，让走势轮廓成为重点 |

宽度比例按两张原截图粗略估算，并非统一 CSS 尺寸测量。

填充可先试顶部 18%–22%、中段 6%–8%、底部 0%。这是一组调试起点，需分别检查浅色和深色背景。

参考图仍有真实行情折角，并非光滑的装饰曲线。优先处理线宽与点密度，不用强平滑抹掉尖峰。

## D 渐变不能解决的部分

当前横轴按完整日界窗口绘制，并保留尚未到达的时间。外汇采用纽约 17:00 日界，其他资产默认 UTC 日界。

这会让刚进入新窗口的外汇只显示左侧短线。按完整日界绘制的股票，也会留下较长的非交易时间空白。

参考图的曲线看起来更铺满。仅凭截图无法确认其时段压缩与缺失数据规则。

本轮建议保留已确定的时间语义。若后续希望股票铺满小图，应单独定义交易时段轴。

参考图采用红涨绿跌，当前采用绿涨红跌。借鉴线条和填充即可，配色沿用当前全局规则。

横向虚线是否代表昨收，截图无法证实。当前 Sparkline 响应没有昨收字段，不能画一条任意横线冒充基准。

## E 推荐调整顺序

1. 先改渐变、线宽、连接圆角和终点样式。
2. 再用真实行情检查密集折线，决定显示点简化规则。
3. 对比窄屏长代码与大价格，调整图表列宽。
4. 保持缺口断线、未来留白和缓存状态表达。

第一步即可改善面积块的硬边。第二步解决 BTC、ETH 一类密集走势的粗糙感。

本轮没有修改应用代码、打包或更新验收实例。

## F 代码依据

`web/src/mobile/WatchPage.tsx`：Spark 使用纯色面积、1.4 线宽和半径 2 的终点。

`web/src/mobile/sparklines.ts`：逐点直线连接；每个数据段封闭到底边；保留时间缺口。

`web/src/mobile/watch-a07.css`：图高 42px；左右信息列占固定宽度，小图使用剩余空间。

`backend/alerts/sparklines.py`：最多读取 1600 点；定义日界窗口并返回真实行情点。
