## 动效能力与候选建议

已核对固定图表库 v31.1.0 的原生 Dialog 模块 491617、原生通知样式、运行中元素动画列表。当前原生 Dialog 是定位/外观容器，没有可直接启用的 slide/enter/exit 参数；公开 `showNoticeDialog` 参数也只有 title/body/callback。同实例原生实测进出均无动画，未发现可直接启用的原生滑入/滑出效果。当前 `NativeInstantNotice` 在 bubble 清空时立即销毁 surface、卸载内容，单加退出 CSS 动画不会完整执行。

**以下是建议，尚未得到用户实施确认，不写入已生效合同：**

- 延用原生 Dialog/NavButton/主题，在呈现层补动画，不引入新 toast 框架或恢复旧 UI。
- 出现：从当前位置上方短距离下滑并淡入；消失：从当前位置向上回收并淡出。可先预览 16–24px 位移、约 200–240ms 入场、约 140–180ms 退场，不视为原生自带参数。
- 只动画 transform/opacity，不动画 top/height，不挤压图表。保持外壳 translateX(-50%) 定位，纵向动画置于独立层，裁切在通知展示区域，避免扫过工具栏或自选表。
- 不抢焦点、不加遮罩、不扩大点击拦截；prefers-reduced-motion 时取消位移，采用立即显示/隐藏或极短淡变。
- 系统 8 秒及悬停/焦点暂停、交易必须确定等既有规则不变。确认/上传等业务处理不依赖 animationend；退出需短暂保留呈现快照并有清理兜底，不能使旧卡按钮继续操作下一条。
- 同条状态/时间区更新不重播入场。交易抢占系统、快速连续新告警或退场中来新消息时动画可中断，业务队列与优先级不被动画延迟；历史消息不因动效补弹。

UI/UX 参考采用当前 session 已用的 ui-ux-pro-max 指南，定向检索 `notification animation reduced motion`：减少动态效果、避免过量动效、时长随场景实测。本轮没有修改产品源码，图片为现状和原生参考，尚无改后动画预览或录屏。

## 用户补充：需要辨认相邻消息的替换

用户说明实际问题是“下一条直接覆盖，不盯着看就难以察觉换了新消息”。建议把动效验收重点从单纯出现/消失改为**不同事件接替时有清晰边界**，当前仍只记录，未确认最终参数或实施。

- `NativeInstantNotice.tsx` 的原生外壳生命周期依赖 `!!state.bubble`，内容组件以事件 ID 为 key；连续有消息时外壳可保持挂载，内容直接变化，没有换条反馈。
- `runtime.ts` 的 `dismiss/pop` 使系统消息按现有队列接替；`confirmAlert/restoreAlerts/pop` 使交易告警在确认后接替。新交易不会自动替换未确认交易，只加入持久队列并更新待确认数量；交易可以抢占系统提示。动效不能改变这些规则。
- 推荐不同事件接替时让旧内容向上轻退、新内容从上方轻入，避免文字直接交叠；只有新事件触发，同事件状态、时区、文案或计数更新不重播。无需默认增加闪烁、声音或换条序号；先预览轻量过渡的可察觉程度。
- 短暂动效能增加余光察觉机会，无法保证用户完全没看时仍知道换过消息；通知中心和告警模块保留既有历史入口。现有系统未读数、交易待确认数都不能冒充“刚刚换过几条”。如果需要持久换条标记，另行确认。
- 后续验收需覆盖：相似标题/正文连续接替、确认后接替、交易抢占系统、同事件更新不重播、快速抢占可中断、减少动态效果、旧按钮不操作下一条。此处为待验收清单，未运行改后场景。
