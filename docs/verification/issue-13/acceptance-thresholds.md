# 核心改造前冻结的数值门槛

冻结日期：2026-10-07；依据为 [12份四场景基线](pg-baseline-report.md)、[消费者微基线](results/consumer-microbaseline.json)和正式方案。目标是后续通过条件，不是当前已经通过。已完成的API重复读小修复不作为核心性能优化的基线替代。

| 指标与范围 | 门槛 | 当前证据 / 对照约束 |
| --- | --- | --- |
| 真正空闲worker CPU | 单核百分比≤5%，且降低≥80% | 旧三次均值26.04%；必须相同配额、同输入、可比较宿主竞争；整合主线复测后比较，不改变5%/80%目标 |
| 真正空闲worker SQL | ≤2条/秒且降低≥90% | 旧均值38.91/s；低频维护扫描单列，正常路径无审计读、历史重算或发布记录写入 |
| M1输入提交到发布可见 | p95≤15秒、p99≤30秒 | 分开记录新分钟、同价观察、价格与量修订；至少每身份两种实时输入；最后30秒截尾单列，其余未发布分母为0 |
| 可运行目标等待 | 最长≤10秒 | 10个身份、九周期，另含实时与大回填并存；阻塞/重试必须有独立到期状态，不能靠忙转 |
| 历史回填吞吐 | ≥660.52 published bars/s，并不低于可比较旧版的80% | 旧均值825.65；当前高竞争基线不足以证明容量，整合主线复测保持绝对下限且不得按优化结果放宽 |
| 发布图表ASGI服务时间 | p95≤100ms、p99≤200ms | 10身份×M1/M30/W1/MN、500bar上限、3次；本次51.33/104.11ms，无网络/provider线程，不冒充网络API SLA |
| 发布告警单次evaluate服务时间 | p95≤200ms、p99≤350ms | 同40配置热状态，当前147.20/168.44ms；包含warming状态需单列，零staging读；不等于输入到告警延迟 |
| 本地网络published图表API延迟 | p95≤500ms、p99≤1000ms | 新增120次实际TCP请求、认证与序列化、≤500bar，p95/p99=450.18/524.08ms；并发发布/告警但关闭provider lifespan，完整应用/浏览器范围未验收 |
| 持续正常输入到告警判断 | p95≤1秒、p99≤2秒（发布可见之后起算） | 新增十个M1触发、十唯一signal，观测p95/p99=1.657/1.657秒，p95超1秒目标；短窗口与50ms观察限制保留，不证明持续正常输入或全部高周期；来源确认另计 |
| 本任务PG / probe配额 | 0.75CPU / 512MiB；0.75CPU / 768MiB | 旧/新串行测试；容器限流、OOM与宿主争抢必须记录，非生产配额 |
| 完整应用与浏览器并发预算 | 总新增应用计算≤1.5CPU，重型浏览器一次一个，PG≤512MiB | 新增真实网页/双图/完整lifespan短测：配额合计1.45CPU、实际应用+浏览器同时采样均值49.31%/最大93.05%；PG单列。离线合成97秒，不代表成功供应商I/O或持续容量；没有停他人服务 |

公平性与发布延迟必须在队列/输入未减少的相同工作范围比较。吞吐只计有效新增bar，不计重复检查或无变化写入；CPU/SQL优化不能减少应发布价格、观察时间或修订。

当前四场景的宿主忙碌率跨65.94–99.93%，不是统一竞争窗口；升降CPU受服务机会、轮数与限流影响。三层合并后先用同fixture重跑整合旧链路，标记可比较窗口，再实施P1–P3。不能按修复成绩临时放宽此表；若三层合同改变了负载身份或接口，应先记录新固定负载和迁移映射，保持行为要求和绝对目标。
