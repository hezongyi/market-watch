# 图表加载调度：实施设计与验收合同

状态：用户已认可统一设计、分阶段实施。基线 `983b402`；实现位于独立分支 `fix/watchlist-latency-20261022`。不包含合并或生产发布。

## 目标与范围

先解决有直接证据的首屏阻塞，并将前端准入规则集中管理。保持数据集身份、修订、展示快照、strict／observed 政策、历史根数和供源新鲜度不变。不新增任务框架或 schema。

风险级别 F1：兼容的前端改动，加上指标容量锁的重要后台链路。检查覆盖真实 PostgreSQL 并发、取消围栏、容量边界和旧路径兼容；对最终差异进行独立 Standards／Spec review。

## 统一规则

| 需求 | 调度规则 | 生命周期 |
| --- | --- | --- |
| 当前活动图的首屏价格 | 获得优先准入；不能抢占已执行的请求 | 保留原生回调和缓存合同 |
| 其他可见图、主动历史读取、前台指标 | 有界公平服务；不能因活动图持续请求而饿死 | 按有效消费者和现有世代判断 |
| 可选预取／预热 | 限制在途占用；固定行情与平台使用一致的本地用途 | 不因失去焦点而删除可复用缓存 |
| 报价、指标释放／续租等辅助读取 | 保留服务机会，不能占满全部普通槽位 | 释放与取消围栏继续有效 |
| 偏好／数据中心管理 | 保持已有两个有界管理槽位 | 不受慢供源阻塞 |

用途仅属于本地调度元数据，不注入固定行情的平台专用参数，不改变查询或缓存身份。普通在途上限保持 4；平台 reserve 上限 2 扩展为统一的 reserve 上限。公平性在每次释放槽位后选择下一项时执行，不能宣称可抢占在途 I/O。

## 实施顺序

### 1. 成功交付与句柄回收解耦

成功 result 立即交付，清理使用独立的 5 秒预算。为整个历史加载生命周期设置有界准入：成功返回后，句柄未清理前仍占生命周期额度，避免提前释放 bridge 槽位导致无界提交。热缓存无需持久句柄，直接释放额度。

生命周期额度反馈给 bridge：父窗口订阅模块可用数，真正准入后按请求 ID 确认；bridge 将尚未确认的派发另计为预占，避免消息传递期间重复使用额度。没有生命周期额度的原生读取留在 bridge 的统一队列，清理完成后再按当前焦点选取，不提前进入第二层 FIFO。初始快照包括旧工作区仍在回收的句柄；确认和结果带本地客户端身份以隔离旧 iframe 的迟到消息。元数据不进入 HTTP 请求体或缓存 key。

模块保留四个生命周期、64 个排队项的防御性上限；排队取消及实际准入时的超时检查仍有效。旧父窗口不支持额度反馈时仍有原有容量保护，但动态焦点选择的完整保证要求本批 web／chart 配套使用。

失败、真实取消仍执行清理；清理失败可观测，客户端最终释放本地占用，服务端原有 TTL 和 owner 容量保护继续生效。不得把清理成功视为价格可交付的前提。清理失败时不能保证远端立即回收，保留这一限制并验证原有过期合同。

回归必须直接执行真实 TypeScript 模块，覆盖 pending 清理、快速连续加载、排队时取消、失败／超时和最终归零。

### 2. 默认预热不能等待指标容量锁

在默认预热入口，先非阻塞获取现有事务锁；锁忙则跳过本次可选预热。保护范围覆盖 `request()` 和 `renew()`，使内部容量检查仍在同一把已持有的锁下执行。真实前台指标沿用原有阻塞准入和取消围栏。

先验证真实 PG 上持锁者未释放时，无指标价格仍能返回；再验证锁空闲后预热仍可登记、容量仍有效、前台需求没有丢失。这一阶段不提前释放展示快照锁或拆开一致性读取。

若非竞争样本中可选预热仍占据明显响应成本，下一步将其从价格事务移至独立的短事务准入，并继续复用既有需求／worker。该步骤必须单独验证快照和失效消费者合同。

### 3. 统一前端准入策略

集中请求分类、选取与公平性判断，避免在各调用点叠加优先级特例。请求携带本地用途，选取时重新判断活动图，避免旧焦点长期享有优先级。固定行情 reserve 显式标记用途；其他旧原生读取继续可完成并填充缓存。

为辅助／后台工作保留服务机会，同时限制它们占满普通容量。reserve、报价、指标释放／续租与辅助缓存读取共享两个后台位，报价单飞；每四次普通派发一次 FIFO。可见图和真实指标不能永久被活动首屏压制；测试使用真实 bridge 竞争重放，并联合真实加载模块验证清理重叠后的焦点选择，包括管理请求、报价串行、取消和原生缓存生命周期。

## 验收与停止条件

- 模块：成功价格的交付不依赖 cancel 返回；本地加载／清理有界；取消与失败正确结束。
- PG：默认预热锁忙时价格不等待该锁；锁空闲时预热保留；前台指标、容量与围栏合同不变。
- 调度：普通并发不超过 4；reserve 不超过 2；辅助工作不能占满；活动首屏优先且其他类别不饿死。
- 浏览器：原五图、原指标、原视口；检查活动图、全图、首次指标、缓存回切、历史翻页、加载中连切及最终资源回落。
- 性能：按缓存类别分别记录，不把单次样本称为 p95，不通过关闭指标／预取制造收益。完整重复性能窗口由用户协调，不能自动停止其他任务。

当前 Ubuntu 有多个验收任务，4 核主机负载约 5–6、可用内存约 6.5 GiB、磁盘约 33 GiB。先运行确定性模块与隔离 PG 检查，不启动额外整套实例或并行压力测试。现有 `mw-acceptance` 的数据、配置、端口和浏览器现场保持；必要更新按该技能的明确授权规则执行。

本批若达到目标则停止扩大重构；若仍慢，依据剩余分段证据决定 worker／供源／ready 通知的下一项，不预设全系统重写。
