# v1.3.2 平台首屏连接池修复

2026-10-02。按用户授权将平台首屏修复与最新 main 整合，发布 v1.3.2 源码并推送 main 和附注标签；保留 v1.3.0、v1.3.1 及其发布记录。最终源码、构建和验证关系见[源码发布清单](../deploy/releases/v1.3.2-source.json)。本次未构建 Docker 镜像、重启实验或生产服务，也未修改出口或发送真实通知。

## 修复行为

服务启动或连接闲置后，同源两张图同时取数可能为第二个请求重新建立代理/TLS 连接：chart 池容量为二，原来启动及顺序 HEAD 只触及一条连接。现在启动和后台以两次流式 HEAD 暂时持有响应，确保取得两条真实 HTTP/1.1 连接，再消费并关闭空响应，使连接可复用。

维护时间与普通读取分开，避免单图每 15 秒读取不断推迟对闲置第二连接的维护。每个后台 HEAD 使用已有 history 额度；额度等待每 100ms 检查前台活动，取消时释放已取得的响应。在途网络操作仍受原超时约束，不承诺立即中断 HEAD。chart/realtime/history 连接容量、数据库预算、请求额度和重试策略保持不变；不预取 candles、不写行情缓存。

完整根因、真实 TCP 回归及原修复分支验收见[首屏修复记录](provider-first-screen-latency-fix.md)。本版本同时保留 v1.3.1 的 managed 历史更正发布、迁移遗漏恢复和图表历史重载修复。

## 性能结论和限制

[144 样本 A/B 报告](provider-first-screen-latency-statistics.md)基于 v1.3.0 与原修复实现、相同主机和固定出口。它支持双图并发收益：慢首屏由 16/36 降至 9/36；该子组检验未校正多重比较。总体 21/72→14/72 的主要终点 p=0.143463，未达统计显著；单图 5/36→5/36，未显示改善。总体 P95 由约 6860ms 增至 7553ms，最大值由 7156ms 增至 8340ms。

这些结果不是线上用户慢率、闲置后概率或 v1.3.2 容器验收。已有慢样本和失败证据完整保留，不承诺每次首屏低于三秒、整体慢率显著下降或全部连接始终预热。原基线 PG16 307项、镜像和浏览器成绩也不充当集成版本验证。

## schema、部署和回退

本次没有新增迁移，schema 仍为 `o16_managed_revisions`。从 v1.3.1 升级无需新增 schema 变更；从 v1.3.0 或旧运行镜像升级仍需先备份并验证 o16，匹配 API/worker 和数据库版本。沿用[v1.3.1 的迁移说明](chart-v1.3.1-delivery.md)，不能将旧 Compose 配置直接作为新版本的生产部署。

源码回退标签为 v1.3.1，可保留 o16 和 managed 修复，但会恢复平台连接维护缺陷。若目标环境已运行新版，仍需匹配实际镜像、配置和数据库；本次没有改变运行服务，因此没有新的运行回退动作。

源码发布不表示生产升级。后续可部署交付需从固定源码构建并记录新镜像 ID，配置目标 origin、worker 和数据库连接预算，在目标隔离环境完成迁移、首屏/缓存及历史修订验收。原 v1.3.0 镜像及本机实验镜像均没有改标为 v1.3.2。
