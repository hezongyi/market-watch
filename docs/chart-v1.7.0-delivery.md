## 阻断修复与复审

- 原生线程 reset/purge 复用线程但替换缓存。储备成功、空终点、miss 和失败全部先验证线程、缓存对象、首柱游标与必需加载状态；共享退避与终点按缓存代次重建，旧响应不能结束新缓存或消耗新预算。
- Yahoo 储备使用持久化元信息，不在元信息 TTL 过期时同步请求上游；未解析元信息返回可重试 503，普通必需读取继续按既有 TTL 刷新。缓存命中和 miss 都不调用上游。
- 新增确定性回归已在修复前失败，修复后通过；覆盖同首柱/不同首柱的重置、旧空/非空成功/错误、同缓存游标变化、终点后重置，以及 Yahoo 完整/缺失元信息。复审按 Standards 与 Spec 独立执行。

原始真实 OANDA、多图同步和逐绘制验收见 `docs/verification/viewport-history/`，其基线 v1.5.2 与提交 5717f81 保留原样，不作为本次全部运行源码的证明。本次固定构建、迁移、回退、健康和浏览器验证另行记录。

## 生产升级与回退

目标为 Unraid 上独立 trading-alerts 项目，升级前实际版本 v1.5.0/schema p17_volume。本次需备份并验证独立 PG14 恢复，再验证 p17→q18 迁移及数据保持。q18 仅新增目录 JSON 字段，没有本 PR 新增迁移；先保留旧镜像及配置。部署使用 standalone 发布 Compose，不与旧 external-db base 合并。API 更新后重启 web 刷新 Nginx 上游解析。

数据库不自动恢复到旧备份；回退前归档新状态。已验证旧应用可读取 q18 时可直接恢复旧服务镜像；任何 q18 downgrade 删除新增目录元信息，须结合当前备份明确处理，不能为回退丢弃用户新布局/行情。备份使用对应新版应用及 PG14 客户端；配置备份脚本允许经过路径校验的版本发布目录。

生产验证只读查看登录、页面、图表与服务，不创建预警、不改密码、不发送测试通知。部署完成后将实际健康、镜像、schema、备份恢复与浏览器结果写入生产清单。
