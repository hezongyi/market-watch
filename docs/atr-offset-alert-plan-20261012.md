用户确认的目标：创建告警时可以给比较目标加阈值，再使用原来的告警流程；第一期阈值采用 ATR，可选 K 线周期与乘数。计算长度默认 14，也允许调整。典型规则为：在 H4 连接高点/低点，价格突破连线外 `0.2 × 上一根已收盘 D1 ATR(14)` 后提醒。

## 1. 使用流程与首期范围

在现有创建/编辑告警的“比较目标”下方增加可选字段，不新增一种告警产品：

```text
条件对象：价格
比较目标：关联画线 / 固定价位 / 价格单位的指标输出
关系：上穿 / 下穿 / 高于 / 低于
突破阈值：无（默认） / ATR
  ATR K线周期：D1（可选）
  ATR 计算长度：14（可调整）
  ATR 乘数：0.2（可调整）
判定周期：H4（沿用当前告警周期）
判定：盘中观察 / 收盘确认（沿用现有设置）
触发次数、到期时间、消息与通知：沿用现有设置
```

明确区分“ATR K线周期”和“ATR 计算长度”；不能用一个名为“周期”的输入同时表达 D1 和 14。

新建规则默认关闭阈值，旧规则不受影响。首次开启 ATR 时采用本次讨论的 D1 / 14 / 0.2；开启或关闭阈值不自动改变原有判定周期、关系、盘中/收盘模式和通知选择。已保存规则以自己的配置为准。

首期约定：

- 左侧为价格或现有价格单位的指标输出；右侧为固定价位、四类受支持画线，或现有价格单位的指标输出。目前可用的指标目标包括 SMA、EMA。
- 水平线、水平射线、趋势线、射线继续复用原生端点映射、线性/对数轴计算和延长方向。
- 上穿/高于向目标上方偏移；下穿/低于向目标下方偏移。不让用户输入负乘数，不另设偏移方向。
- 启用 ATR 时仅开放上述四种有明确方向的关系。无阈值时全部原有关系仍可使用。“穿过”双向穿越、价格区间的 ATR 扩展留待后续明确单边/双边含义；不能在首期隐式生成一条 ATR 通道。
- RSI、MACD 等非价格单位的输出不支持 ATR 价格偏移。前后端都校验，不能仅隐藏选项。
- 固定 ATR 平滑方式为现有 Wilder 实现；首期不增加 SMA/RMA 平滑方式选择。
- 周期选项来自所选系列实际能力，支持不同于告警周期的 ATR 周期，包括更小周期。不能仅把所有 `FRAMES` 硬编码成均可用。
- 第一阶段不新增固定点数、百分比、多个阈值叠加、自动画趋势线、自动识别整理区或独立推送流程。

界面展示规则摘要，例如：

> H4 收盘价上穿趋势线 + 0.2 × D1 ATR(14)；ATR 取本根 H4 开始前最近已收盘值。

参数保存到现有告警配置，编辑、刷新与重启后恢复。已有的命名规则模板方案应保存这组参数；若模板功能尚未落地，本任务不以新建整个模板系统为前置条件。模板只保存配置，新规则必须重新绑定实际画线、系列身份和 ATR 数据依赖。

## 2. 数值与时间口径

### 2.1 实际告警边界

设某次观察的原目标价为 `B`，选定 ATR 为 `A`，正乘数为 `k`：

```text
上穿 / 高于：T = B + k × A
下穿 / 低于：T = B - k × A
```

把 `T` 作为 Observation 的右侧值传给现有 `advance()` / `consume()`。左侧值、实际市场价格、观察时间及逻辑事件身份继续沿用原流程。

穿越使用严格超过：相等不触发。现有 `above/below` 也是从不满足到满足才触发，不表示每次扫描只要处于边界外就重复发信号。ATR 偏移不改变这些语义。

例：原目标为 `1.1000`，D1 ATR 为 `0.0060`，乘数 `0.2`，上方边界为 `1.1012`。触及 `1.1012` 不触发；在有效基准下上穿到更高价格才触发。下方边界为 `1.0988`。

计算使用原始精度。ATR 输出沿用现有数值口径，再按 `Decimal(str(value))` 接入价格比较；乘数以十进制字符串持久保存，不能按显示小数位先把 ATR、价差或边界截断。预览按品种精度显示，显示精度不参与判定。计算结果须为有限、有效的价格，非法配置或边界不进入比较器。

### 2.2 ATR 算法与初始化

复用 `chart_indicators.py` 的 ATR 定义及 `indicator_state.py` 的 ATR 状态算法，不另写一种 ATR：

```text
TR[t] = max(H[t]-L[t], abs(H[t]-C[t-1]), abs(L[t]-C[t-1]))
首次 ATR = n 个有效 TR 的算术平均
后续 ATR[t] = ((n-1) × ATR[t-1] + TR[t]) / n
```

首个有效 TR 依赖前一根收盘价，因此 n=14 至少需要 15 根合法完整 OHLC；这只是首次出值下限，不是完整历史等价所需的全部历史。递归状态须从固定、持久起点或已验证检查点初始化，不能每次扫描/翻页只截取最近 15 根重新求均值。

已有 `history_requirement()` 对 ATR 返回 `10 × n` 的近似预热数量，可作为读数预算线索，不能当作固定起点状态的数学替代。新规则的 ATR 历史起点单独绑定到 ATR 周期，不能把 H4 的 `calculation_origin` 或页面起点直接当作 D1 起点。

### 2.3 跨周期对齐：按判定 K 线开始时取值

设当前告警判定 K 线为 `E=[e_start,e_end)`。选取同一系列中 **`end <= e_start` 的最近一个预期 ATR 周期柱**，且它必须来源确认、完整覆盖、初始化完成。该柱 ATR 记为 `A_E`。

整个 `E` 内的盘中观察及最终收盘判定都使用 `A_E`。不能在收盘模式中改用 `e_end` 时最新 ATR，从而让本根突破参与自己的门槛；也不能因 worker 运行得晚而使用观察时点之后才结束的柱。

| 判定周期 / ATR 周期 | 实际取值 |
| --- | --- |
| H4 / H4 | 当前 H4 开始前，上一根已收盘 H4 的 ATR |
| H4 / D1 | 当前 H4 开始前，最近已收盘日线 ATR；按相同交易日历，当天共用 |
| H4 / H1 | 当前 H4 开始前，最近已收盘 H1 ATR；本根 H4 内不跟随之后的 H1 更新 |
| D1 / H4 | 日线开始前，最近已收盘 H4 ATR；当根日线内固定 |

当 H4 收盘与 D1 收盘同一时刻，刚结束的 D1 不参与这根 H4 的门槛；下一根 H4 开始时可以使用它。同周期的当前柱同样被排除。

“日线”采用当前系列绑定的交易日历、日线对齐与报价口径；例如 NY17 遵从纽约交易日及夏令时，不按浏览器本地零点或固定 24 小时偏移找昨天。正常周末休市时取上一预期交易柱，不能伪造空日线。

必须先找到按日历应有的最近已结束柱，再检查它是否可用。若该柱缺失或确认延迟，不得向前跳到更旧 ATR，也不得用当前未收盘 ATR 填补。缺口/预热不足时等待有效依赖，并在列表显示具体原因。

历史重放按每根判定柱自己的 `e_start` 作时间连接；实时只使用当时已经来源确认可用的输入。`end <= e_start` 本身不足以证明实时当时可用；必须记录输入修订与可用/确认水位。事后补齐的输入不伪装成当时已知的实时 ATR。

## 3. ATR 更新、穿越基准与恢复

### 3.1 ATR 自身刷新不生成信号

自然进入新判定 K 线时，ATR 缓冲可能变化。若价格没变、只是 ATR 变小，不应因此产生本次新增的突破提醒。

复用比较器，在调用前仅调整上一观察的右侧基准。设上一基准的实际边界为 `T_prev`，此前有符号偏移为 `d_old`，新偏移为 `d_new`：

```text
上一观察用于比较的目标 = T_prev + (d_new - d_old)
本次观察的目标         = B_now + d_new
```

上一观察的左侧值不变；累计次数、已消费 sequence、事件身份和运行轮次不变。这样两次价格观察使用同一个新 ATR 偏移，ATR 切换本身不能使相对位置换边；本次真实价格若确实跨过新边界，仍可触发。

示例：固定目标 100；前三行偏移从 2 降到 1，最后一行从 1 升到 2。

| 上一价格 → 本次价格 | 原边界 → 新边界 | 应有结果 |
| --- | --- | --- |
| 101.5 → 101.5 | 102 → 101 | 无信号；不能只因门槛下降触发 |
| 100.8 → 101.2 | 102 → 101 | 有上穿；上一价格仍低于新边界，本次已高于 |
| 100.8 → 100.9 | 102 → 101 | 无信号 |
| 101.5 → 102.5 | 101 → 102 | 有上穿；新门槛虽提高，价格仍真实跨越 |

这里调整的是比较所需的上一目标，不是插入一条虚构价格观察。不能消耗首个新报价的 sequence，也不能通过整根首次观察只重建基准来漏掉第二行的跳空/快速突破。更新偏移、判断、写入状态/信号/通知必须处于现有同一告警锁和事务中；同一输入重试时不能再次叠加差值。

runtime 持久保存“上一已消费观察所用的有符号偏移、ATR 参考柱、算法/输入修订、判定柱身份”，与 state 同时提交。被修改的历史 ATR 不当作自然刷新：转入修订核对/重建流程，不能用新的数值改写已发送事件。

### 3.2 保留原目标本身的动态含义

只消除 ATR 自身变化的影响，不抵消原目标的正常变化。画线价格按原生 K 线序号计算；盘中同一根位置沿用现有实现，不自行改为连续钟表时间插值。SMA/EMA 等目标变化继续按原条件比较。

因此趋势线或均线本身的运动仍可能形成相对穿越。这与现有动态目标语义一致；本方案不承诺价格必须单独朝某方向运动，也不新增动量过滤。编辑/拖动已绑定画线仍生成新规则版本并重建基准，不视为自然 ATR 刷新。

### 3.3 初始基准、数据缺失与恢复

- 新建、编辑和恢复复用现有生效时间及首个有效基准政策；创建前已处于边界外不补发“刚刚突破”。
- 对完整连续、未失效的旧基准，正常 ATR 切换使用 3.1 的换算，不无条件跳过第一条有效观察。
- ATR 初次预热、确认延迟、缺口或修订后恢复时，不能用恢复后的 ATR 跨越未观测区间生成新鲜通知。当前有效观察用于恢复基准，计数保留，下一次真实穿越才判定。
- 原有报价陈旧、来源身份改变、历史修订、组合接缝、迟到投递和到期政策继续执行，ATR 依赖不能绕过这些门槛。
- 盘中仍是来源实际提供的有效样本；单靠 H4 OHLC 的 high/low 不能还原全部穿越顺序或承诺抓住每次瞬时刺穿。
- 首期不增加“不限次数”或新的候选消费机制。有限次数及到期使用当前产品选项；若 CDL 方案独立扩展生命周期，本功能兼容其结果。

## 4. 配置与内部 Interface

### 4.1 可选配置

建议在 `Condition` 增加可空的 `offset`。下例为拟定配置，**不是当前已发布能力**：

```json
{
  "timeframe": "H4",
  "mode": "close",
  "condition": {
    "relation": "cross_up",
    "left": { "kind": "price" },
    "right": {
      "kind": "line",
      "line": {
        "kind": "horizontal_line",
        "points": [{ "time": 1791763200000, "index": 0, "price": "1.1000" }],
        "scale": "linear",
        "extend_left": false,
        "extend_right": false,
        "mapping_version": "bar-index-v1"
      }
    },
    "offset": {
      "kind": "atr",
      "version": "1",
      "timeframe": "D1",
      "period": 14,
      "multiplier": "0.2",
      "reference": "closed_at_evaluation_bar_open"
    }
  }
}
```

无阈值时不发送 `offset`，或发送 null。方向由关系唯一推导。`version=1` 绑定本方案的 Wilder、开盘前已收盘取值及 ATR 刷新基准语义，不复用以后改变含义的版本。

配置校验：周期必须为系列能力中的已验证周期；`period` 为整数并复用现有 ATR 参数 schema 的限制；`multiplier` 为有限正十进制数，建议首期范围 `0 < k <= 100`，UI 步进 0.01。不接受负数、零、NaN、Infinity 或未知字段；要零偏移就关闭阈值。开启 ATR 时条件两边须是可比较价格单位，且关系属于第 1 节四项。

参数字段依旧由现有配置版本持久化。新增字段缺省为 null 后，旧请求/旧 JSON 可读；不要批量重写旧配置、请求摘要或事件 evidence。新配置的 canonical 字段参与现有 hash/幂等校验，升级前请求重放须保留原始协议摘要或做明确兼容归一化，不能仅因新增 `offset:null` 判成用户改过请求。

### 4.2 求值 Seam 与模块职责

使用 codebase-design 的 Module / Interface / Adapter / Seam 原则：把新增复杂性集中在“原目标求值之后、Observation 提交之前”，让普通和组合路径共享同一求值及基准换算 Module。不要重构整个告警系统，也不引入通用表达式语言。

建议 `chart_alert_offsets.py` 提供小型内部 Interface：

```text
resolve(offset_spec, relation, evaluation_bar, bound_atr_reader)
  → 偏移值、ATR参考/依赖证据、就绪状态

apply(base_target, resolved_offset, prior_runtime)
  → 实际边界、上一右值的换算信息
```

Interface 约束：不采集行情、不写数据库、不发送通知；未就绪返回明确状态；参考选择按第 2 节；乘数和边界有完整单位/精度约束；同一绑定输入可重放。数据 Adapter 由调用方注入，实现已有 managed/provider/composite 读取差异。内部可有 helper，但不制造多层仅传参的抽象。

`advance()` 的穿越计算原则不改。worker 或 `consume()` 附近的同一事务适配上一右值，把最终 Observation 交给现有 `consume()`，沿用事件 key 和计数/Outbox 原子提交。原目标为 None 时实际目标仍为 None，不能因 ATR 可用就凭空提供价格。

## 5. 跨周期输入、复用点与实施路径

### 5.1 数据依赖是本期必做内容

一条 H4 规则引用 D1 ATR，意味着后台有两个周期依赖，不是把 ATR 名称加进下拉框就完成。为每条规则建立按周期去重的输入需求：判定周期/目标计算依赖，以及 ATR 周期/长度/固定起点依赖。同周期复用已有数据，多个规则相同 ATR spec 共享计算和采集预算。

绑定两组依赖的同一品种、来源、账户范围、报价 basis、日历和来源参数。不能用 OANDA H4 价格配其他来源日线 ATR；也不能用 Bid 画线配 Mid ATR、切换账户后沿用旧值。配置只保存用户参数，dataset/revision/origin 等输入绑定保存在规则版本的 market_identity；runtime 保存可变化的计算水位和当前参考。

| 路径 | 必需改动 |
| --- | --- |
| managed | 复用 `chart_rows` / `managed_dataset.read_rows`、聚合与发布；绑定 ATR 独立固定起点/检查点，确保无浏览器也维护所需历史及周期。只读已有数据不等于已经注册后台需求；既有历史维护范围不足须给出等待原因，不静默扩大已批准范围 |
| provider | 创建时通过 `provider_cache.ensure(meta, atr_frame)` 绑定第二数据集；`provider_service` 轮询需求和保护清理名单必须包含它。不得只改 `ChartAlertVersion.dataset_id`，该字段目前只表示主判定数据集 |
| composite | ATR 周期读取同一个固定 revision/history version/input revision；复用 `chart_page`、`CompositeAggregateTask` 和 `fixed_indicators.chart_results`，`provisional=False`。检查 ATR 依赖的完整聚合水位、初始化、接缝和恢复，不混入 active 新修订或只看主 H4 就绪 |

ATR 依赖也参与历史修订检测/计算失效与数据保留。第一期的绑定可复用规则版本 JSON，避免先新增独立规则/信号表；若历史保留扫描不能识别嵌套依赖，则同步修正扫描或给出明确关联。暂停/完成/到期停止新增采集需求，暂停保留恢复所需输入；删除和资源回收沿用已有规则。

所有供源 I/O 继续在 worker 的原有采集阶段、数据库判定事务之外执行。不要在持有告警锁时下载 D1 历史。递归 ATR 用已有 `IndicatorState` / fixed 输出机制；普通路径的持久 ATR 状态按确认前缀增量推进并可恢复，不能每次全量扫描十万根或引入每条规则各自请求供应商的循环。

| `backend/alerts/chart_alert_api.py` | capabilities 返回 offset 支持与 ATR 可选周期；创建/编辑验证真实能力，保留原来源身份检查 |
| `backend/alerts/chart_alert_message.py` | 条件摘要追加 ±ATR 说明；`{threshold}` 为实际边界，默认通知/详情可显示原目标、ATR和价差 |
| `web/src/advanced/chartAlerts.ts`、`ChartAlertDialog.tsx` | offset 类型、无/ATR 控件、周期/长度/乘数、单位与方向可用性、预填与编辑保存 |
| `advanced-host/chart-alerts.js` | 复用原生画线创建、拖动/编辑的配置传递，避免更新画线时丢失 offset；不在浏览器另算 ATR |

无需为了 ATR 偏移把 ATR 加入当前普通 Indicator 的 SMA/EMA/RSI/MACD 白名单：offset 引用独立 ATR spec，计算目录中 ATR 已存在。价格单位指标目标继续遵从告警能力白名单，不因本功能顺带宣称所有图表指标均可告警。

### 5.3 显示与证据

创建页只显示选择项、可读规则和就绪提示；可在已有行情可用时展示“原目标 / ATR缓冲 / 实际边界”，缺数据时显示等待，不以零替代。前端预览由后端同一求值口径提供，不能用另一种 ATR 近似证明实际会触发。

事件沿用 `SignalRow.threshold` 保存当次实际边界。evidence 补充原目标、有符号偏移、ATR 数值、周期/长度/乘数、参考柱 start/end、独立计算起点/算法、dataset/revision/input revision、确认水位、基准换算和恢复原因。保留当次快照，打开历史事件不重新计算边界。

通知渠道和既有消息占位符继续复用；不必新增占位符才能完成本功能。修改规则、暂停恢复、重启和重复报价不能重复投递同一逻辑事件。

首期不自动画 ATR 平移线/通道，也不新增绘图对象绑定；图表原连线继续显示，列表和事件展示告警实际边界。这避免把随周期变化的缓冲误表现为永久固定平行线。

### 5.4 推荐实施顺序

1. **配置与纯求值**：offset、单位/方向校验、固定参考选择和价格求值；用可控输入验证时间边界及 ATR 更新换算。
2. **后台数据依赖**：独立起点、跨周期绑定/采集/完整性/保留，普通和组合 Adapter；先解决无浏览器 D1 依赖维护。
3. **原流程接入**：锁内基准换算、Observation、修订/恢复及事件证据，保持旧规则和通知链。
4. **创建与编辑界面**：控件、能力提示、可读摘要、保存恢复及画线更新；已有模板模块有则接入，否则仅完成可序列化配置。
5. **Ubuntu 隔离验收**：下节功能矩阵和旧规则回归，提供实际环境、地址、启停方式与记录。

## 6. 验收标准

以下是实施后必须验证的行为，本轮未运行这些测试。

| 场景 | 预期 |
| --- | --- |
| offset 缺失/null，升级前规则与请求重放 | 原有行为及幂等一致，不生成新规则或错误冲突 |
| 上穿/下穿、固定价位/水平线/趋势线/SMA目标 | 实际边界等于原目标 ± ATR×乘数；相等不触发 |
| RSI/MACD、区间/双向关系启用 offset | 前后端给出明确不支持，不静默改变单位或关系 |
| H4/D1、本根盘中与收盘 | 共用开盘前同一个已收盘 D1 ATR；本根 D1 变化不影响门槛 |
| H4/D1 共用收盘边界 | 最后一根 H4 不读刚结束 D1；下一根 H4 可读，包含严格时间断言 |
| H4/H4 与 H4/H1 | 前一根已收盘值；更小周期在本根 H4 内更新不改变已固定缓冲 |
| NY17、夏令时、正常周末休市 | 按实际日历选前一交易柱，无伪造空柱或固定 UTC 零点偏差 |
| 最近预期 ATR 柱缺失/未确认、预热不足 | 等待，不用更旧值或未收盘值；补齐后安全恢复基准 |
| ATR 缩小，价格不变，原目标不变 | 无新增信号；没有虚构报价或额外触发次数 |
| ATR 切换后首个实际价格跨越新门槛 | 连续有效基准下正常触发，不因无条件重置漏报 |
| ATR 输入历史修订、主周期输入修订 | 缓存/检查点失效可见，进入既有核对/恢复政策，不重发旧事件 |
| 分页、同 spec 多规则、重启检查点 | 同固定起点结果一致，避免重复采集/计算；消费水位和 offset 同步恢复 |
| 偏移更新/信号事务前后故障 | 重试无重复差值、无重复计数或通知，信号与 Outbox 一致 |
| 画线无效范围、对数轴及拖动提交 | 无效范围不求伪目标，原几何一致，编辑保留 offset 并生成新版本 |
| provider 关闭全部浏览器 | H4 与 D1 两依赖继续更新；清理保护不误删 ATR 数据集 |
| composite 固定修订及 ATR 接缝依赖 | 不混 active 新修订；拒绝/接受接缝沿用规则，完整水位不足不判定 |
| 暂停/恢复、编辑、次数与到期 | 原生命周期语义一致，依赖采集释放与保留符合状态 |
| 默认通知与事件详情 | 实际 threshold 可复现，原目标/ATR/价差可追溯；显示精度不改变结果 |

算法夹具对照当前 TA-Lib 与既有状态计算，确保 TR、种子与递推一致。浏览器验证真实创建/编辑/刷新及画线更新；通知使用本任务测试 sink，不外发真实消息。盘中路径只用真实可控样本，不拿 H4 OHLC extrema 构造不存在的先后顺序。

技术验收验证规则正确，不能证明 `0.2` 是盈利或最优参数。研究依据见 [ATR 阈值研究](research/atr-trendline-breakout-threshold-20261012.md)；若后续验证参数效果，需固定画线方法、数据口径和确认方式另做历史比较。
