# OANDA 的采集协议切换与来源身份分开管理

日期：2026-10-15。状态：决策已采纳；局部实现和定向验证完成，尚未切换生产。

实现基线：`v1.25.6` / `ee5b885626104577244f4fc40342d60b1a52c664`。系统级 Ubuntu REST worker、图表交接和故障恢复验收仍是收口条件。

用户认可由默认每 2 秒批量 candle 接替 OANDA 报价流及其业务，并认可不接入 pricing。
1 秒作为可配置的后续选项；已有 1 秒网络探针保留原始结果，完整系统按真实 2 秒节拍验收。
`candles/latest` 提供供应商 OHLCV 和 complete；当前未闭合 M1 close 提供看盘最新价
和采样式盘中告警输入。统一所有权、需求、恢复和主 SSE 出口；形成中 OHLC 不再由报价样本累积。

来源身份继续按 ADR 0001 隔离。协议从报价流转为 REST，不自动覆盖已有来源历史，
也不把同名品种视为相同序列。只有账户、环境、供应商品种、BID/ASK/MID、平滑、单位、
周期/日历参数和量语义经过等价核对后，REST 确认结果才可接替原确认输入。
采集方法另有 `stream` / `rest_batch` 标签、协议版本、序号和新的所有权世代，保留到
数据和告警证据中。接收时间用于蜡烛快照观察，不冒充逐笔价格发生时间。
Bid/Ask 对、价差和 tradeable 不再作为 candle-only 模式的必需输入，也不能捏造。

未来 MT4 交易使用实际交易经纪商的 Bid/Ask、来源时间、价差和交易状态，接口与更新机制
届时设计。OANDA candle close 是看盘和信号参考，不代表 MT4 可成交价。信号保留原来源
身份，执行前另校验 MT4 品种映射、报价新鲜度与价格偏离。本次不接入 OANDA pricing，
不实现 MT4 交易或预建交易框架，仅明确两种来源的职责边界。

平台高周期仍采用供应商原生周期；组合高周期仍采用其固定 M1 输入与配置日历聚合。
未完成 REST 柱是新的 provisional 观测方法，不能宣称与原报价累积 provisional 相同。
切换时 fence 旧在途写入并重新建立接受/告警基准，固定历史与既有证据保留。

存量 tick/intrabar 告警迁移为默认每 2 秒当前 close 采样，切换时重新建立基准、保留历史证据。
用户已接受可能遗漏两次采样之间短暂触价；不能借助累计 M1 high/low 重建不存在的观察、
先后顺序或创建告警之后的触价。盘中价格和指标按同一快照计算，收盘规则仍等 complete。
当前柱缺失或只收到旧柱时不刷新即时价格有效性；close 不变不等于断线，HTTP 成功也
不证明仍在交易。按 ADR 0002/0003 保留原覆盖门禁和日线
价格证明规则。最新两根蜡烛不证明长期查询覆盖，恢复继续需要有界历史请求。

代价是需要改造当前依赖流心跳、临时报价 OHLC 和固定确认等待的模块，并接受报价
采样间隔与观察方式变化。收益是看盘、指标和盘中价格统一来自供应商蜡烛，批量共享取数，减少分钟交接的
两套数据差异。正常换柱顺序与实际回调接受仍需实现和验收，协议替换本身不保证无闪。
