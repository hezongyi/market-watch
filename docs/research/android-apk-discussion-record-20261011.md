# Market Watch Android APK：讨论、选型与研究归档

归档日期：2026-10-11（Asia/Singapore）。目标设备：OPPO Find X8 / ColorOS 16。本文汇总此前 APK 交接与研究，并按用户补充的“个人使用、维护简单、网页后续会变化”要求记录当前建议，供后续继续分析。

**当前推荐：复用现有 React + TypeScript + Vite 工程实现手机页面，由小型 Kotlin + Android 系统 WebView 外壳在线加载受控 HTTPS 手机入口。** 如无需自行构建和分发 APK，PWA/浏览器添加到桌面是维护更少的候选。技术选型仍是建议，用户尚未确认实施。

本次交付为文档归档与 PR；没有实现、构建、安装或发布新 APK，没有新增手机验收、后台通知测试或生产变更。后台通知资料保留为历史研究，不纳入当前界面方案。

## 当前技术选择与维护边界

以下是常见路线的项目适用性比较，没有调查市场占有率或做流行度排名。详细依据见 [手机界面与集成续析](android-apk-ui-integration-analysis-20261011.md) 和 [外壳官方事实](android-apk-shell-official-facts-20261011.md)。

| 技术路线 | 网页变化后的维护 | 当前建议 |
|---|---|---|
| 手机网页 + PWA | 主要发布网页；安装结果取决于设备和浏览器，可能为 WebAPK 或快捷方式；需要明确缓存与更新行为。 | 无需自有 APK 时优先评估，当前网站尚未完成 PWA。 |
| Kotlin + 系统 WebView，在线 HTTPS 页面 | 多数界面和业务改动发布网页即可；外壳处理安装、窗口、返回、外部链接、错误和恢复。 | **明确需要 APK 时首选。** |
| TWA / Bubblewrap | 网页在线更新；维护宿主 APK、签名、浏览器依赖和 Digital Asset Links。 | 浏览器能力足够时的备选；宿主不能直接访问网页 Cookie、localStorage 或沿用 WebView 原生桥。 |
| Capacitor（可配 Ionic）标准本地打包 | 前端资产通常随 APK 更新；本地页面来源不同，现有相对 `/api`、会话与 CSRF 需要新增集成契约。 | 明确需要本地资产、离线、多平台或多个原生插件时重评。官方将 `server.url`、`allowNavigation` 标为非生产用途。 |
| React Native / Expo、Flutter | 新增一套业务界面与导航，Advanced Charts 仍需 WebView 或另选图表。 | 当前个人维护目标下，重写收益不足。 |
| Kotlin + Jetpack Compose 完整原生界面 | 网页和 Android 业务界面分别维护，图表仍须单独集成。 | 首期不建议重做全部原生业务界面。 |

推荐外壳保持很小：加载稳定手机入口，处理系统返回、安全区、键盘、横竖屏、外部链接、加载失败和 WebView 版本诊断。没有需要原生实现的功能时，不引入插件或网页到原生的桥；不要按网页 DOM、按钮位置或 CSS 选择器驱动业务操作。

列表、导航、指标参数、数据中心展示和多数流程变化由网页维护；需要接口变化时沿用现有服务端交付。新版网页通常在下次页面加载或可控刷新生效，已经打开的页面不会自动无条件换成新代码。引入缓存后需设计更新策略。

新增原生能力、改变网页与外壳的契约、修改包配置或适配 Android 兼容性时仍需更新 APK。应保管稳定 applicationId、签名密钥和递增 versionCode；签名密钥不提交仓库。在线加载依赖网络与设备 WebView 提供程序，不承诺离线行情或固定 Chromium 内核。

## 手机页面需要解决的实际问题

当前缺少数据中心、指标与自选入口，主要来自项目的触屏只读策略和桌面导航结构。`AdvancedWorkspace` 按 `(pointer:coarse)` 传入 `readonly`，父页面限制偏好写入和数据中心请求，图表宿主不安装相应入口。仅给现有页面套 APK 不会补齐功能；应按功能设置移动能力，避免全局取消只读后意外修改桌面工作区。

建议先提供自选、单图、指标和数据中心浏览的手机路径。指标放图表操作区；自选和数据中心为一级页面。若纳入前台告警，增加告警一级页。这些导航、数据中心深度与候选 `/m/*` 路由尚未实现，也尚未作为最终产品范围确认。

| 集成点 | 已有能力 | 需要明确或新增的内容 |
|---|---|---|
| 自选 | `mw.watchlists.v1` 存储 `{lists, active}`；偏好有 revision 与 HTTP 409 冲突机制。 | 共用组内容，手机当前组、滚动和筛选独立；手机保存内容时保留桌面 active；冲突不无声覆盖。 |
| 单图 | Advanced Charts、历史加载、datafeed 和 Python 指标适配。 | 独立手机状态作用域，避免手机品种/周期/指标覆盖桌面多图；保存时处理文档大小及历史版本引用。 |
| 品种身份 | `MWP:` 平台、裸品种 managed、`MWH:` 固定历史、`MWC:` 组合。 | 保留真实编码、来源与修订语义，不能按显示名称重新匹配。 |
| 数据中心 | 已有业务 API、部分窄屏样式，以及桌面窗口与 `CenterContext`。 | 手机页面控制器、返回栈、开图/入自选；不能仅添加一个现有 `/market-data` 链接。 |
| 登录与图表 | 相对 `/api`、同源请求、HttpOnly Strict Cookie、写请求 CSRF；主应用和图表分别位于两个来源。 | 验证 WebView 自己的登录存储、会话过期和恢复；继续由可信父页代理认证请求，不把凭据或通用原生能力给图表 iframe。 |

模块边界、现有 API 路径、状态规则及新增契约详见 [集成续析](android-apk-ui-integration-analysis-20261011.md)。早期 `mobile/` 是小型提醒伴侣，可参考部分构建及状态处理；它没有自选、图表、指标和数据中心，不能算作已完成的五项功能 App。

### 手机交互建议

这些是本文保留的设计建议，供引用时使用；不是官方图表行为或用户已确认的界面规格。

- 一级导航带文字标签；指标作用于当前单图，不单独占一级入口。
- 返回先关闭键盘/弹层，再回详情上级或来源列表；回到列表保留滚动、筛选和选择。
- 品种、周期、指标入口可见；排序、删除等操作提供可见按钮，不只依靠长按或拖动。
- 针对实际设备核验触控目标、安全区、字体放大和软键盘遮挡；桌面 32/36/40px 控件不视为已通过手机验收。
- 区分登录过期、连接失败、无数据、行情陈旧和图表初始化失败，提供可读状态与重试；不以黑底或模拟行情代替真实反馈。

## 当前估算与待验证问题

按一名熟悉项目的工程师、数据中心浏览版、复用既有图表和服务端估算，基础交付约 **14–22 工作日（约 3–5 周）**。包括关键集成原型、手机核心页面、数据中心浏览、Android 外壳和集成/真机验收；不含后台通知或可选前台告警。这是规划量级，尚未通过原型校准。

可选增量：前台告警列表/详情/在线确认约 2–4 工作日；再增加规则新建/编辑/启停约 3–5 工作日；数据中心完整管理约另加 5–10 工作日。完整画线编辑另估。详细阶段见 [当前工作量分析](android-apk-ui-integration-analysis-20261011.md#不含后台通知的阶段工作量)，不沿用早期含通知的 20–35 工作日总量。

后续需要收敛数据中心与前台告警范围，并在 Find X8 上验证 WebView 提供程序、双 HTTPS 来源、Cookie/CSRF、图表加载、返回/旋转、进程恢复、会话过期及网页/APK 更新。还需确定手机状态存储、历史引用与必要的版本化外壳契约。本次只记录这些验证问题，没有运行原型。

## 讨论路线的变化

1. 用户在 Android 360 极速浏览器看到专业图表黑底，随后确认同机 Chrome 正常，并发现手机没有自选、指标、数据中心等入口。
2. 最初评估自选、单图、指标、告警通知、数据中心五项功能，调查 WebView、已有提醒伴侣和 OPPO 官方推送。早期建议将通知准入与可靠性作为首期门槛。
3. 用户明确不接 OPPO 推送，要求研究自有 App 后台直连服务器；因此比较 ntfy、Gotify、OkHttp、UnifiedPush，并提出设备 SSE 方案。厂商推送门槛不再作为路线前提。
4. 用户进一步优先处理现有 ntfy 正常后台接收，研究转向设置、版本、上游 issue 和无障碍系统绑定。未取得新的 Find X8 修复或长待机验收结果。
5. 用户要求交接 APK 分析，明确排除后台通知处理。保留 UI、状态、登录、复用与外壳选型；前台告警子功能仍未定。
6. 用户补充“只供个人使用、维护简单、网页还会变化”。当前建议收敛为同一 Web 工程的手机页面 + 在线 HTTPS WebView 小外壳，并列出 PWA、TWA 和常见跨平台方案。
7. 用户要求将截至当前的讨论研究提交 PR。此次将已有笔记、最新分析及交接上下文一起归档，标明各阶段的适用范围。

因此早期文件中的“当前”“最新”“先验证通知”等措辞应按该文件所处阶段理解。历史资料保留事实、引文和当时建议；当前范围以本总览及最新界面分析为准。

## 证据层级与历史验收摘要

### 浏览器与 APK

用户反馈同一 Find X8 的 Chrome 正常、360 黑屏。它说明浏览器之间存在差异，不能证明 Advanced Charts 不支持移动端，也不能确定是 `blob:`、CSP、广告拦截或某个内核版本的问题。新 APK 的系统 WebView 未在该设备上验收；浏览器模拟、源码分析和 Chrome 成功均不能代替这项结果。

### 历史验收摘要

此处摘录此前研究引用的本地手机记录，供跨文档查阅；**没有新增测试**。原始记录位于仓库外，含私有运行信息，不随本次 PR 发布。

- 此前记录的客户端为 ntfy Play 1.25.2；前台与约 2 分钟短锁屏接收成功。
- 从最近任务划掉后，订阅服务通知消失、实时接收失败；重新打开会补收。该操作不自动等同设置页“强行停止”。
- 部分重开对照的即时投递/常驻通知状态不确定，ColorOS 电池优化例外、后台权限全部调整后的复测和长时间待机结果未完整记录。
- 因此此前结果证明特定条件下订阅停止，未确定手机清理、启动限制、设置变化、网络半失效或客户端缺陷中的具体原因。
- 旧提醒伴侣的编译、签名与 JVM 测试只支持它们各自的构建/逻辑结论，不代表 Find X8 锁屏或新的完整 APK 已验收。已有交付矩阵的历史结果继续按原范围保留。
