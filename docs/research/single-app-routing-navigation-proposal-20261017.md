# Market Watch 路由、导航与登录收敛建议

日期：2026-10-17。源码基线：`99124bb`。状态：路由、导航方向与登录视觉已确认，正式应用尚未实施。当前能力与依赖见[路由盘点](single-app-entry-route-audit-20261017.md)。本建议沿用专业图表的 React 宿主、隔离图表来源和现有业务接口，以一次入口收敛及后续逐页承接为实施顺序。

用户已认可路由与导航方向，并明确复用现有汉堡菜单、保留专业图表布局。登录页正式确定为 **A · 极简居中＋第二种 Magic UI Dot Pattern / Glow 呼吸发光点阵**；[登录页定稿、截图与引用示例](../design/login-approved-20261017/README.md)已固定确认样例及隔离预览。B · 图表分屏、C · 工作台锁屏保留为设计存档；本节登录文案与跳转契约继续作为正式实施的功能约束。

## 推荐的产品结构

主入口是网站根地址 `/`，完成登录后进入专业图表。图表、通知、数据中心、演练与设置属于同一个应用；各业务保留可直接访问的地址。应用使用一套菜单、会话、主题、通知状态和返回图表的规则。专业图表保留原生布局、画线、指标、工作区和警报操作。

主界面称“图表”，去掉“专业图表（验证版）”入口标签；产品名称继续用“守望 · Market Watch”。旧“行情与监控”移为兼容功能。旧“图表工作区”撤下主导航，其历史地址与数据依赖单独处理。

## 路由设置

保留当前 `/advanced-charts`、`/signals`、`/replay`、`/settings` 等业务路径，按需要增加工作区和子功能定位；以下表格包含建议新增路径，不是现状清单。

| 路由 | 建议行为 | 实施安排 |
| --- | --- | --- |
| `/` | 统一入口；根据会话进入登录或专业图表默认工作区解析。重定向使用 replace。 | 首批 |
| `/login?next=<站内业务地址>` | 独立登录页；已登录时进入有效 next，否则进入 `/advanced-charts`。 | 首批新增 |
| `/advanced-charts` | 图表入口解析页：恢复设备上次工作区，或选择已有工作区；没有工作区时显示创建引导。 | 首批默认入口；恢复细化可逐步补齐 |
| `/advanced-charts/:workspaceId` | 指定专业工作区；地址与当前工作区同步，刷新或返回可恢复。显式 ID 无效时显示工作区不可用及选择入口。 | 建议新增，首批优先 |
| `/signals?signal=<signalId>` | 全量“通知中心”，兼容旧 Watch 和图表告警；查看、确认及失败重试。signal 指定时定位该事件。 | 首批复用旧内容与路由；定位及 UI 后续承接 |
| `/replay` | 演练列表/新建入口；继续支持 `?dataset_version=<UUID>` 创建指定固定版本的演练。 | 首批保留 |
| `/replay/:runId` | 继续指定演练，刷新和分享后恢复同一演练。 | 后续新增 |
| `/settings` | 默认进入通知设置；使用 replace 规范到 `/settings/notifications`。 | 首批可先复用旧单页 |
| `/settings/notifications` | ntfy 优先级、静音时段、推送测试和连接状态。 | 分组承接阶段新增 |
| `/settings/sound` | 网页声音开关、试听及浏览器声音可用状态。 | 分组承接阶段新增 |
| `/settings/system` | 行情、历史、通知 worker 和备份等运行状态。 | 分组承接阶段新增 |
| `/settings/account` | 修改密码及现有账户能力。 | 分组承接阶段新增 |
| `/legacy/monitoring` | 旧 Watch 查看、状态、取消及已有管理能力；明确标注兼容功能。 | 首批新增，承接原根 Dashboard |
| `/chart-workspaces`、`/chart-workspaces/:id` | 兼容旧图表历史访问。首批不出现在主导航；彻底停用编辑器后转为有查看/导出方式的退役承接页。 | 首批保留路径，分阶段退役 |
| `/market-data` 及当前白名单子路径 | 兼容解析为图表工作区内的数据中心状态，继续保留原路径的过滤、版本和定位信息。 | 首批保留现有机制 |
| `/chart-data-center?session=<UUID>` | 数据中心内部兼容 iframe 端点，由已认证父宿主控制；直接独立打开给出从图表打开的说明。 | 内部端点保留 |
| 其他路径 | 同一应用样式的不存在页面，提供“返回图表”；不把未知 URL 无条件静默跳首页。 | 首批统一 |

业务 URL 不因 React 页面实现被替换而再改一次。比如通知中心可先在 `/signals` 复用现有内容，随后替换其布局和交互，已发 ntfy 链接继续有效。`/replay?dataset_version=...` 和数据中心内部窗口继续遵循现有协议。

兼容地址转换与默认入口解析放在前端一处。Web Nginx 和启用时的 Python website fallback 负责返回应用入口文件，不维护另一套业务跳转。API、健康检查、MCP、设备协议、通知动作端点保持各自响应类型。

## 工作区、面板和返回状态

建议的 URL 示例：

```text
/advanced-charts/<workspaceId>
/advanced-charts/<workspaceId>?panel=alerts
/advanced-charts/<workspaceId>?data_center=<编码后的 /market-data 地址>
/signals?signal=<signalId>
/replay?dataset_version=<versionId>
/replay/<runId>
/settings/notifications
```

`panel=alerts` 是建议新增的图表警报面板状态；`data_center` 沿用已有参数，内部仍通过 `centerLocation` 过滤业务路径。工作区 ID、signal ID、dataset_version 和 runId 是不同身份，分别验证。旧工作区 ID 不转换成专业工作区 ID。

默认工作区选择顺序：设备上次成功打开且仍存在的专业工作区、后台现有的最近更新工作区、空态引导。显式访问 `/advanced-charts/:workspaceId` 时，以该 ID 为准；不可用时展示明确落点，避免静默打开另一个工作区。切换工作区成功后同步地址，并记录设备上的最近选择。现有源码仅按更新时间选首个工作区，这项“上次使用”恢复是建议补充的行为。

从图表进入通知、设置或演练时，在当前标签页保存“返回图表”上下文，包含工作区地址与必要面板状态。功能页的“返回图表”优先回这个上下文；直接打开功能页的新标签页则回默认工作区解析。刷新后仍可恢复当前标签页的返回上下文。数据中心已有的 return_to/return_key 继续只承担其内部业务返回，保持现有验证范围。

打开数据中心和警报面板时保留图表实例。进入通知、设置或演练等完整页面时，完成脏状态处理后释放图表实例和行情订阅；返回时按工作区恢复，避免隐藏图表持续占用资源。全局会话与通知状态仍由同一应用壳持有。返回同一工作区不等于承诺恢复所有未持久化的供应商临时状态。

图表有未保存更改时，统一处理“保存后继续 / 放弃更改 / 取消切换”。已开启自动保存时可沿现有保存流程完成后导航；自动保存关闭时不因切页擅自保存用户更改。保存失败保留草稿与当前选择，不用一次失败的导航丢掉修改。

## 入口与导航

直接复用专业图表左上角现有“守望”菜单，只调整菜单内的导航项。现有图表布局、顶栏高度、工作区选择、保存、指标、绘图工具及右侧面板布局均保持不变；不新增图表上方的导航栏或常驻侧栏，不额外占用图表区域。

以下仅列出菜单内的应用导航项；主题、历史数据容量、保存样式、刷新历史、草稿恢复等现有图表操作继续保留。

```text
守望菜单
  图表
  通知                       [待确认数量]
  历史演练
  设置
  ───────────────────
  兼容功能
    旧版监控
  ───────────────────
  退出登录
```

“数据中心”不列入守望菜单，继续通过图表顶栏现有“数据中心”按钮进入；现有内部与兼容路由保留。“警报”使用图表已有右侧面板管理规则及其日志。“通知”提供独立的全量信号入口，两者的范围要明确：警报是规则管理，通知是已发生事件及投递/确认结果。“通知”入口及待确认数量放在现有菜单内，不另加顶栏铃铛；尚未引入独立已读状态，因此访问列表本身不清零待确认数量。

在通知、演练、设置和兼容功能页，顶部使用同一品牌、同一菜单以及“返回图表”；内容区承接原 React 业务功能。该页头只出现在这些独立功能页，专业图表不额外渲染应用页头。旧常驻侧栏、旧“行情与监控”首页导航和“守望主页”跳转逐步由这一套导航替代。设置内部可用左侧分组或标签导航，图表原生画线工具栏不充当应用导航。

手机使用相同菜单顺序和含文字的入口。图表沿当前策略保持只读，通知查看/确认及全局设置可达。首次没有工作区时显示明确空态，提供通知和设置入口，并说明需在桌面创建工作区；以后若要支持手机新建，作为独立能力设计。

从图表子来源触发导航时，仅传明确的导航动作与经过验证的业务参数，由可信 React 父宿主统一处理；不把任意地址或站点凭据交给隔离图表来源。

## 登录页面

采用已确认的 A · 极简居中，保留品牌标志和专业图表的深灰、细边框、蓝色按钮风格，将介绍区域收敛成简洁的居中登录卡片；同时提供浅色主题。桌面使用窄卡片，手机按可读宽度和触控尺寸布局。专业图表实例与行情订阅在认证成功后启动。

背景采用 Magic UI Dot Pattern / Glow 的固定点位呼吸效果：低对比灰蓝点阵，少量点以 7–12 秒周期缓慢发光，卡片不透明且周边弱化。右上角提供动画开关；表单聚焦、提交及页面隐藏时暂停，减少动态偏好下静态显示。使用原生 SVG/CSS，限制动画点数，不为此引入 Motion/WebGL。具体尺寸、深浅主题与许可引用见[已确认样例](../design/login-approved-20261017/README.md)。

普通入口的文案：

```text
守望 · Market Watch

登录守望
进入图表，管理警报与通知。

管理员密码
[ 密码输入框                         显示 ]

[ 登录并进入图表 ]

单人账户 · 私有监控
```

保留密码自动填充、粘贴、回车提交及清晰焦点，增加可访问的密码显示/隐藏控制。提交时按钮显示“正在登录…”，阻止重复提交，失败后保留可修正的输入和明确错误。登录状态检查中显示连接反馈；网络错误显示重试，明确的未登录响应才进入登录流程。

从通知或其他深链接进入时，主按钮改为“登录并继续”，辅助提示为“登录后继续查看本次通知”或对应的功能名称，不暴露内部路由字符串。登录页不提供第二个应用选择入口。

推荐登录跳转契约：

| 场景 | 建议结果 |
| --- | --- |
| 未登录访问 `/` | 到 `/login?next=%2Fadvanced-charts`；成功后进入默认专业工作区。 |
| 未登录访问具体工作区、信号、设置、演练或数据中心旧链接 | 将完整、允许的 pathname/search/hash 编码为 next；成功后继续原目的地及兼容解析。 |
| 已登录访问 `/login` | 进入允许的 next；缺省进入图表，不再次显示密码表单。 |
| 已打开页面的请求返回会话 401 | 顶层应用统一保留安全的目的地与本地草稿，再显示登录；成功后恢复原功能。普通业务错误和网络失败不当作退出。 |
| 主动退出 | 按未保存更改规则处理，调用现有退出接口，清理内存中的会话状态，replace 到 `/login`。 |
| 非法、外站或递归 next | 回专业图表默认入口。只接受明确支持的站内业务地址；API、内部 iframe、`/login` 和退出动作不作为普通 next。 |

内部数据中心 iframe 的认证失效由顶层应用处理；恢复地址应是宿主图表和数据中心业务状态，避免在嵌套 iframe 中再开一套登录。网页登录不接管通知动作 Bearer grant、设备 token 或 MCP 凭证。

## 浏览器标签与彩色收藏

用户补充两类目标：浏览器标签显示当前品种/最新价/日涨跌幅，以及自选表品种旁可选颜色的收藏旗标。具体参考截图、官方资料和当前库运行证据见[专项分析](native-chart-tab-colored-favorites-20261017.md)；以下属于后续实施建议，未修改正式图表。

浏览器标签左侧使用**当前守望 Logo** 作为全站 favicon，与已确认登录页的品牌图形一致。标题建议为 `SPX 7,659.44 ▼ −1.09% · 守望`，跟随多图布局中当前激活主图的品种。复用现有报价和隔离消息桥，由最外层 React 宿主设置 `document.title`。日涨跌口径与原生自选表一致；缺数据不编造数值，离开图表恢复对应页面标题。

收藏明确采用红、蓝、绿、黄、紫、青、粉七色旗标，而非普通“收藏”列表。已有原生自选表及其多列表/分组/行情/存储继续使用；同一品种在不同列表中显示同一收藏颜色。

官网确有旗标选色控件，但项目当前实际加载的 **TT v31.1.0** 中相关动作为空，独立运行未出现色板；本次没有找到可直接启用的公开开关。优先核实受支持的原生组件与颜色持久化接口，不假定升级即可获得。若继续使用当前库实现相同交互，需要独立的品种旗标与账户偏好模块，并评估行内适配的版本维护成本；不修改许可库，不重做自选表。无论走哪条路径，均不增加图表导航栏、不改变图表区域，只在自选表品种行内提供小旗入口与浮层色板。

## 旧路由退役安排

第一批：根入口与独立登录页、调整现有菜单导航、旧 Dashboard 迁至 `/legacy/monitoring`、撤下旧图表工作区主入口。旧信号、设置、演练先复用业务内容，工作区地址与返回上下文优先接入。旧图表 URL 继续兼容，保留存量查看渠道。

第二批：整合全量通知与信号 UI、按信号精确定位、分组设置页、网页声音归属、演练 runId 深链接和各页面返回行为。图表警报管理与全量通知共享已有事件/确认语义，覆盖旧 Watch 信号与失败重试后，再退旧 Signals 展示实现。

第三批：在实际核对旧布局、模板、画线、草稿、MCP 和历史引用后，决定旧编辑器只读归档、导出或格式迁移；旧工作区数据删除与接口契约退役分别定义。新旧工作区不是同一文档格式，现有 migrate_legacy_templates 也不证明旧编辑器数据已经迁移。

## 实施边界与检查

本轮为 P0 文档设计。首批以 F0 UI/路由变更规划，使用现有登录接口及持久化接口；若实际实现改变持久格式、后台通知处理或历史回收语义，按最终变更重新评估。

后续最小验收包括：无会话/已有会话访问根地址，具体工作区刷新和返回，signal/dataset_version 深链接登录恢复，旧 Watch 查看与取消，旧图表链接兼容，设置及演练访问，图表脏状态切页/退出，会话过期与网络失败区分，手机和无工作区空态，以及内部数据中心 fallback。图表布局、顶栏高度与可用区域应保持不变，菜单中没有重复的数据中心入口，现有数据中心按钮仍可用。为实际启用的 Web/Python 服务核对入口覆盖；应用导航变化不改变 API、SSE、设备或通知动作协议。
