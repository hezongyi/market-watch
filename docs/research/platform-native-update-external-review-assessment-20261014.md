# 平台原生更新 v2 外部审核意见分析

日期：2026-10-14。对象：[当前 v2 方案](../platform-native-update-implementation-plan-20261014.md)及用户提供的审核意见。仅分析，不改变已冻结审阅方案、应用或生产；以下分期和数值门槛尚不是已执行的发布决定。

## 判断

总体接受。此次意见主要补充工程投入顺序、可量化验收和异常终局；与先前复审“数据合同层可进入原型”并不矛盾。v2 补齐了责任与版本合同，但仍把轻重工程放在同一实施序列，尚未建立成本和收益决定后续投入的门槛。

需要调整三点：阶段 A 不是只改 reset 条件，必须包含分页接受凭据与价格/指标一致性；真实更正比例不能作为是否保持正确性的开关；volume 依赖拆分不等于原生主序列可以独立回写旧 volume。

## 对七项风险的回应

| 意见 | 判断和落实方式 |
| --- | --- |
| A/B 分期及 go/no-go | 接受分期，但拆出 A0 观测、A1 收敛和必要一致性修复。阶段 A 继续用既有历史恢复处理真实更正；阶段 B 才引入完整冻结恢复包、恢复队列和画面保留。真实修订稀少也不能跳过更正，更不能把 A 宣称为全面无闪。 |
| 证据不足将 reset 带回来 | 接受。unknown 单独计数并按原因分拆；先有界复核，而非账本 miss 立即 reset。保留尾部和当前接受范围证明，远端使用区间摘要/可验证基线，不因不在视窗就忽略已缓存数据。unknown 持续异常首先修复阶段 A 账本/并发/预算，不能靠做阶段 B 掩盖。 |
| 恢复包与长历史张力 | 接受，是实质缺口。预算拒绝只是保护，不能成为永远不更正的终局。先评估同一预算下按页冻结/共享输入；仍无法覆盖时回退已验证的普通恢复并明确未满足无闪目标，或由用户明确选择缩小历史/调整容量。不能自动丢掉此前拖出的历史。若普通恢复也失败，显示未完成并可重试，不声称一致。 |
| volume 修订占比 | 接受必出统计和依赖核对；不直接接受拆 pane 就免主序列恢复。当前 barsOf 将 volume 放入原生主 Bar，旧 volume 无法靠普通实时回调单独回写。可单独避免重算不依赖 volume 的 Python 指标；若要分离主价格和量数据，应是另一个有语义/兼容性验收的产品改动。 |
| 量化及长时间验收 | 接受。加入按负载分层的延迟、缓存命中、请求/数据量、内存、队列和游标指标，以及长时间运行。预算/超时/重试/TTL 必须在进入完整实现前有数值、单位、作用域、默认值和溢出行为。现有录屏不是干净性能基线，不能凭其编造“不退化”阈值。 |
| 闭源库版本固定与回归 | 接受。记录公开类型对应 v31.1、实际运行资源构建指纹、适配补丁身份及浏览器环境；将原型确认行为固化为应用回归，升级时重跑，保留许可内容保密。不能把文件名或单一 dataReady 当绘制合同。 |
| 开关、灰度和回退 | 接受阶段独立开关。阶段 A 退回 v1.25.3 已有修订判断/恢复策略；阶段 B 退回阶段 A 的普通恢复。不是让每个 bar 都全局 reset，也不是切 marketPolling=1。停用时必须结束/取消在途包、处理缓冲并核对新订阅，测试四种开关组合和运行中切换。账号策略由认证服务端控制，不放松来源口径隔离。 |

## 建议的分期与决策

### A0：先用数据确定问题构成

保持已有恢复行为，加入低成本、私有明细可关联的观察。每个候选与实际 reset 分别计数，分类为仅状态、仅 OHLC、仅 volume、混合数值、插入/删除/标签变化、缺口/身份、unknown；同时记录 UI 空白次数与持续时间、同一候选重复恢复和跨分钟最终值到达相对于新柱交付的时序。

必须报告 volume 修订频率与幅度分布、确认延迟，以及 unknown 的原因和账本命中率。分母至少包括每图表小时、每 M1 接续和每个候选；同源多图不能把一次供源修订算作多次独立来源事件。比较不只用“真实更正占原 reset 的比例”，否则大量误 reset 被消除后，真实比例自然会上升。

### A1：分类与必要正确性修复独立交付

实现接受基线/候选复核、分钟交接、区间凭据及分页竞争修复。修复平台非 SWING 两事务混版，定义普通增量价格与 Python 指标的输入身份、拒收条件与 pending；这些不能等待 B，因为不 reset 后原有重载更不能承担纠正混版的责任。

阶段 A 的必要一致观察可以采用短事务冻结输入/读回核对，但不要求同时建设全窗口恢复包和画面覆盖层。确有旧柱修订仍用既有可验证恢复，接受可能有短空白并在报告明确列出。若既有恢复无法满足价格/指标正确性，A 不得作为完成版上线，应补最小正确性恢复或退回旧模式。

阶段 A 的 go 条件：确定性正常 tail/append/metadata 回放零 reset；实际修订无漏修；分页/世代负载无游标倒退或丢 bar；Supertrend 同冻结输入完整重算一致；量化性能、缓存和资源达到先登记门槛。任一正确性项失败为 no-go，与闪烁收益大小无关。

unknown 的接续观察必须单独建预算。稳定来源、覆盖未淘汰的实时尾部受控回放要求 unknown 恢复为零；长历史/多图负载的非零容许率由 A0 分层测量后登记上限，不能事后把样本变差解释成通过。未给出上限和命中率报告，不进入 A1 发布验收。

### B：按剩余问题启动恢复体验工程

A 正确性与自身 unknown 门槛先通过。若剩余真实更正在目标使用场景仍造成可见空白，则不满足原始无闪目标，启动必要恢复原型；修订率、空白时间占比及峰值帮助排序和选覆盖场景，不作为丢弃修订的阈值。

若代表性观察暂未见真实更正，B 可以暂缓，但只能称“A 已消除正常/误判重载”，不能声称真实恢复连续性已证明或永远不会修订。若大量残余 reset 来自 unknown，先继续修 A，暂缓 B。

B 原型 go 条件：同版覆盖和资源预算闭合、运行时撤下旧画面条件可实现、交互/取消接续成立，且录屏通过连续画面目标。原型失败维持 A 的正确恢复，明确无闪目标未完成，不自动改变用户需求。

## 验收补充与进入完整实现的检查项

- 性能：同硬件、同冻结回放与相同图格/指标/历史深度，分别测热历史、冷历史和预热命中路径；getBars 从调用到 callback 的 p50/p95/p99、可见载入完成时间、交互延迟、请求数/字节数、前端/PG 缓存命中、主机堆/后端资源、队列高水位、释放后存量。预登记非退化容许幅度与测量误差，不把冷数据与热数据混在同一平均值。
- 持续运行：10–15 个 M1 边界作为快速检查；另至少一次建议 4 小时连续运行，加覆盖真实时段切换的观察或确定性回放。覆盖 24x7 与有交易时段的代表品种、多图/多参数、定期拖动和断线。与源有关的休市不能用生成假 bar 代替。
- 数值清单：账本/区间/核对预算，包条数/字节/并发/TTL，计算前缀/响应预算，队列条数/字节，准备/绘制/补齐超时，最大重试数，unknown 允许率，性能回归容许幅度。每项需有默认/生效值、超限状态、告警可见性与可重复测试；不能把浏览器回退常量当服务端生效能力。
- 模型回放：简明时间键 Bar/reference ledger 模型作为 oracle，固定随机种子组合乱序、重复、重叠、丢包、取消和世代切换；失败保存最小可复现轨迹。与真实 native 回归互补，不仅验证自己的实现镜像。
- 负向隔离：另一会话/账户、其他数据口径、过期 token、注销会话、旧恢复世代和错误覆盖范围均不能读取或提交包；输入共享仍受原有权限约束。
- 组合回归：固定历史与实时接缝、组合规则/版本绑定、DisplaySnapshot 选择与过期/迟到拒收、Python 同快照结果、同源多图、共享流订阅切换及真实历史更正；不要只测试主价格是否出现。
- 回退：验证 A/B 独立开关及切换时队列/包/世代清理，保持数据库、用户布局/绘图工具和告警配置；任何生产灰度或回退仍单独按明确授权执行。

## 结构调整建议

下一版把当前第 4 步拆为“同版输入合同”“恢复状态机”“画面展示门槛”“预算与终局”；给关键不变量编号，测试逐项引用：身份隔离、旧世代拒收、接受范围不推广、价格/指标输入同版、真实修订不能丢弃、视图取消不能取消同身份更正责任、资源有界且有终局。编号用于对照，不替代具体协议或测试。

该分析支持修订为分阶段方案；此处没有改写 v2 的已审阅内容，也没有把新分期冒充已经复审通过。
