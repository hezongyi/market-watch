## A 建议：原生行情 + 自建行情

将“平台行情”命名为 **原生行情**。
该名称说明 OHLC 周期由供应商直接提供。
它不等于不复权，也不保证所有来源实时更新。

将“组合行情”并入自建行情的可选扩展：**实时接续**。
用户只管理原生行情和自建行情两类产品入口。

底层映射、接续修订、拼接点和审计仍保留。
统一入口不要求合并数据库表或重写身份。

## B 为什么改名“原生行情”

本地不重切供应商直接返回的周期。
新浪、腾讯 A 股八周期和腾讯港股日周月均按原生周期获取。
供应商名称、原生周期、复权口径和缓存状态仍展示。

| 候选 | 含义 | 问题 |
|---|---|---|
| **原生行情** | 供应商原周期 | 首次使用时需要简短解释 |
| 供应商行情 | 第三方来源 | 未表达周期原生 |
| 直连行情 | 直接获取 | 易被理解为浏览器直连 |
| 平台品种 | 搜索目录 | 没说价格序列如何形成 |

## C 自建行情上的实时接续开关

自建详情显示“实时接续：关闭 / 开启”。
开启时，先选择并核对实时来源。
图表使用固定历史基线，再显示确认尾部与临时观察。

关闭接续时，历史和已确认尾部仍可读。
关闭只停止新实时采集，不删除历史、映射、审计或告警。
依赖接续的告警显示暂停判定，保留必要的已提交输入结算。
现有图表保留原身份，不静默换成另一份历史。
暂停历史维护与关闭实时接续是两个独立开关。

当前代码已把实时映射关联自建数据集。
通用实时开关也按自建品种设置。
独立“组合行情”主入口仍是概念分裂所在。

## D 内部数据模型继续保留

`RealtimeMapping` 记录两种产品的对应关系。
`CompositeRevision` 固定历史版本、接续来源与拼接点。
告警与历史回放需要这些证据保持稳定。

第一阶段只收敛页面和术语。
保留 `MWC:`、旧工作区、告警版本和旧 API 的读取兼容。
不要删除组合表、重写身份或静默更换实时品种。

## E 边界行为

| 情况 | 结果 |
|---|---|
| 从未开启 | 只有固定历史，无实时订阅 |
| 配置后关闭 | 显示映射和关闭状态，保留确认数据 |
| 市场闭市 | 显示历史与闭市状态，不当作错误 |
| 账户变化 | 重新核对映射，不自动更换品种 |
| 新历史版本发布 | 经基线切换流程生成新修订，不原位改写旧基线 |
| 多日界或多历史数据 | 每个自建数据集单独设置接续 |

当前接续只支持已核对的 OANDA Practice Bid 映射。
自建股票、期货和其他原生周期不能自动获得接续能力。
同一自建数据集可有多份配置，须明确选择默认配置。
开启接续不代表无条件恢复全部旧告警。
