# Swing 长样本的休市与缺口

实际 Docker API 验收发现：原4002根离线模型按连续K线下标计算，未调用应用的交易日历分段。应用在没有额外假日日历时识别四个交易日内缺口：2024-12-24 22:00Z→12-25 22:00Z、2024-12-31 22:00Z→2025-01-01 22:00Z、2025-12-24 22:00Z→12-25 22:00Z、2025-12-31 22:00Z→2026-01-01 22:00Z。

保守分段结果为high261／low246，间隔总和3878／3865，间隔数257／241，均值15.089494163424124／16.03734439834025，显示仍为15／16。只核对整数会漏掉此差异。

仓库已有官方页面文本：[OANDA SG假日日程快照](../sources/oanda-sg-holiday-trading-hours-20260929.txt)，来源 <https://www.oanda.com/sg-en/trading/holiday-trading-hours/>。快照说明时刻为Eastern Time，2025圣诞及2025/2026元旦记录外汇前日16:59结束、当日17:05重开；2025-01-01有FX 17:05重开记录。对应22:00Z至22:05Z的有限闭市内部区间可以解释该日H4缺柱，边界分钟不作为完整闭市。

**证据限度：快照没有2024圣诞完整日程，也没有2024元旦前日的关闭记录。** 2026-10-12再次请求主站被网络拒绝，help页面只返回Secure Login。因此2024圣诞时段与2024-12-31关闭使用明确的冻结验收V1假设，不能宣称逐日官方核实，也不能仅以没有K线推断休市。

[冻结验收日历](patternsmart-evidence-20261012/swing-acceptance-calendar.json) 为该任务专属数据集明确声明上述四段有限闭市政策，reason字段标出假设。它用于连接已约定的连续数组数值基准与应用的正常休市处理；不作为全局OANDA日历，不修改生产，不取消真正缺数的分段。没有此政策时应用继续输出保守分段值。

`test_frozen_calendar_declares_holidays_but_preserves_unknown_gaps` 同时验证：显式政策下4002根结果等于原基准；没有政策时仍识别4个缺口并得到261／246；删除非假日的周三K线仍产生真实缺口。生产数据需要使用该数据集已审核的来源日历，不能把本验收假设默认为所有年份或账户的规则。
