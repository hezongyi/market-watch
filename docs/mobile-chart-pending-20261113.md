## 分析依据

Ubuntu 浏览器 XAUUSD 单次：首次约 10.46s，同会话导航返回约 0.139s，切周期约 3.807s / 1.518s / 1.472s。首屏 countBack 约 60，最终返回 2000 根。仅为单次浏览器观察，不代表 Android 或冷供应商保证时延。缓存命中时返回额外历史不一定是耗时来源，不能将 2000 根一概归因为延迟。

手机导航切页已保留同一 widget；重建、周期切换需要分别检查。IndexedDB 当前保存布局和设置，不含完整 K 线历史。原生库提供 `takeClientScreenshot()`，可生成本地预览，但预览是图片，不是可交互历史缓存。

`loadNativeHistory` 只在收到整份 result 后交付数据，进度不包含可供绘制的中间 K 线。因此“去掉遮罩”和“服务器提前交付可见范围”不是同一件事。客户端历史加载有四个生命周期名额，取消后尚需清理服务器句柄；已有运行时焦点优先级不等于后台请求可以瞬间撤销。

## 建议路径，细节待确定

### 1. 先保证显示连续性

- 导航返回继续使用保留的 widget，避免再次出现全屏加载遮罩。
- 同品种、同周期刷新保留已有曲线和指标，新结果可用后立即更新；仅保留轻量“更新中 / 更新失败”反馈。
- 重建或切回曾看过的周期，先验证原生缓存能否立即恢复；需要过渡时显示该目标上次本地预览，行情及指标就绪后替换。
- 预览绑定服务器/用户、来源、品种、周期、主题及布局，少量有界保存，注销清理；注明上次时间，不伪装成可交互图表，不把旧 M5 显示成 H1。
- 从未打开且无匹配缓存的目标不能凭空显示真实旧图，用安静占位及失败重试。切换目标时不能把上一品种当成新目标数据。
- 首轮保留现有预取和整份 result 协议：可立即显示已有画面，不能承诺冷请求在现有历史任务完成前交付新图。若仍要求“可见范围满足就交付”，需单独评估结果交付协议，保持原预取任务继续，仅增加一致的可绘制快照交付；不默认纳入本轮，也不缩减指标预热。

### 2. 手机资源准备与少量行情预热

- 登录成功、自选首屏稳定后，空闲准备版本化脚本；目录、能力、布局与脚本并行准备，复用结果，只改手机生命周期。
- 建议首轮为“上次图表品种 + 当前自选排序第一品种”，去重后最多两个，每个只准备最近使用的一个周期；没有周期记录时采用当前图表周期，不扩散至所有周期。
- 本地访问计数可后续用于替换候选，首轮不叠加更多热门品种。计数按真实打开、服务器及来源区分，不修改服务器偏好。
- 后台串行、最多一个预热任务，没有前台需求才继续下一候选；不创建隐藏完整 widget 来逐品种预热。
- 用户进入图表或切周期，停止分派预热；同目标且需求兼容的在途任务优先复用/提升，不同目标请求取消，当前图表先获得可用容量。清理可能滞后，需要实测前台等待。
- App 后台暂停预热；回前台先恢复当前图表与行情，空闲再预热。注销或换服务器清理会话准备结果。
- 预热只是提前发起现有规则下的请求，不改供应商预取量。必须验证结果能被当前图表复用，避免提前拉取后重复加载。
