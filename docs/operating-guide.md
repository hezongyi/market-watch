# 守望使用指南

本指南对应单前端源码候选。主入口是 `/advanced-charts/:workspaceId?`；登录、账户、通知设置和图表位于同一 origin。候选只在 Ubuntu 本机 Docker 验收，地址和启动/停止命令见 [验收进度](verification/single-frontend-20261026/progress.md)。生产是否已升级必须另行核实。

## 创建与管理告警

1. 登录后打开已有工作区，核对品种、数据来源、周期和更新时间。
2. 使用图表原生告警入口创建规则，或从受支持的画线、指标和价格轴菜单进入。服务端验证所选条件、来源与图格关联；数据未就绪时按界面提示等待或重试。
3. 在原生告警面板读取、编辑或暂停/恢复规则。规则支持单次或有限 2/3 次触发；编辑与生命周期操作均检查当前版本，冲突时先核对服务器规则。
4. 关闭网页后，持久规则仍由后台推进；API 进程持有告警循环，API 重启期间会暂停判定。恢复后依靠持久检查点去重，不承诺停机期间持续监控。
5. 触发事件、投递状态与用户确认相互独立；确认事件不会改写规则次数。网页与 MCP 使用同一套 ChartAlert。

旧 Watch、兼容图表和历史演练已退役，不再创建、恢复或执行。新旧规则不自动转换。旧信号、审计、投递和演练数据仍保留；旧待投递任务退役不伪装为用户已确认。

## 工作区与数据中心

使用原生保存、另存为和加载功能管理工作区；刷新保留原应用地址。布局、画线、参数和告警关联随保存保留。保存期间的新编辑不会被旧快照标成已保存；失败草稿保留，按提示核对或复制恢复。手机保持只读。

数据中心从原生按钮进入，管理来源、自建历史、组合、任务和导出。历史准备、失败重试和发布进度在对应数据中心视图核对；任务排队不表示历史就绪。原生接入失败会显示可键盘操作的重试入口，不回退到另一业务 iframe。

行情默认按实际存在的有效 K 线计算；少量 M1 缺口不制造价格、不自动推断休市，也不作为默认递归指标重置条件。严格覆盖检查是显式选项。来源、报价口径、时间坐标和精度必须按界面与响应核对。

## 通知与账户

通知面板展示当前事件；旧 `/signals?signal=...` 链接会定位当前事件或显示历史退役说明。历史确认仍可使用，确认不会重新投递旧通知。

账户密码、通知及声音设置通过设置页管理，设置页不依赖图表库加载成功。网页声音需要浏览器授权和用户交互；页面关闭后的手机提醒取决于部署时明确启用的通知 worker、ntfy 配置和手机网络。服务器接受消息不证明手机已经收到，网站确认也不能保证远程停止手机响铃。

本任务关闭真实外部通知。已保存的真实手机接收记录属于各自历史验收，不代表本候选已完成锁屏或长期待机验收。

## 运维边界

`/readyz` 只表示基础可用；业务健康另外报告 API 告警循环心跳、最近成功/错误、规则 ready/waiting/blocked/stale 及投递积压。正常休市或单规则等待不等于循环停止。

日历和历史版本仍受 [交易日历维护](calendar-maintenance.md) 及持久引用保护；归档旧规则不会自动释放证据。合并、生产发布与永久删除按 AGENTS.md 另行授权。候选回退不得自动恢复旧 Watch 或重发旧通知，具体边界见 [完成审计](verification/single-frontend-20261026/completion-audit.md)。
