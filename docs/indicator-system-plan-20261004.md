# Market Watch 指标体系与搜索窗口方案

日期：2026-10-04。基线：62488c6（项目 v1.7.0）。本轮仅分析、核查和方案；未修改实现、安装依赖或部署服务。独立 worktree：market-watch-indicator-plan；branch：docs/indicator-system-plan。

## 本次范围与优先级（按用户最新确认修订）

主线是优化指标搜索窗口；其次审视现有 Python 指标架构，形成有证据、可独立交付的加固清单。暂不接入 Supertrend，也不以任何新指标作为布局交付的前置条件。以后每个待移植指标单独讨论，确认算法、输入、输出和验收标准，再补实际需要的接口。

本轮仍只调整方案文档。保留现有 TA-Lib 0.6.8、Python 3.11 和 NumPy 2.4.6 环境，不引入 pandas-ta 或其他发行版。此前的依赖冲突核查仅是未来选型参考，不构成本轮升级任务。

PineJS 核查结论不变：支持 JavaScript 指标与 Pine 风格 StudyScript 回调，没有 Pine Script 文本编译执行接口。详见 [证据核查](pinejs-interface-verification-20261004.md)。该报告中有关内置 SuperTrend 的发现作为事实记录保留，不代表新增接入计划。

## Python 架构判断

现有“后端 Python 计算 → 通用显示适配 → 原生图表”方向合理，8 个现有指标共用计算入口和显示协议，暂不需要拆成独立服务、建立插件市场或引入新的运行环境。

建议维持三个职责清楚的 Module：

- **指标定义与计算 Module**：管理注册、参数校验、输出声明、预热要求和纯算法；不读取数据库、不操作图表。
- **行情编排 Module**：获取历史、确认数据修订与完整性、裁剪输出、处理订阅；统一调用计算 Interface。
- **显示 Adapter**：把声明和计算结果映射为原生 study；名称搜索、收藏和图表实例管理放在选择器中。

现有 register/calculate 是可沿用的 Seam。优先将已分散的知识集中，不为假设中的指标增加新的抽象层。独立 Python 包仍是未来复用方向；当前代码可先在仓库内整理职责，实际需要第二个消费方时再决定抽包。

### A. 布局交付所需的最小配套

| 项目 | 当前证据与问题 | 建议 |
|---|---|---|
| 目录显示模型 | 后端已有 label，advanced-host/indicators.js 仍以“守望 Python + ID”显示 | 选择器使用中文名称、英文别名、来源、主/副图等展示字段；已有元信息优先复用，只补缺少的字段 |
| 名称与身份分开 | name、原生 metainfo.id、合成 symbol 共同关联加载与恢复 | 单独维护展示名与稳定 ID 映射；首期不要为改中文名重命名已注册 study；算法 ID、版本、原生实例 ID 分开处理 |
| 跨来源目录归一 | 原生指标来自图表库，Python 来自 catalog | 由选择器 Adapter 统一成列表条目，添加时路由到已注册 study；不复制一份计算注册表到前端 |
| 能力缺省 | 原生公开接口不一定提供全部用途/主副图元信息 | 只显示可靠字段；缺失则省略，不根据名字猜测，不为补标签执行指标 |
| 收藏与实例关联 | 现有原生收藏通过 settings_adapter 持久化；已添加对象由当前图表管理 | 先核实公开接口读写能力及稳定键；保持一个收藏事实来源，多实例按原生实例 ID 管理，不按指标名称去重 |

布局所需的元信息整理可以随窗口改动交付；下列计算架构加固可独立排期，不阻塞布局。

### B. 现有架构值得补强的地方

| 优先级 | 证据与风险 | 有限的优化范围 | 验收要点 |
|---|---|---|---|
| 高 | advanced_api.catalog 通过 calculate([], spec) 执行算法以推导输出；目录与算法运行耦合 | 显式声明现有 8 个指标的输出 key、顺序和绘图类型；catalog 只序列化公开元信息，排除 calculator/history_requirement 等内部 callable | 搜索目录不执行算法；生成的 plot 顺序与旧版一致；注册时能发现声明错误 |
| 高 | chart_indicators.py 的 period 分支先于自定义 history_requirement | 明确“已声明的自定义要求优先”，保留现有 8 个指标的预热规则；不顺便重写所有历史路径 | 自定义声明不被参数名遮蔽；现有指标预热、缺口处理和分页数值不回退 |
| 中高 | 输出 key 来自一次空计算，后续只检查长度；缺少 key 可静默留空，多余 key 可能触发异常 | 注册/计算入口校验 pane、重复 ID、输出 key 集合、顺序、一维长度和数值类型；计算函数不修改输入 | 正常值和真实 0 保留；NaN 转 null；错误标注指标 ID 和原因，不能伪装成“历史不足” |
| 中 | deviation 特例与整数范围在 Python/JS 各写一份 | 用统一参数声明描述现有整数、浮点范围与默认值；保留 MACD fast<slow 的跨参数约束 | 前后端规则一致、旧参数仍有效；新声明字段向后兼容；暂不增加尚无用例的布尔/枚举编辑器 |
| 中 | version 仅接受 1，显示 Adapter 中 study ID 与 plot 顺序影响恢复 | 先书面固定兼容规则：旧 ID/输入顺序/输出顺序保持稳定，语义变更使用新 ID；需要同 ID 多版本时另设计 | 旧工作区、模板、收藏、参数和样式仍可恢复；显示名改变不改变计算语义 |
| 中 | 当前已有多条历史取数路径，不同请求历史范围可能影响递归指标 | 明确闭合 K 线、gap_before、输入起点和裁剪职责；用现有 EMA/RSI/MACD 核对实际路径 | 固定同一输入起点后，分页与整段结果一致；追加未来数据不改变已确认历史；不把固定倍数预热描述为任意递归指标严格等价保证 |
| 后续测量 | 多条曲线经合成品种取数，后台按请求计算；已有共享历史请求机制不等于已无重复计算 | 先量化计算次数、输入长度和耗时，再决定请求内复用或缓存；不为提速截短递归历史 | 如增加缓存，键含数据集/价格口径/周期/修订/历史起点/算法版本/规范化参数，修订和补历史必须失效；此项尚未有性能实测结论 |

依据：[chart_indicators.py](../backend/alerts/chart_indicators.py)、[advanced_api.py](../backend/alerts/advanced_api.py)、[indicators.js](../advanced-host/indicators.js)、[managed_dataset.py](../backend/alerts/managed_dataset.py)、[provider_cache.py](../backend/alerts/provider_cache.py)。上述是静态审查发现与拟议验收要求，不表示已实施修复或已经发生线上故障。

图表指标与预警指标仍是两种不同 Interface：[indicators.py](../backend/alerts/indicators.py) 当前预警只消费 close 并返回 value/reference。以后出现同一算法同时用于二者的具体需求时，共用纯算法并各自保留 Adapter；现在不强行合并注册表，也不把添加图表指标解释为开启预警。

### C. 留待具体指标讨论的接口

暂不实现 OHLCV/时间输入扩展、多周期/多品种计算、盘中逐 tick 状态、箭头/填色/矩形/标签、事件输出、任意脚本在线执行、插件热加载、pandas-ta 环境升级或独立计算服务。是否补接口由具体指标的真实要求决定。

每次移植按同一简短流程：固定源码和版本 → 明确输入及收盘/重绘语义 → 确认最小接口缺口 → 实现算法与显示适配 → 使用相同行情逐根对照 → 验证保存恢复。不能用“已支持同名函数”代替数值兼容验收。

## 指标搜索窗口方案

采用用户同意的“顶部搜索 + 左侧分类 + 右侧列表 + 已添加独立入口”。维持项目原生浅/深色视觉。以下是产品方案，尚未实现或运行浏览器验证。

| 区域 | 内容与行为 |
|---|---|
| 顶部 | 标题“指标”、关闭按钮、固定搜索框；提示“搜索名称或缩写，如 均线 / SMA / RSI” |
| 左侧 | 全部、收藏、内置指标、我的 Python、当前图表已添加；来源与状态是主导航，趋势/波动等用途分类作可选筛选，不混成同层导航 |
| 右侧列表 | 收藏星、中文名称和英文别名、来源标记、主图/副图、添加按钮；紧凑行，不使用大卡片；列表独立滚动 |
| 简要详情 | 点详情展开用途、输入、版本和计算说明，默认不占固定第三栏；依赖包版本保留在高级详情 |
| 已添加 | 显示具体实例和参数摘要，例如 SMA(20)、SMA(60)；设置、显隐、移除；仅作用于当前活动图表 |
| 底部 | 添加结果状态提示、完成按钮；连续添加时窗口保持打开，保留查询和滚动位置 |

桌面建议宽约 820–920px（受视口约束），分类栏约 160–180px，弹窗最大高度约 80vh。窄屏转换为单列+分类选择，避免水平滚动。尺寸是设计起点，后续需在真实窗口验证。

交互细则：

- 搜索覆盖名称、别名和 ID，排序为精确匹配优先、前缀其次、包含最后；同名原生/Python 条目明确区分。
- 当前分类内搜索，无结果时提供“在全部指标中搜索”和清除筛选，不显示空白列表。
- 收藏和添加是独立动作；允许同一指标多个参数实例，不因“已添加”而禁用添加。
- 参数继续使用原生设置窗口；添加后可以直接进入设置，关闭设置返回列表状态。
- “原生 / Python”展示计算来源；不要把 TA-Lib 与 pandas-ta 当作用户必须选择的平行菜单。算法不同才作为明确命名的独立变体。
- 展示已有收藏数据，迁移需保持原生收藏与自定义入口一致；不能平行维护两个互不相通的收藏列表。
- 键盘焦点约束在对话框内、Escape 关闭、关闭后归还焦点；添加状态不抢焦点。小屏操作目标至少 44px，桌面紧凑行仍需可访问的按钮目标。

技术路线：仅缩放/间距可使用现有 custom_css_url；要完整实现上述分类、中文别名和实例管理，优先项目自有选择器，通过公开图表 API 枚举/创建/管理 study，Python 目录来自已有 catalog。实现前验证当前 v31 的原生 study 名称、输入、实体 ID 与收藏映射，不修改 vendor 压缩包，不通过搬动 vendor DOM 来拼布局。样式层作为备选仅能完成部分布局要求。

## 实施顺序与完成标准（本轮仅方案）

1. **布局接入核查**：验证当前库公开 Interface 能否枚举/创建指标、管理实例、打开原生设置、读取和复用收藏。确认中文展示映射和浅深色规则。若收藏没有合适公开读写路径，记录兼容限制并单独确定方案；不访问 vendor 私有对象或直接改内部 settings 键来模拟支持。
2. **先交付搜索窗口**：使用现有内置指标和现有 8 个 Python 指标，完成顶部搜索、左侧导航、列表、收藏和当前图表已添加管理，以及必要的目录展示字段。不等待新增指标或计算框架重构。
3. **独立交付架构加固**：按 B 表优先级处理目录与算法解耦、预热声明、输出契约，再处理已有参数规则集中化与兼容验证。允许分批，不做一次性大重构；没有性能证据不先引入复杂缓存。
4. **以后按指标扩展**：用户提出某个具体指标后，单独讨论实现、依赖与所需 Interface；Supertrend 当前不排入实施任务。

布局验收使用 SMA/EMA/RSI/MACD/BBANDS 等既有条目：中英文搜索、来源区分、分类空结果、连续添加、同名不同参数实例、当前图表操作、多图切换、收藏刷新恢复、旧工作区恢复、参数设置、浅深色、窄屏和键盘操作。活动图表变化时刷新已添加列表，未完成的异步添加仍绑定发起时的图表，不误加到另一张图。

架构加固验收围绕真实风险：目录不执行算法、已有输出及 plot 顺序保持一致、自定义预热声明生效、非法输出失败明确、旧参数/模板可恢复、既有递归指标历史行为不回退。布局和架构分别记录验证结果，不能以其中一项通过代替另一项。

未来开发与验收仅在 Ubuntu 本机独立 Docker Compose project 内进行，数据库、端口和卷独立；不使用 unraid 开发。本轮只修改方案文档，没有新增运行实例，因此无新增访问地址、启动停止命令或部署验收结果。
