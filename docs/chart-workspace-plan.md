# 专业图表工作区实施方案（需求定稿）

日期：2026-09-29。状态：用户已确认共享、同步、保存、指标口径、周期、布局与周/月边界；最新补充确定TradingView参考视觉、独立全屏工作区，以及W1/MN从D1聚合。需求已定稿，用户已授权实施；已在独立开发分支实现并验收，未部署生产。实现调整与维护说明见 chart-workspace-implementation.md。

## 1. 已确认范围

- 新增独立图表工作区；既有监控、通知、演练模块继续使用现有实现。
- 多个命名工作区，每个支持1、2、3、4张独立品种/周期图。
- 八类画线：水平线、趋势线、射线、矩形区域、斐波那契回撤、文字、平行通道、多空仓位盈亏比。
- 十字线与时间范围跨图同步为刚需；同品种跨周期共享画线。
- 电脑为主要分析/编辑设备，手机查看和接收现有通知；不做完整手机画线编辑。
- 沿用现有M1采集，不新增逐笔或秒级实时行情；显示数据截至时间，不暗示当前报价实时跳动。
- EURUSD/XAUUSD继续OANDA Bid、NY17交易日；BTCUSDT继续Binance Last、UTC0。用户显示时区与分桶时区分离。
- 暂不做画线触碰/突破通知、自动下单。
- 指标以Python长期维护，优先复用TA-Lib/NumPy。图表显示与算法分离。
- 技术候选已运行验证，当前优先Lightweight Charts5.2.1＋固定版本Line Tools；独立模块不替换原有Chart组件。

## 2. 已确认决策与新增口径

用户已确认：

| 项目 | 决定 |
|---|---|
| 画线共享 | 同工作区＋同品种跨周期共享，不同工作区独立 |
| 同步 | 默认同步十字线时间、缩放与左右时间范围，各图周期独立；不同品种不共用价格位置，可关闭同步 |
| 保存 | 服务器自动保存＋手动立即保存，支持命名、复制、重命名、删除；手机读取已保存内容 |
| 指标 | SMA、EMA、布林带、RSI、MACD、ATR，新增LWMA、随机摆动指标；多条均线、参数修改、模板保存，Python维护算法 |
| 盈亏比 | 入场/止损/止盈、距离、百分比和盈亏比，不增加本金、手数与金额计算 |
| 周期 | M1/M5/M15/M30/H1/H4/D1/W1/MN；MN表示自然月，不是固定30天 |
| 布局 | 单图、左右双图、上下双图、上单下双、上双下单、四宫格；可拖动分隔线、临时最大化 |
| 显示时区 | 默认随品种原始分桶时区：外汇/黄金America/New_York，BTC UTC；可切换显示时区但不改分桶 |

已确认的计算口径：

1. **指标定义**：LWMA为线性加权均线（最近值权重最大，TA-Lib WMA）；随机摆动指标为Stochastic %K/%D，默认14/3/3、SMA平滑、20/80水平线，参数可修改。采用Stochastic，不采用KDJ或StochRSI。TA-Lib STOCH参数为fastk_period=14、slowk_period=3、slowk_matype=0、slowd_period=3、slowd_matype=0。LWMA周期N的权重从最旧1到最新N，归一化分母N(N+1)/2。
2. **周/月边界**：FX/XAU周线按纽约周日17:00至下周日17:00；月线以D1交易日结束日期归属月份，月初第一个日历日对应的D1从前一天纽约17:00开始，遇休市不虚构K线。BTC周线UTC周一00:00起、月线UTC每月1日00:00起。此定义不声称与OANDA原生W/M或其他平台完全一致，若需平台一致须另核对。

## 2.1 界面参考与复用决定

- **整体布局与操作习惯参考TradingView**：顶部工作区/品种/周期/指标/布局，左侧绘图工具，图表内指标图例及对象编辑，底部时间与数据状态。按本项目已确认功能取舍。
- **开源工具栏实现参考KLineChart Pro**：工具分组、图标和面板交互，许可允许的代码可选择复用并保留出处。其Solid组件不能原样当React组件使用；只移植有价值部分，不引入Pro旧核心。
- 图表引擎仍是Lightweight Charts＋固定版本Line Tools，不因参考Pro界面切换引擎。
- **视觉风格参考TradingView**：紧凑的专业图表界面、清晰的轴线与网格、克制配色、窄工具栏与较高信息密度；新模块不沿用现有“守望”页面的配色和卡片布局。使用自有中文文案及开源图标，保留图表库归属要求。
- **独立全屏页面**：用户从现有站点入口进入后，显示图表工作区自己的页面框架，不渲染“守望”的左侧导航或仪表盘页头。图表左侧保留的是绘图工具栏。顶部提供工作区切换和返回工作台入口；这里的全屏指占满网页可用区域，不自动调用浏览器Fullscreen API。
- 默认通过独立路由在当前标签页进入；入口为普通链接，用户也可新标签页打开。是否浏览器新标签不影响工作区隔离与保存。
- 周期栏直接展示常用周期，窄屏提供更多菜单；手机以切换查看单图为主，保持电脑布局数据。
- 3图布局用明确模板和CSS Grid实现，与1/2/4图共用状态，不增加自由停靠桌面。

## 3. 产品规则（已获认可的建议及实现细化）

### 工作区与保存

- 顶部选择工作区；布局按钮、品种/周期、指标、同步开关；左侧绘图工具栏；选中对象后显示样式编辑。
- 保存布局比例、图表顺序、品种、周期、显示时区、指标参数/样式、画线、同步设置和视图模式。
- 视图模式分为“跟随最新”和“固定历史位置”；历史位置按时间范围保存，新增行情不强行拉回最新。
- 自动保存候选策略：绘图结束/拖动结束与参数变更后防抖保存，拖动过程中不逐事件写库。界面明确显示保存中、已保存、失败。
- 断网/保存失败保留待提交本地草稿并显示状态；重新连接进行版本检查，不以卸载页面请求作为唯一保障。
- 多标签编辑同一工作区采用revision乐观锁；冲突返回409，提供刷新或另存副本，不静默覆盖。手机只读不写回布局/视区。
- 工作区复制时复制画线并分配新ID，避免两个独立分析方案相互修改。此规则依据已确认的工作区隔离原则。

### 绘图

- 时间＋价格存储锚点，严禁只保存屏幕像素或当前数据下标。
- 编辑/删除/隐藏/锁定、颜色/线宽/线型；文字编辑；斐波那契级别可配置。
- 建议包含当前会话撤销/重做和删除确认；历史版本永久撤销不纳入基础实现。
- 一次只激活一种工具；Esc取消未完成绘图，切品种/周期/布局前明确结束或取消绘图。正式解决原型中连续工具切换状态问题。
- 同品种跨周期共享需处理增改删，不只是复制新建对象；通过稳定ID防止重复/循环同步。
- 工具显示在主图；首版指标副图画线暂列扩展项，用户如需要应单独确认。
- 盈亏比按绝对价格距离计算，止损/止盈方向校验；止损等于入场时显示无效，不除零。是否涉及金额/手数本版不纳入。

### 多图同步

- 按时间同步，不按相同K线根数或屏幕下标同步；同品种可同步十字线价格，不同品种仅时间。
- 按目标K线[start,end)归属光标时间；休市/缺失区间不把上一根已结束K线伪装成当前覆盖，不吸附到未来K线。
- 可见时间范围按统一时间边界协调；边界落在不同周期K线之间时明确离散化规则。端点无数据时可截断并提示，不能无限互相回写。
- 控制主操作源、重入与节流；加载历史/切周期完成后恢复视区，不能因异步旧请求覆盖新选择。
- 同品种多图共用行情与指标缓存，避免四图变成四份重复上游请求。

### 历史和更新

- 复用现有/api/candles的before/limit分页（当前每次最多2000根），向左加载历史。
- 同品种/周期请求合并；离开页面停止轮询，隐藏标签降低刷新频率。
- 保留数据缺口/未完成状态，缺失不填虚构K线；现有M1更新节奏下不承诺分钟内触价展示。
- 已形成高周期K线与形成中K线按后台实际语义显示；指标正式基线使用已完成K线，不改变现有收盘预警行为。


### 新增周期的后端工作

M30/W1/MN不是只在周期栏增加按钮：必须扩展后台时间周期注册、聚合、历史导入/修复、完整性检测及指标取数。月长不固定，周/月跨夏令时的实际秒数也会变化，不能用固定分钟数替代日历边界。

- M30沿用本品种既有分桶锚点及交易日历。
- **W1/MN仅从本系统D1聚合**，不使用行情商W/M，也不在前端重分桶。按已确认交易日归属分组：open取第一根有效D1的open，high取最大值，low取最小值，close取最后一根的close。
- D1为唯一周/月价格输入；底层历史不足时先补齐/修复D1，再重建受影响的W1/MN。D1修订必须使对应周/月聚合和指标缓存失效。
- 周/月完整性同时检查周期是否结束、所有预期交易日的D1是否存在且完整，以及日历覆盖是否充分；休市不视为缺失，未知缺口不能被聚合掩盖。仅有数根D1也能画形成中/不完整周月线，但不能标为完整。
- 切换显示时区只改变标签格式，轴位置与存储保持UTC时间戳。月线显示所属交易月份，避免边界时间位于前月造成误解。
- 形成中的周/月K线与已收盘状态明确区分；历史周/月指标预热可能需要较长数据历史，不用目前少量开发样本宣称覆盖。
- 新周期首版提供给图表工作区，不自动扩大既有策略/演练允许的周期范围。检查现有共享TIMEFRAMES校验，避免新增图表周期意外改变既有API语义。
- 验收包括跨年周、闰年2月、长短月、夏令时切换、节假日缺口与完整/形成中标记。已有M1—D1结果必须保持一致。

## 4. 技术设计

### 前端

新增独立路由与懒加载模块（建议/chart-workspaces/:id），置于独立页面框架中，与既有侧栏布局为同级路由。共享登录鉴权，不共享现有侧栏和仪表盘页头；原站仅增加入口，既有行情/演练页面不迁移。

1. 工作区管理和布局组件：React/TypeScript，固定分屏用CSS Grid；不引入自由停靠库。
2. 图表适配器：包装Lightweight Charts、Line Tools，负责生命周期、坐标、数据增量、绘图事件，不让业务代码依赖插件内部实现。
3. 同步协调器：时间范围、十字线、画线共享；独立于单图实例。
4. 状态/保存：工作区文档、绘图对象、revision、草稿和保存状态。
5. 指标通用渲染器：line/histogram/area等标准图层及主副图；复杂绘图另扩展。

复用原型验证结果和上游组件，不将原型main.js直接作为生产模块。社区插件固定提交、保留LICENSE/NOTICE、以可复现编译产物接入；升级前跑关键绘图/恢复案例。

### 后端和数据库

复用FastAPI、SQLAlchemy、Alembic与现有PG；开发/测试仍用隔离库。

建议新增：

- chart_workspaces：名称、布局/设置JSONB、schema_version、revision、更新时间。
- chart_drawings：所属工作区/品种、稳定ID、类型、锚点、样式/插件状态、schema_version、revision；共享键为工作区ID＋品种ID。
- chart_indicator_templates：可复用指标组合、参数和样式；模板与实例分离，修改模板不悄悄改变已有工作区。

保存工作区及绘图差异应有事务边界；对对象数、载荷大小、参数和渲染类型做合理校验。所有接口复用现有身份校验。

建议API：工作区CRUD/复制、revision校验保存、绘图变更、指标目录/模板、指标历史序列。服务端更新与前端保存格式各自版本化。

## 5. 指标长期维护

### 稳定契约

指标声明id、version、参数schema、warmup、输入字段、图层定义和Python计算函数。返回按UTC时间戳对齐的序列；warmup不足为null，不填零。输出可有多条线/柱（例如MACD）。

- 常规指标新增：添加Python插件＋元数据即可生成参数表单和标准图层。
- 特殊交互图形可能仍需TypeScript适配，不承诺所有Python结果无需前端开发。
- 参数模板与算法版本一起保存；升级算法不静默重算用户旧分析。
- 现有预警Reading协议保持；另新增历史序列输出层。图表与预警共用计算内核，但“图上能显示”不自动等于“已支持对应预警条件”。
- 递推指标（EMA/RSI等）统一历史初始化、预热和数据修订策略，避免短窗口与长窗口数值不一致；历史分页不能改变已确定的指标值而不解释原因。
- 缓存按品种、周期、指标版本、参数、数据修订隔离；设计算量边界，防止图表请求拖慢通知和行情任务。首版优先轻量计算，测出瓶颈才引入额外运行单元。
- 无Pine Script兼容层，不开放未经隔离的网页Python任意执行。
- 无统一可靠volume输入时，不提供假成交量驱动的VWAP/OBV等指标。

原型已验证SMA、EMA、RSI及自定义EMA偏离百分比；布林带、MACD、ATR、LWMA、随机摆动指标已纳入需求清单，未声称已实现或验收。

## 6. 实施顺序与验收门槛

1. 需求定稿：已完成，按本文实现；重大范围变更另记录。
2. 基础工作区：独立路由、接口/迁移、命名与布局、行情分页；用开发库演示。
3. 绘图和同步：八类工具、编辑/撤销、共享、同步、保存恢复；含休市/DST/历史分页/未来空白区坐标验证。
4. 指标和模板：目录/参数、Python序列接口、首批指标、模板；新增示例插件验证维护路径。
5. 稳定性：多标签冲突、断网保存、性能和手机只读；对既有预警模块做针对性不受影响验证。
6. 发布准备：迁移/备份/回退方案、固定镜像清单、版本候选。开发完成后再按本项目发布授权流程安排生产上线，不在本需求核实阶段部署。

关键验收：

- 从工作台进入独立图表页面后无原站侧栏，图表工具栏/工作区切换/返回入口正常；视觉参考TradingView。
- W1/MN的OHLC逐项与D1独立聚合结果一致；日线缺失、修订、休市和未收盘状态正确传递。
- A/B命名工作区各自恢复布局、品种、周期、指标和画线；共享边界符合工作区隔离原则。
- 同步开关可用；M5/H4/D1与不同品种均无循环跳动；光标/视区规则可解释。
- 八类工具均能真实鼠标创建、编辑、删除、刷新恢复；多空工具双向检查；撤销与保存不会复活已删除对象。
- 夏令时/周末/黄金维护窗口/历史前插后，画线原始锚点和视觉定位一致；未来空白区投影不靠“最近10根K线”等不可靠推测。
- Python数值对照与warmup、参数边界、多输出、数据修订检查；算法版本和模板可恢复。
- 1/2/3/4布局切换及4图＋指标＋约100条画线作为初始验收规模，目标交互无明显阻塞；具体设备基线记录实测，不承诺未经测量的FPS。
- 手机可切换查看各图，不能因响应式布局覆盖电脑工作区保存状态。
- 生产行情、通知、既有监控/演练行为不因新模块改变。
