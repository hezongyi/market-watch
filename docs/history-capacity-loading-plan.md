# 可调连续历史容量与加载反馈（2026-10-05）

基线 `54be695`，独立 worktree `market-watch-chart-sync`，分支 `fix/native-chart-window-sync`。用户认可汉堡菜单调整容量、默认 200,000 根的连续加载方案，并要求右下角历史加载提示稳定、信息完整。Ubuntu 为唯一开发验收环境；不操作 Unraid/生产。

## 已授权实现

- 保持原生连续数据路径，不引入自动切窗或历史模式，不为设置/提示 reset 图表。
- 汉堡菜单“历史数据容量”，带主题、可见标签、键盘操作的弹窗。默认每品种周期累计 200,000 根，20,000–1,000,000（部署可降低服务端上限）。后端严格校验并持久化，当前 widget 立即应用，以后工作区复用。其他已打开页面刷新后应用。
- 工作区加权容量随用户容量乘四，上限受部署保护限制；每 pane 基础权重 1，每指标增加 0.5。默认 800,000 加权根；不是四个各有指标的 200,000 根图均可加载。默认响应上限 128 MiB、任务 600 秒，独立保护不被用户设置绕过。
- 降低容量保留常驻数据与已有区间定位，拒绝新增增长/指标的超额开销；释放已有数据需重新打开工作区。运行中的后端任务按当前设置检查，调低后可能明确拒绝，已缓存页保留。
- 超限明确说明来源、投影根数、实际限制、设置入口；拒绝后仍可执行后续有效导航。原图保留。
- 提示覆盖真实 getBars 排队、缓存检查、等待/补数、交付及原生回调处理至下一帧。缓存返回路径也覆盖。显示品种、周期、请求根数、请求时间范围（UTC）、实际缓存页数、收到根数、耗时；并行按品种周期聚合，保留取消。缓存页数不是总量百分比，所示日期是请求区间，不保证都包含实际交易 bar。
- 小于 250ms 的加载不弹出；已显示的短任务保留结束状态，减少短闪。完成、失败、取消、旧 frame/工作区不能留下或复活提示。耗时更新不在 live region 中逐秒播报。

## 验证范围

默认/持久化/严格输入/后端准入、升高后原请求可加载、降低后常驻范围仍可定位、热/冷阶段和真实页数、取消失败释放、真实四图原生同步与 hover 回归。真实产品复核用户 W1 2025-07-14 → M5；原 80,000 配置投影约 91,983 根，候选 200,000 配置应允许。

## 新建议仅分析，尚未授权实现

用户提出超限后让 M5 跳到容量允许的最早边界，避免仍停在 2026 年误认为失效。认可其交互价值，但本轮用户要求“分析”。需要区分缓存最早位置与真实容量极限；有余量时先有预算地补齐并计算真实交易边界，原拒绝导航结束后另行定位。提示同时列请求与实际日期；十字线不得伪装已到请求日期。仅容量超限回退，不对取消、网络/行情失败回退。此行为会替代“超限保留原位置”，本轮不擅自实施。

## 已知性能边界

现有真实库研究显示单源 200,000 根、多指标四图混合布局仍可能出现约 3 秒主线程任务，低速客户端更长。加载提示改善可见反馈，不能消除原生同步计算阻塞。允许配置值不等同于每设备/每指标组合的性能保证。
