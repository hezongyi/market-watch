# Issue #75：已确认的通知界面与分流合同

2026-10-19 用户确认方案 A、系统消息与交易告警分流、顶部居中即时浮窗，并授权实施。此合同替代此前把交易告警纳入通知中心、把通知中心挂到右侧 widgetbar 的界面约定；原 #75 的可靠接收、来源证据、持久去重、投递/阅读隔离仍适用。

## 消息归属与唯一即时出口

| 类别 | 查看和管理位置 | 即时提示 | 点击记录去向 |
| --- | --- | --- | --- |
| 系统消息 | 工具栏入口打开的右上角通知中心 | 首次异常、严重升级提示；普通 info 只入记录；同一异常重复合并次数；恢复更新原事故 | 系统消息详情 |
| 交易告警 | 现有右侧警报 / 日志模块 | 遵守规则 notify_web 与事件去重；持久排队，点击确定后消失，共用同一浮窗 | 对应告警日志中的实际 signal |

中心列表、搜索、筛选、连续滚动加载和未读角标只包含系统消息。按事故显示最新一条，底层每次发生保留，详情中的排查内容可以分页回查。全部已读只操作用户点击时的日志水位，不会把后来到达的消息提前读掉，不变更 handled、原手机 ack 或 outbox。重建 epoch 不匹配时拒绝执行。

旧专业图表通知深链和旧 signal 深链均把交易事件引向现有告警日志；兼容提醒历史不重复展示专业图表告警。旧主页全量通知/声音主动消费继续退役，历史查询与原手机停止协议保留。原被动保存等待、样式保存成功、修改密码成功窗口也归入中心。用户主动打开的设置/表单、输入校验以及防止草稿丢失的确认属于操作界面，不是额外的消息出口。

## 布局与操作

通知中心是右上角非模态浮层；不注册新 widgetbar page，不收起或替换原有侧栏，不改变画布大小，不新增工具栏行。即时浮窗固定在屏幕顶部水平中线、现有工具栏下方 8px；最多一张。没有背景遮罩、全屏拦截层或焦点陷阱，不自动拿走键盘焦点，也不拦截卡片外的 Escape。卡片自身覆盖区域接收卡片的交互，不能穿透点击。原生控件菜单只在用户打开时按既有方式处理焦点。

窄屏仍使用同一非模态中心，不自动转换成模态窗口。浮窗宽度按可用视口与可见自选表边界收缩；测试覆盖实际侧栏尺寸。图表外壳加载失败时，父页面以同一中心/浮窗提供降级展示，并与正常适配互斥，不生成第二套消息存储或消费器。

## 复用边界

直接复用已确认预览的 NativeSystemMessages、Dialog / DialogSearch / NavButton 和图表原生 5px 滚动条。搜索不自动聚焦，点击后也不显示蓝色外框。复用现有 NativeAlertControls：原生 InputControl、Select、Checkbox、Button，以及 AlertMenu 对接的原生 PopupMenu / PopupMenuItem；工具栏入口用固定 52px 的系统 SVG 图标和红色数字角标，0 隐藏、超过 99 显示 99+。新增内容仅为消息列表、详情排版和非模态定位容器。许可库文件不修改。native-alert-shell 增加 page=null 的只加载控件模式，所有 widgetbar 私有访问继续封装在固定版本适配器中。根部 Runtime / IndexedDB / 幂等投影 / 声音调度和现有告警模块继续复用。

系统异常浮窗开关按当前主体和浏览器 profile 存储，并跨同源标签同步；关闭只影响系统提示，交易告警和两类历史记录不受影响。关闭开关不追弹先前消息。

## 已确认的即时调度

系统消息显示 8 秒，悬停或焦点进入暂停；交易告警不抢焦点、无模态遮罩，持续到点击“确定”，查看图表或记录不能确认。当前告警不被新告警替换，新告警排队并显示另外待确认数。告警优先于系统浮窗，抢占后的系统消息与告警等待期间到来的系统消息仅保留在中心，不补弹。确认凭据独立于阅读、处理和手机停止，刷新恢复未确认项目，不受旧 30 秒 TTL 或 20 条队列上限影响。


### 慢加载时保持图表布局（2026-10-19 补充）

- 删除超过 5 秒自动出现的历史加载条，指标计算、历史失败和声音解锁也不再占用顶部行。普通切换沿用图表内部加载状态，不生成系统消息。
- 历史／容量／指标的实际故障沿用系统消息中心和统一即时浮窗；不再自动打开另一块状态面板。
- “图表菜单 → 历史加载详情”按需打开浮层，保留进度、重试、取消与容量设置；“取消历史加载”也可直接从图表菜单操作。浮层不参与 flex 布局。
- 声音开关／解锁保留在现有设置页的网页声音入口；不再显示专业图表顶部解锁条。
- 验收必须覆盖真实历史请求延迟超过 5 秒的切换场景，比较 iframe 和图表画布在加载前、中、后的坐标与尺寸。
