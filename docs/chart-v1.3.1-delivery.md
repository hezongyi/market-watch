# v1.3.1 自建历史修订修复

2026-10-02。按用户授权发布修复源码，合并main并推送main及v1.3.1附注标签；保留v1.3.0和原发布记录。源码及验证关联见[源码发布清单](../deploy/releases/v1.3.1-source.json)。本次没有升级Ubuntu运行容器或Unraid生产，也没有发送真实通知。

## 修复行为

此前自建发布器只处理最新2000根及历史左边界之前的数据，已经发布的内部区间更正可能永远留在staging。现在写入更正时，同事务登记受影响的已发布桶；发布器等待对应聚合完成，按有界页更新快照并清除任务。M15更正映射到M30，D1更正映射到周/月桶；事务失败及重启不会丢更正，也不改变原批准历史起点。

此前自建接口返回history_check=null，已打开图表不会因历史更正触发重载。现在对本会话范围的稳定历史前缀检查已发布行的修订号，通过现有公开reset/重载路径处理更正。排除最后一根实时bar、新增行情及会话左边界之前的扩展，保留原会话边界和既有视区恢复路径。日/周/月时间标签先转换到相应交易日会话起点再检查。

## schema、升级及回退

新迁移为`o16_managed_revisions`，基线`n15_provider_revisions`：

- `chart_published_bars`新增行修订号，已有值初始化为1。
- 新增`chart_publication_jobs`持久待核对桶。迁移为既有快照登记一次核对，修正v1.3.0可能遗漏的更正；后续后台按有限页处理，不全量重发。
- 升级不更改原始行情、维护起点、已有快照内容或平台缓存。
- 降级保留原始行情及发布快照，删除新队列和行修订号。回退到v1.3.0会重新具有已知缺陷；正式回退仍须备份、停写，并匹配schema与API/worker版本。

部署前在明确选定的隔离或正式库备份并验证，再由对应新镜像执行迁移。`compose.advanced.yaml`仍是旧版部署准备配置，不能直接用作v1.3.1正式部署：需要专用realtime-worker和chart-aggregation-worker、正式chart origin、数据库连接预算和发布镜像选择。

## 验证范围

本次用当前源码、内存SQLite及新建临时PostgreSQL17库验证，未使用运行库、共享开发库或生产库。新增回归覆盖超过2000根的内部修订、跨事务持久性、M30/周/月更正、聚合未完成时保持旧快照、事务回滚、迁移往返及会话修订检查。前端新增测试使用真实后端响应，确认历史更正触发公开重载而更早扩展不重置会话；既有视区恢复及忙碌重试测试同时保留。

完整PG17环境后端312通过、1跳过；跳过的是需要配套pg_dump/pg_restore的备份往返测试，本轮缺少这些工具，未将旧PG16成绩当作新测试。36项前端VM、Ruff、TypeScript/Vite构建通过。最终源码、构建及证据文件关联以源码发布清单为准。

## 镜像和运行边界

本轮Docker socket与组切换受环境限制，未构建新的API/web/chart容器镜像，未重新标记v1.3.0镜像，也未重启既有服务。v1.3.1源码包含运行代码和schema变更，旧v1.3.0镜像及验收不覆盖这些修复。发布清单明确区分源码验证与容器交付；后续部署需从清单固定源码构建、记录实际镜像ID，并在目标隔离环境验证迁移和图表历史修订后再安排上线。
