基线：`cf72811d`，开发实例应用 `fc3fa6a9`；PR #134。用户授权继续实施、验收、开发部署和更新 PR，不追踪 CI，不合并、不打正式 tag、不操作生产。

## 范围与约束

F1：缓存回收与逐报价持久链路，保留逐条事务提交、报价展示、告警输入、所有者/epoch 围栏和首个告警注册的 dataset 锁顺序。无 schema/持久格式变化；不用报价批处理、降频或负面消费者缓存。

1. 对不变的 provider 缓存跳过容量全表计数。使用现有 dataset 提交修订，过期回收每分钟保留；软配额强制周期复查，失败不确认缓存。
2. 核对聚合唤醒来源，只排除没有可运行工作的通知。保持真实新需求、输入修订、重试和断线轮询路径。
3. 固定报价回放记录 SQL、CPU、提交时延，再精简重复查询和事务内工作。实际日历、状态与消费者仍在当前事务读取。
4. 按证据决定是否继续调整其他历史/组合循环；不为目标数字盲目拉长轮询。
