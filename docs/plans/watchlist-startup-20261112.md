# 自选表首屏诊断（2026-11-12）

范围：Ubuntu 本机 mw-dev，真实五图工作区。以下先记录基线调查，认可后的执行和验收见后文。

## 证据

- 浏览器 probe.cjs / probe.json：5 张图 OHLC 在 3747ms 可见，13 行名称在 3966ms 可用；首批混合报价 4889ms 发出，34898ms 取消，约30秒无响应头；首行价格35045ms，全部13行35697ms。
- 当前自选13行：3组合、10平台。平台行会请求外部行情。
- 单独组合 HTTP 报价55–195ms（另一个启动中单请求500ms）。
- 图表库 `_startQuotesSubscription` 明确先调用 getQuotes，在成功回调内才调用 subscribeQuotes；慢首快照因此阻断自选实时订阅启动。超时后本地失败行回调释放此路径，订阅34896ms起陆续启动。
- 后端 quote_snapshot 对品种串行执行，并在最新价后同步查询昨收；整批完成才返回。
- 独立冷进程 backend-probe（非原浏览器请求逐段追踪）：BTCUSDT 最新价11.493s，昨收0.098s；EURUSD 最新价18.044s，昨收23.051s超时；下一OANDA品种最新价6.622s。65秒预算主动结束，无常驻调试器。
- 上游独立复测：EURUSD最新价5.186s，其中配额等待2.944s、HTTP1.788s（含代理TLS1.508s）；无优先级0修复任务，无冷却期。耗时存在波动，不能将冷进程耗时等同于原请求各阶段耗时。
- provider_chart quote=True 使用 history 配额，跨进程同源history并发1；平台M1与昨收D1竞争这一额度；进程内还有同源报价slot1、前端全局quotes在途1。直接提高并发可能增加外部流量与竞争。
- 浏览器无页面异常。列表偏好/目录请求约10–15ms，不构成30秒瓶颈。

## 建议顺序

1. 首次getQuotes用已有真实快照/名称及时回调一次，未有报价不填价格、涨跌或伪造时间；解除订阅启动依赖外部整批查询。后续逐行通过订阅更新。
2. 首快照采用本地缓存读取；缺失/过期由共享后台任务有界刷新。按品种/来源隔离等待，慢源不阻塞已就绪组合。保持身份、重置、切换工作区与取消边界。
3. 昨收及涨跌字段从最新价关键路径移出。以完整来源身份、报价口径、交易日缓存复用，日界线失效；缺失则先留空并异步补齐。
4. HTTP与实时订阅复用同品种在途工作，避免订阅后再强制整表外部刷新。保留限流并隔离本地读取和外部刷新，不通过简单扩大全局并发解决。

## 实施后的最小验收

- 重跑原13行、5图工作区浏览器脚本，比较首行/全部已就绪行报价时间及图表时间。
- 故意延迟一个平台源30秒，其余本地组合及时出价并持续接收真实实时更新。
- 昨收缺失不阻塞最新价；补齐后涨跌口径正确，失败/陈旧状态与时间真实。
- 快速切自选、图表、工作区及来源修订，旧响应不得覆盖新身份。
- 短时检查上游请求数与CPU，避免取消旧请求后仍积累外部刷新。

## 执行范围与最小检查

用户认可方案后执行。分类 F0：兼容的报价读取/显示更新，未改变 schema、历史持久格式、采集频率、告警计算或投递；昨收仅为显示补充字段。保持平台供源配额不变。

- 原生 getQuotes 首次仅异步返回已有真实快照/名称，一次回调即释放 subscribeQuotes 的启动依赖；订阅后通过 snapshot_only 本地读补齐组合/已提交平台报价。
- API 本地快照按完整 provider dataset 身份匹配已提交的共享报价任务，缺失时读取相同身份本地 ProviderBar；Yahoo 保持市场报价口径，禁止用 M1 冒充。旧值保留原始时间并标 stale，缺失为 pending，不发上游请求、不创建需求。
- 只有共享 worker 继续按原供源周期刷新实时平台报价；请求型 AKShare/Tencent 保留独立 HTTP 刷新。前端本地快照不占外部报价互斥通道。
- 共享 worker 外部平台报价最多占两个原有计算线程，另外两个保留给本地行情；昨收使用独立最多两任务、同源一任务、无排队的后台补齐，按完整身份/原生日界线与5分钟窗口复用，失败30秒后才允许重试。
- 自动回归：原生 getQuotes→subscribeQuotes 握手、慢外部请求期间组合逐行交付、替换/取消/修订围栏、本地首快照禁止上游 IO、身份隔离、陈旧时间真实性、昨收非阻塞与有界复用、本地计算任务保留槽位。
- Ubuntu R1：在已授权维护的持久开发 project `mw-dev` 上更新候选并测真实工作区；不额外创建数据库/端口，不复制用户数据。启动前只读资源检查：约7.9 GiB可用内存、18 GiB磁盘，现有开发服务占用可核实；本轮只替换应用镜像，额外运行时线程按需启动、无新数据库常驻开销。保留旧镜像、配置和启动器以便回退。
- 不查询或追踪 CI，不合并、打正式 tag 或发布生产。

## 首轮浏览器复测与持久缓存补充

候选 c2f03a57 部署后，五图 4.257s、首行4.468s、三组合最迟6.793s，冷平台最后一行24.303s；不将平台首次未有数据的外网等待误报为已消除。第二轮将包含平台的HTTP快照人为暂停30秒，三组合最迟7.065s、全部13行7.065s通过SSE显示，零页面错误，说明首快照不再阻塞订阅。

针对平台重启后再次冷读，进一步让 worker 单蜡烛报价使用现有 ProviderDataset/ProviderBar 的跨进程租约和持久缓存，与同身份图表/别名复用。仍只请求1条当前原生蜡烛，保留 history 上游配额，不为自选拉取历史区间，不启用旧独立采集器；REST-batch 的账户最新所有权继续走既有等待路径。相关回归验证一次取数可供别名复用，且下一次本地HTTP快照直接读到真实M1数据。
