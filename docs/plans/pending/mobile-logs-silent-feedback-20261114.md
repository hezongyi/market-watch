## 目标与现状依据

日常操作保持安静，用户遇到问题后从“更多 → 日志”回查，日志条目信息紧凑且足以排查。

当前 `MobileApp.tsx` 的 `report` 仅写入一个 message 字符串，由 `MobileToast.tsx` 挂到页面/顶层弹层；新消息覆盖旧消息，无持久操作历史。`notices.ts` 另有服务器事件前台提醒，自选还有独立提醒条。`RecordsSheet.tsx` 已有触发、异常/恢复、系统事件记录，但不覆盖全部手机操作。`shell.ts` 仍有 APK 桥接错误的原生 alert；App 还有独立网页更新横条。`api.ts` 已有有界且脱敏的请求诊断可复用，不能假定每条错误都已有请求关联或服务器追踪标识。

## 已确认的反馈规则

- 添加成功、分组保存、缓存失败、自动重连、后台刷新异常等写入日志，默认不弹窗、不发提示音/震动、不要求关闭；不新增“日志已记录”提示、红点或未读压力。
- 当前操作以原控件表达进度和实际结果：保存中、已保存、实时开关及真实短状态等。保存失败、名称校验、版本冲突等在相关控件旁简短说明，同时记日志；不能让写失败看起来成功。
- 关闭顶部结果浮窗不意味着删除必要确认、脏表单保护、会话失效登录引导、离线/缓存状态或来源差异核对；部分成功必须如实表达。就近反馈不遮挡操作、不插大卡片、不推动列表。
- 覆盖普通 MobileToast、服务器事件的前台浮窗/自选提醒条、网页更新横条及 APK 桥接原生 alert 的去向。更新发现写入日志，并通过更多的检查更新入口处理；协议不兼容等影响当前操作的错误在相关界面表达，不只隐藏到日志。
- 服务器事件前台改静默，不改服务器告警投递、后台通知和已处理语义；查日志/关闭提醒不自动标记告警已处理，不伪造送达、确认或实收。必要的展示去重与服务器回执语义须分别核查，不沿用弹窗已展示标记冒充业务处理。

## 更多入口与日志布局

- “更多”的“应用”分区新增“日志”，打开沿用现有动效、返回/关闭、主题的稳定大容量抽屉。已有“告警记录”保留告警查询与处理，相关日志提供跳转，不重复复制完整告警内容。
- 最新记录在前，日期适当分组；只提供“全部／异常”切换和关键词搜索。“异常”包含警告及错误；正常成功/恢复也可在全部中回查。不新增统计看板或多层筛选。
- 默认紧凑两行：第一行时间、结果/级别、动作；第二行对象、供应商、关键原因。用细分隔及文字层次，不做逐条大卡片，不为密度牺牲字号和触摸可达性。
- 点击展开详情，显示实际可获得的错误码、页面/模块、操作对象、脱敏接口路径、耗时、首次/最近发生时间、次数、App/网页版本及已有请求标识。未知值省略或标未知，不能生成看似真实的诊断数据；请求参数、标识等技术细节放展开层。
- 支持复制单条、导出脱敏日志，便于用户提供排查依据；导出时间包含时区。复制/导出结果用原按钮反馈，不重新引入浮窗。

示例，仅说明布局，不代表当前实际故障：

```text
14:32:08  失败  开启实时
XAUUSD · OANDA · 认证失败 · HTTP 401

14:31:46  成功  添加自选
NVDA · Yahoo · 分组：美股
```

## 采集、合并与存储

- 使用统一结构化记录入口，包含时间、级别、模块、动作、结果、摘要及有界上下文；逐调用点补来源和动作，不只将旧字符串原样堆进日志，也不靠解析中文文案猜测级别。
- 同一模块/对象/错误的连续重复合并，保留首次、最近、次数和最新原因；恢复记录与故障关联，能看清失败→重试→恢复。不同品种、操作或请求结果不能错误合并。
- 不逐条记录正常报价、心跳、轮询；连接只记录有意义的状态变化和异常/恢复。主动切页/改词取消请求不作为故障。避免把 API 错误、操作失败和事件上报重复写成多条相同故障。
- 本机持久保存最近7天且最多1000条，两个上限同时适用，写入/打开时有界清理；重启仍能查看，离线可读。采用现有手机数据库能力，按服务器和账号隔离，不复用其他账号记录。注销/切服务器沿用现有本地清理规则；预登录故障隔离为当前服务器匿名作用域，不混入其他用户历史。
- 写入异步且有界，不阻塞行情或操作；本机存储不可用时退到有界内存日志，并在日志页说明无法持久保存。不递归记录“记录日志失败”，不因配额故障刷屏。
- 白名单保存排查所需上下文，写入前脱敏，展示/复制/导出使用同一安全数据；不保存密码、Token、Cookie、CSRF、完整请求体/响应或带敏感参数的URL。普通日志不自动上传；已有服务器事件链按原职责运行。
