# 开启全部供应商源

状态：2026-11-14 Ubuntu 本任务实例六源已启用并读到真实样本；目录已核查。Yahoo 美股完整目录受分页限制，保留旧快照及准确代码补录；未更改生产。 见 [本轮验收记录](../../verification/mobile-completion-20261114/README.md)。下文保留原方案及历史实施边界，当前状态以本段和验收记录为准。

## 目标与范围

- 开启项目已支持的六个供应商源：OANDA、Binance、Yahoo Finance、Dukascopy、AKShare、FXCM。当前手机目录标签包含 OANDA Practice、FXCM Demo；沿用已有账户/环境口径，不擅自改成实盘账户。
- 实施先在 Ubuntu 本任务隔离验收实例完成；生产部署须有对应明确授权。保留现有凭据、代理和账户配置，不将私有配置提交仓库。
- “开启来源”不等于开启全部自建实时、自动订阅全部品种或触发全量历史下载；也不扩展尚不支持的自建实时接续来源。目前自建实时接续的 OANDA Practice 能力边界保持。

## 实施路径

1. 核查最新源码、各源开关与依赖、API及相关 worker 的实际有效配置，区分“已开启”“缺配置”“目录未同步”“读取失败”。没有独立开关的源核查接入路径是否可用，不凭 UI 能列出名称就认定开启。
2. 对有开关的来源启用对应配置，沿用私有凭据/网络设置；缺失账户或认证时明确记录缺口，不伪装可用。不在本次记录阶段读取或修改运行环境配置。
3. OANDA 保持 REST batch 的账户级 worker 归属，不能为“全部开启”误启旧 provider poller 造成重复采集。AKShare 等来源按各自目录探测与周期能力核查，不假定能力完全一致。
4. 更新必要目录并做有界样本验证；保留目录恢复与失败反馈。来源状态在手机端如实反映，不为显示正常隐藏错误。

## 验收与交付

- 六源分别记录实际开关/配置是否生效、目录可搜索情况、一个受支持品种/周期的有界真实读取结果。启用、目录同步、网络可读分别记录；失败明确原因，不以旧缓存或空成功代替。
- 核对 API 与相关 worker 配置一致，OANDA 没有重复采集；原有自建实时启停及历史维护计划未被批量改变。
- 当前已知 Dukascopy USDCAD 存在 TLS EOF 读取问题，需重新实测并如实记录，不能把“开启全部”当成已解决该故障。
- 按实际改动选择最小检查与 Ubuntu smoke，交付列出运行主机、地址、启动/停止入口和逐源结果。没有真实读取证据的源不能标为验收完成。
