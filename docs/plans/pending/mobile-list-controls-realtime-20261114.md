## 一、隐藏已加入与重复提交

确认口径：按入口分别排除，不交叉误伤。

- 自选添加搜索：排除当前账号**所有自选分组**已关注的同一真实品种；与此前“只按目标组判重”的规则相比，这是用户最新要求的变更。加入仍落手机当前组，“全部”落首组，无组创建默认组。
- 添加自建搜索：排除已登记为自建的**同供应商、同准确产品/账户口径**。代码相同的 OANDA 与 Dukascopy 不合并，现货/CFD 等不同真实产品不按显示名称合并。已有多个模式/复权/日界线配置保留，普通添加不再重复提供该原生产品；高级配置的新增不在本轮普通入口中处理。
- 两页各自按自身集合排除：原生已建为自建，不意味着它不能作为原生加入自选；原生已自选也不阻止创建自建。自建已存在时，仍可从自选搜索关注该自建。
- 自选自建结果按稳定 dataset 身份核对，不能只比较当前 MWH 版本或 MWC ticker：同一自建换了固定版本/接续身份后，不应重新出现在普通添加结果。用户已有显式固定版本/多个配置引用不自动迁移或删除；普通添加去重与高级引用的语义分别保留。
- 已归档仍视作已自建，不通过添加再造一份；恢复入口留在数据管理的归档列表。自选中的临时失联/缺数据品种仍算已关注，不能用状态异常绕过去重。
- 添加成功立即移出搜索结果，保留查询和滚动，按需要补足可视结果。服务端过滤后再分页，不能只在已加载25行中隐藏，防止空页、漏项和过早“已显示全部”。自选/自建集合更新后让相关搜索快照失效，旧离线快照不允许直接写入。
- 提交前读取最新集合、解析真实身份并复核；保留前端同步提交锁、偏好 revision/冲突保护、后端自建身份唯一约束和响应丢失核对。并发重复则定位/提示已存在，不再发送第二次创建或把失败显示成成功。不自动重试写入。
- 从某一组移除但别组仍持有：继续隐藏；从所有组移除后可重新搜索添加。跨组整理走“管理”中的移动功能，不通过添加搜索重复建关注；不静默搬走旧组成员。

实施核查：`DataPage.tsx`、`DataManagedPage.tsx`、`watchlists.ts`、`dataMarkets.ts`、`watchSymbolSearch.ts`、`DataCatalogSheet.tsx`；后端三个目录入口需支持同义的排除范围和有界批量身份映射，不能每行读取 continuation。`history_creation_check.py`、创建写路径的最终去重仍以真实 dataset identity 为准，不因 UI 产品级隐藏改变持久身份。不要假定现有 `addSymbol` 已经全局判重，它目前只防同组同 ticker。

## 二、分组抽屉的具体布局

- 标题栏从左至右：`自选分组`，右侧 `新建（FolderPlus）`、`管理（SlidersHorizontal）`、现有返回/关闭。三者均为无底框图标，图标约18–20px、触摸目标至少44px；不另加底部重复入口。
- 当前实际右上按钮是 X“关闭”，不是返回箭头。建议本轮保留这一退出语义；新建和重命名的编辑层才用“返回分组”，不顺便把所有页面的关闭图标改成箭头。
- 普通列表每行：分组图标、名称、轻量数量、重命名铅笔；选中仍有清晰选择状态。“全部自选”为系统聚合项，不提供重命名/删除；实际分组（包括默认组）可改名。
- 分组选择区域与铅笔是两个兄弟交互目标，不能把 Button 嵌进 RadioGroupItem/整行 button。点铅笔只编辑该行，无需先切换当前组；不触发选择或关闭。可访问名称包含组名。
- 点新建进入简短名称表单；点铅笔预填该组名，标题“重命名分组”。名称校验、保存中锁定、失败保留、并发冲突、离线禁写沿用。打开表单默认不主动弹系统键盘。
- 保存后返回分组列表并保留位置。重命名不改变当前选组；建议新建成功后选中新组便于随后添加，且不改桌面 active。取消/返回不保存，脏表单仍确认放弃。
- 管理入口保留品种/分组整理、排序/移除/删除组和原保存/取消；分组页不再重复提供常驻的新建输入和行内名称输入，重命名复用同一铅笔表单。为全局防重复补“移动到分组”，通过明确提交从原组移至目标，保留现有历史多组成员，不能为整理自动删关注。
- 删除组继续保留独有品种到未分组。退场完成后再交接编辑层/管理层，避免叠抽屉、丢焦点或截断动效。

实现接口：`MobileSheet.tsx` / `WatchOverlays.tsx` 当前标题栏只含关闭按钮，需增加可选 header actions 槽，仅相关抽屉传入；不复制整套 Drawer。保留 overlay/dirty/系统返回/主题/退出缓存内容的生命周期。

## 三、添加自建只保留搜索与结果

- 正常添加面板为标题、搜索框、三行品种结果、必要加载/空态/错误反馈；移除来源选择、类别选择和常驻目录操作区。源码当前没有独立叫“操作状态”的添加控件，最接近的是“目录筛选与更新”；实施以用户要简化的这段工具区为范围核对，不删除写入状态反馈。
- 代码/中文名/供应商/类别都能部分匹配，空白分词 AND、每词跨字段 OR、不限顺序，服务端先匹配再分页；沿用上一轮方案。例如 `xau oa`、`黄金 oa`、`外汇 oa`、`美股 yah`、`股票 yahoo`、`指数`。
- 类别由可靠 asset class / 目录市场字段及对应中英文别名匹配。股票、基金/ETF、指数、期货、金属/贵金属、外汇、加密等明确映射；“美股”必须有美国市场证据，不能只因供应商是 Yahoo 推断。无分类证据时不编造。
- 不自动把来源关键词变成保存的筛选状态，不新增搜索标签/chips。“未找到”提示可举一个代码+来源例子，不靠教程说明整个查询语言。
- 目录更新、来源认证和 Yahoo 准确代码补录是必要能力，移到既有“任务与来源/目录工具”，不把它们放在正常添加表单。目录缺失时给简短可达的更新入口，不能删掉唯一恢复路径；后台选择来源/更新市场不属于正常添加筛选。
- 网络/提交中/成功/错误反馈仍保留；“操作状态控件可删除”不等于隐藏失败或把准备中显示为可用。创建本身必要的能力核验、模式和维护设置不在本轮删除范围。

## 四、自选仅区分“自建是否开启实时”（表达建议待确认）

用户澄清：行情是否正常可看 sparkline，不需要上一版提议的逐品种青/灰/琥珀健康点。上一版实时新鲜度指示需求撤回，不实施。

sparkline 不能可靠表达实时开关：当前红绿表示当前交易窗口及涨跌，蓝色表示闭市/旧日回显，灰色与缓存/离线有关；实时开启遇到休市或尚无新数据也可呈蓝色，固定历史维护更新后也可能有当日曲线。不能把蓝色定义为关闭或红绿定义为开启，也不为开关改变现有曲线配色/几何/动态。

用户认为小闪电视觉焦点过重，不采用该建议。备选均复用第三行现有自建标识，不增加行高、固定列宽或挤压 sparkline，不加动画、健康点或醒目颜色，尚待用户选择：

- 推荐：关闭写“自建”，开启写“自建·实时”；沿用次要信息的灰色、小字号，不加独立底框、加粗或强调色。文字最明确，原有供应商仍保留。实施前需用长供应商名称、375px 与150%字号核查第三行容纳情况；不能通过扩大左列解决。
- 更省空间：两态都写“自建”，关闭为现有轻描边，开启用很淡的中性灰底；不加图标、不变宽。视觉更安静，但含义不如文字直接，且不能只依赖颜色，需有“该自建实时已开启/已关闭”的可访问说明及详情可查状态。

两者仅表达开关配置；准备中/休市仍为开启，不表示当前收到数据。实时状态未知时不得套用明确关闭样式。当前只记录备选，不把推荐视作用户已选定。

实现时读取后端真实 realtime_enabled / continuation.enabled，经现有引用解析映射到稳定 dataset；不能单凭 MWC/MWH 前缀、是否存在曲线、公共连接或价格跳动猜测。开启/关闭后通过现有变更事件刷新状态，不额外增加逐行轮询。未知不冒充关闭，离线旧状态标明缓存语义；明确选择的 MWH 固定版本仍保持固定历史，不因其父自建开关开启而偷偷换成 MWC 或给固定报价追加实时尾部。若展示父自建开关状态，说明中区分“该自建已开启实时”与“此引用仍为固定版本”。

## 五、已确认待实现：数据列表一键实时开关

每行右侧放紧凑 Switch，直接开启/关闭，无额外确认页或确认弹窗；左侧三行信息不变，点行主体仍进详情。开关与详情区域是兄弟节点，不能在当前整行 Button 里嵌另一个交互控件。

- 可直接开启：后端确认支持接续、所需固定历史基线可用、当前账户有已经核对且有效的默认映射（唯一有效映射可沿用后端默认），没有待确认产品差异、失效配置或歧义。开启后可先处于准备中，开启不等于已收到数据。
- 不具备条件：灰色禁用且旁边有短原因，如“待历史”“待配置”“不支持”“账户变更”；点行主体在详情处理。灰色 Switch 本身不假装可点；禁用原因也能通过辅助技术读到。
- 首次需要来源核对/接受产品差异的品种不自动确认。要真正做到列表直接开关，先在详情完成一次必要配置，此后无确认；不为了减少页面猜测黄金/白银的价格口径或来源映射。
- 正在运行的 enabled 开关保持可关闭，即便当前配置失效或来源故障；不把 can_enable 与 can_disable 混成一个条件，避免坏状态无法停。离线/提交中禁写，不因休市禁用已配置的开启能力。
- Switch 仅表达用户启停意图；运行中、准备中、闭市、异常由旁边一条短状态表达，不让 enabled=receiving。正常“关闭但可开”和“不满足条件禁用”视觉需可区分。
- 点击提交期间只锁定该行，保留列表/滚动，展示 pending；不先假报成功。失败回退/保留实际状态并给行内反馈，响应丢失先读回核对，不盲目再发写入。批量源状态刷新不覆盖该行正在提交的结果。
- 关闭影响历史身份下的接续/依赖告警，沿用现有后端行为。无确认的替代反馈为短通知“实时已关闭，历史保留”，需要恢复时用户显式再开；不自动恢复，不删除尾部缓存或历史。

代码证据：`DataManagedPage.tsx` 的 `toggleLive` 已直接调用 `/datasets/{id}/continuation`，无有效默认映射才进核对页；关闭当前有确认框。`managed_continuation.py` 已有 supported/ready_to_enable/default_mapping_id 与写端核验，但 `continuation_summaries.py` 当前列表只给 enabled/configured/status，**不足以凭 configured 渲染可用开关**。

实施应在现有摘要有界批量输出 can_enable/can_disable/disabled_reason/实际有效默认映射等必要信息，复用后端同一套资格规则与写端核验，不逐行调用完整 report 或创建实时需求。列表/详情共用命令语义，保留服务端并发与 first_use 事务；首次开启缺确认仍灰色。没有新增实时采集流程。

## 六、已确认待实现：数据主页保留最少的决策信息

当前主页为标题+添加搜索、列表内筛选框与工具、`自建行情 · N`、三行身份、状态 Badge、完整“数据至”时间和行尾箭头，另有分页；没有独立统计卡片。按已基本认可的方向：

- 保留标题和右上添加搜索；列表内“查找已有自建”的用途不同，数量较多时仍有价值，默认收成列表工具中的搜索图标或按需展开，而非两条常驻搜索框。
- 列表保留三行身份、实时开关和一个真正有决策价值的短状态。历史维护错误与实时开启不能互相遮盖：以异常优先，同时保留开关与其实际运行说明。
- `数据至`只显示确有意义的缺口/陈旧/任务进行中提示；正常完整日期和各周期范围移入详情。是否滞后按维护计划/来源时段判断，不能所有上日数据都当陈旧。
- 整行可进详情时，行尾箭头可去，避免同时挤开关、Badge、日期和箭头。同代码多配置的必要区分短标识保留。
- 不建议新增自建统计卡或实时/历史数量看板。现有 `自建行情 · N` 也不需单独占一行：移到标题旁低对比小数字，不再另占一行。数字只是轻量总量，筛选时需说明是结果数；它不构成额外后端全库计数要求。
- 来源/类别可用同一模糊查询；运行状态（待准备/异常/关闭等）是动态事实，不应偷偷作为普通名称子串处理。当前“需要处理/暂停/归档”工具对维护有用，建议只在管理工具保留，归档恢复入口尤其不能丢。用户若进一步决定移除主页筛选，仍需保留这些管理路径。
- “任务与来源”保留为次级工具，健康时不常驻通信记录或多个状态卡；异常时可给定向入口。主列表分页与无限滚动不是本轮新增要求，不顺便改动。
