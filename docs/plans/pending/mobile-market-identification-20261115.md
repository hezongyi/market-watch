## 3. 页面规则

| 位置 | 最终展示 | 必须保留 |
| --- | --- | --- |
| 添加自选 | 左上代码+一个分类标签，左下中文名；右上供应商，右下必要口径/合约/环境；右侧独立添加动作 | 原生自建合并、当前组添加、全局身份防重、成功留勾、重开排除、自动分页 |
| 添加自建 | 同一两行组件；右上实际来源，右下已知合约/环境 | 选择来源产品；不预先承诺最终复权、维护方式、实时能力 |
| 创建设置 | 顶部与刚选条目的内容及样式一致 | 历史起点、维护周期默认值、自动更新、更多设置、脏表单返回、校验与接口语义原样 |
| 数据主列表 | 两行：代码+分类；中文名+供应商；右侧已有实时开关 | 禁用条件、状态、点击详情；只在同名配置冲突时补必要区别 |
| 自选主列表及管理中的紧凑品种行 | 原三行、原尺寸；仅供应商文字统一 | 代码列/价格列宽、字号策略、行距、sparkline、报价精度、连接生命周期 |
| 品种详情、维护详情 | 复用统一名称与分类；完整代码、真实口径/环境按字段显示 | 已认可的品种级覆盖、维护信息与必要错误说明，不恢复复杂数据明细 |
| 告警/其他手机品种选择或摘要 | 统一来源名称；只有确实复用本次选择行时才采用两行组件 | 不顺带重排告警、图表、更多页面 |
| 手机日志 | 可读实际来源；详情保留通道及可追踪的原始标识 | 原错误语义、脱敏、容量/清理规则；不把旧日志改写成未经证实的新来源 |

右侧是次要信息，但具有身份意义的差异不能隐藏：同代码同来源不同复权、CFD、交割、永续、模拟/实盘，必须在可见行中区分。自建搜索保留轻量“自建”文字；同源同码自建冲突时按实际身份补 NY17/UTC0 等最少差异。

两行指两层信息，常规字号保持两行；150% 字号优先可读和完整辨认，必要时允许辅助文字换行，不能靠极小字体、重叠或裁掉关键合约信息来维持行数。长代码优先利用现有合法 display_symbol；仅有可靠结构化合约信息时可在左侧显示基础代码、右侧完整合约区别。完整代码保留在详情；不能随意裁剪原始代码制造歧义。

## 4. 分类与颜色

| 实际产品 | 主标签 | 色系 | 右侧必要区别 |
| --- | --- | --- | --- |
| 股票 | 深A、沪A、北A、港股、美股、日股等；地区未知用股票 | 蓝紫，同族复用 | 复权、来源；不能仅凭供应商判为美股 |
| 外汇 | 外汇 | 青绿 | bid/ask/mid、来源环境 |
| 贵金属 | 贵金属 | 柔和金色 | CFD 等真实产品形式 |
| 股票指数 | 股指 | 靛蓝 | CFD（如适用） |
| 非股票指数/细类不明的指数 | 指数 | 靛蓝 | 已知产品形式 |
| 期货（包括股指期货） | 期货 | 琥珀 | 主力连续/连续类型/具体合约月份 |
| 加密资产 | 加密 | 紫 | 现货/永续/交割日期 |
| ETF/普通基金 | ETF/基金，分开判断 | 蓝青 | 必要交易市场 |
| 债券/期权 | 债券/期权 | 灰蓝 | 必要期限/到期/看涨看跌/行权价等身份区别 |
| 已知商品类、不能归入上述类别 | 商品 | 琥珀 | CFD 等实际形式 |
| 缺少可靠分类 | 待分类；已有可靠细类名称则保留该名称 | 中性 | 不猜资产类型 |

- 优先实际产品形式，再考虑标的资产：指数期货标期货、指数 CFD 标股指/指数并显式带 CFD；ETF 不按挂牌地误标普通股票。
- metadata/identity/供应商已验证规则是依据；不从中文名或代码正则泛猜。不以一个 INDEX 类型就断定股票指数。
- 仅一个主标签着色；供应商、价格口径、合约区别均普通文字。同一分类在搜索、创建头部、数据列表颜色一致。
- 预览里的颜色转为手机主题语义 token，浅底深字、暗色独立对比度；不用涨跌红绿表示类别，不引入每个供应商一套色彩。
- 预览仅提供覆盖样本。债券、期权等真实目录没有产品时不添假数据、不接新供应商、不解锁创建或实时。

## 5. 来源展示与搜索

### 5.1 显示规则与事实来源

- 已确认 `sina-*` family → 新浪财经；`tencent-a`/`tencent-hk` → 腾讯财经；已确认东方财富 → 东方财富；未知 family → AKShare。
- 来源取实际价格系列的 identity 或最终生效的读取元数据。目录默认 family 不可覆盖已存系列的真实来源；不能将所有 eastmoney 条目直接改名新浪。现有创建路由的归一化语义保持，不因文案触发切源。
- 默认品种摘要只显示上游名；详情分别显示“行情来源：新浪财经”“采集通道：AKShare”。未知上游时显示 AKShare，不编造来源。
- 历史与实时来源不同：主列表沿用现有代表来源规则，详情分别标明历史来源和实时来源；不能丢掉箭头后的事实、不能只用历史来源覆盖实时日志。
- 自选固定列可容纳新浪财经/腾讯财经，不附加“（AKShare）”；更长的其他源按现有布局溢出策略处理，可在详情查看全称，不压缩 sparkline。
- AKShare 同步、目录刷新、启停等是通道操作。保留一个 AKShare 入口，并以“采集通道”等恰当标签说明；不能虚构独立新浪/腾讯启停、复制通道统计或拆后台配置。

### 5.2 搜索规则

- 简称、全称、英文和通道别名：新浪/新浪财经/sina，腾讯/腾讯财经/tencent，AKShare；东方财富/eastmoney 如实际存在同样支持。
- 搜新浪只匹配新浪实际上游，不能因为底层均为 AKShare 就同时返回腾讯；搜 AKShare 可以匹配其全部真实上游。
- 支持代码、中文、分类、交易市场、合约形式与来源组合，如 `300750 新浪`、`宁德 腾讯财经`、`期货 新浪`、`比特币 永续`、`xau oa`。
- 仍为空白分词 AND、单词跨字段 OR；匹配和排除在服务端分页前执行。禁止只筛当前页或把全部目录拉到手机再筛。
- 针对 native、history-catalog、managed 三条搜索路径验证同义词；不把供应商别名一律加进 PROVIDERS 的 `akshare` 值中导致上游混淆。
- 不改变去重键、cursor、retained、默认分组、账户隔离和旧请求取消；避免逐条补请求和全表重复 JSON 变换。新增别名优先复用现有索引/已知 family 条件。
