# Advanced Charts 告警系统设计方案

日期：2026-10-06。状态：用户已确认核心需求，并已明确授权在隔离 worktree 中接续开发、真实验收后交付。本文仍是设计及验收合同，不表示功能已完成或上线；实施状态见 [接续开发记录](chart-alerts-implementation-progress-20261006.md)。生产发布及真实通知外发需另行明确授权。

## 1. 目标与确认范围

Advanced Charts 是创建、编辑和查看告警的主要入口。后台持久监控，关闭网页后继续运行；沿用现有行情、PostgreSQL、worker 和通知链路。

| 项目 | 已确认决定 |
| --- | --- |
| 条件范围 | 价格、价格区间、画线突破、指标；矩形告警暂不做 |
| 行情 | 默认使用发起操作图表的行情来源；可显式调整为后台支持的来源 |
| 判定 | 收盘确认、盘中触发都支持，默认收盘；具体组合按能力开放 |
| 次数 | 仅一次 / 多次；多次可选 2 或 3 次，默认 2 次；默认创建模式仍为仅一次 |
| 多次语义 | 条件解除后再次成立，才计为下一次；达到上限自动停止。持续满足不会定时产生新信号 |
| 首批指标 | SMA、EMA、RSI、MACD；价格与指标交叉、指标与常数比较、兼容输出之间交叉 |
| 创建基准 | 创建时条件已成立不立即触发，建立基准后等待新的满足事件 |
| 画线更新 | 拖动后提交，成功后新条件生效；明确删除关联画线时暂停告警 |
| 指标参数 | 保存参数快照；图表参数变化时提示更新，首期不自动修改告警 |

后文标为“建议”的细节是为形成可审阅方案而给出的设计默认值，并非每项都已单独获得用户确认。尚待技术验证的能力不能显示为已支持。

不纳入首期：矩形告警、任意原生指标、任意脚本执行、多条件组合、涨跌幅条件、自动交易、新增邮件/短信/Webhook、无限持续触发、条件持续满足时定时重复产生信号。价格区间不因排除矩形而取消。已有回落突破、前日高低点规则保留。

6. 平台的部分“报价”入口读取当前 M1 数据，不等于完整逐 tick 报价流。

## 3. 交互设计

### 3.1 创建与编辑

工具栏、价格右键、画线/指标右键和侧栏加号打开同一表单。价格轴加号作为候选入口，须验证本地许可库及多图行为后开放。

表单按以下顺序呈现：

1. 品种与行情：来源、系列、价格口径；默认继承发起操作的图表。
2. 条件：对象 + 关系 + 比较目标。
3. 判定：收盘确认 / 盘中观察；显示固定判定周期。
4. 触发：仅一次 / 多次；多次选择 2 或 3 次。
5. 到期：快捷选项和自定义日期，显示时区；建议默认不限。
6. 消息、通知：主表单显示摘要，进入子页配置。
7. 取消、创建告警/保存。

消息与通知子页的“应用”只修改草稿，最终创建/保存才提交后台。取消或提交失败保留可恢复的输入。提交成功返回实际生效版本、时间和运行健康状态，不能把“保存成功、等待数据”显示成“已正常监控”。

条件示例：

| 对象 | 关系 | 比较目标 |
| --- | --- | --- |
| 价格 | 上穿 | 1.12061 |
| 价格 | 进入价格区间 | 下限、上限 |
| 价格 | 下穿 | 关联趋势线 |
| RSI(14).value | 上穿 | 70 |
| SMA(10).value | 上穿 | SMA(20).value |
| MACD.macd | 上穿 | MACD.signal |

菜单优先显示穿过、上穿、下穿，更多比较条件按需展开。后台校验单位与输出兼容性，例如不能直接比较价格和 RSI。

多图上下文在发起时固定：工作区身份、图表实例身份/代次、系列、周期、目标对象。异步返回不能重新读取当前活动图并将结果应用到另一图。桥接消息校验来源、窗口、结构和请求身份；鉴权及写入仍由父页面承担。

### 3.2 右侧面板

采用“告警 / 日志”两个标签。

- 告警：名称、条件摘要、来源、周期、运行状态、已触发次数/上限、最近触发；支持创建、编辑、暂停、恢复、复制和删除。
- 日志：每次触发的事件时间、检测时间、实际数值、阈值、规则版本、迟到标记、通知状态；支持定位图表、查看证据和确认通知。
- 首期筛选：文本搜索、当前品种、运行状态；日志默认按触发时间倒序。
- 数据等待、陈旧、失败必须以文字显示，不能只靠颜色；抽样报价显示实际观测口径和最近数据时间。
- 图上提供关联条件和触发位置；原生 marks 当前关闭，需选择并验证公开标记或绘图接口，不宣称已有能力。

原有独立页面与新面板使用同一后台事实来源。复杂排序、自定义列、预设、CSV、批量重启等后续再排期。

## 4. 行情身份与能力

规则保存规范化的来源、平台品种身份、managed/provider 系列、价格口径、周期、交易日历/对齐版本及适用的复权方式。显示名称、临时图表对象 ID、历史窗口身份不能作为后台行情身份。

保存后切换图表品种、来源或周期不修改告警。显式修改规则来源时生成新版本，校验目标来源的价格、日历、指标与几何，重新建立基准；保留旧事件。

能力查询按“来源 × 系列 × 品种 × 周期 × 条件类型 × 判定模式”返回可用性及原因。前端据此展示，后台在写入时再次校验。

| 能力 | 设计目标 | 开放前要求 |
| --- | --- | --- |
| managed 收盘 | 复用现有完整 K 线与聚合 | 补齐所选周期的完整性及日历合同 |
| provider 收盘 | 复用平台原生周期行情 | 持久需求、收盘确认、缺口及修订处理 |
| 价格盘中 | 按实际观察值判定 | 明确抽样频率、时间戳、口径及陈旧门槛 |
| 指标盘中 | 对当前未收盘样本计算 | 统一临时状态、预热及重绘语义后开放 |
| Yahoo | 按来源实际周期和延迟开放 | 显示延迟、交易时段及复权限制 |
| MT4 | 未来来源 Adapter | 只读探针不等于持续运行支持，不提前开放 |

收盘确认不等于墙钟刚过周期边界；需数据完整及来源确认。正常闭市与数据中断分别处理。

## 5. 条件与次数语义

### 5.1 基本比较

建议使用严格突破：上穿为前差值 ≤ 0、本差值 > 0；下穿为前差值 ≥ 0、本差值 < 0。差值来自两个同时刻兼容值：价格与常数、价格与动态线值，或两个指标输出。

价格区间建议使用闭区间 `[下限, 上限]`：进入为外→内，离开为内→外；上破上沿和下破下沿分别按边界穿越判断。一次观察由下方跳到上方，不推测中间出现过区间内报价；可以构成上沿突破，不能声称观察到了进入。

高于/低于是状态条件，首次由不满足变成满足才产生事件。创建时已满足只建立基准。价格触及与穿越不能混用；首期不以旧 `touch` 字段冒充完整触价规则。

### 5.2 有限多次

- `max_triggers` 为 1、2、3；选择“多次”时默认 2。
- 新的有效触发事件才增加次数；发送重试、设备重复响铃、页面重复请求不增加。
- 定向上穿后，必须观察到差值恢复至 ≤ 0，下一次上穿才有效；下穿镜像处理。
- 双向“穿过”按每次有效方向转换计数，反向穿越也是下一次事件。等于边界的处理按上述比较规则固定，避免沿用一句泛化“解除”而产生歧义。
- 进入区间须先离开才能再次进入；离开区间须先进入才能再次离开。
- 收盘规则在完整收盘样本之间计数；盘中规则在实际观察样本之间计数。盘中同根 K 线可能出现多次有效往返，首期如需“每根最多一次”，必须作为独立频率策略明确配置，不能默加改变已确认语义。
- 达到上限后监控完成，已产生通知继续按自身生命周期处理。

### 5.3 基准、生效与恢复

创建、明确重新启用、改变条件时建立比较基准；历史只用于预热，不补发启用之前的事件。收盘模式以生效前最后完整样本建立基准，生效后才收盘的完整 K 线可以参与判定；盘中模式只采用足够新鲜且有效的基准，否则等待首个有效样本。

建议：暂停/恢复及普通编辑保留累计次数；已完成规则通过明确“重新启用”建立新一轮运行并重置本轮次数，旧事件保留。降低次数上限至已触发数或以下时显示完成结果。复制生成新规则草稿，经保存才运行。

区分用户暂停与数据等待：用户暂停期间不补发；数据中断期间，收盘样本补齐后按顺序恢复，事件标记迟到。迟到通知的投递策略建议单独配置，不能让大量过时事件无提示地响铃。盘中缺失路径不能由 OHLC 推测重建。

历史修订保留证据版本，重建受影响运行状态但不自动重发相同历史事件。无法安全重建时显示等待处理，不静默沿用不一致状态。

## 6. 画线与指标

### 6.1 画线

建议首批覆盖水平线、水平射线、趋势线、射线；通道后续考虑。水平射线及斜线必须保存有效范围/延伸方向。

后台保存几何快照、判定周期、线性/对数坐标方式及版本，并保存稳定业务关联身份。临时原生 shape ID 只用于当前图表映射。

拖动中预览，结束时提交期望版本；成功后切换新规则版本并建立基准，位置修改本身不构成行情穿越。提交期间旧版仍运行，旧版触发事件准确记录旧条件。失败保留旧生效条件并提供重试/恢复；超时先查询提交结果，不能盲目回滚。连续快速拖动防止旧响应覆盖新结果。

明确删除关联画线暂停规则。布局加载、图表销毁、切换品种导致暂时找不到对象，不视为用户删除。建议复制工作区不自动复制活跃告警；撤销/重做作为新的编辑提交，不自动恢复已经暂停的监控。页面刷新从后台版本核对图上状态，告警保存不依赖布局自动保存。

斜线不得直接用墙钟时间插值代替原生几何。实现前验证端点与 K 线序号映射、周末/停盘、缺口、未来端点、延伸范围、对数价格轴及周期变化。图上与后台阈值不一致的组合不能开放；斜线仍属于目标范围，不因验证难度而静默删除。

### 6.2 指标

复用指标任务的算法定义与纯计算，图表显示和告警各自保留 Adapter。规则快照保存算法身份/版本、规范化参数、输出 key、数据系列、周期及计算历史合同；原生 study 实例 ID 不充当算法 ID。

SMA、EMA、RSI、MACD 逐个对照。统一历史起点、预热、缺口分段、数据修订与计算精度；递归指标不能仅因使用相同 TA-Lib 函数就宣称一致。图上显示的舍入值不用于后台判定。

盘中计算使用已确认历史加当前临时 K 线，不重复推进递归状态；收盘才提交对应确认状态。临时值变化不撤销已发生的盘中信号，但日志保留当时数值。当前只接受完整 K 线的显示计算路径需适配后才能声称盘中指标可用。

修改图表指标参数只提示快照不同，经用户保存后更新告警。建议移除指标显示也不删除后台快照告警，面板显示关联已移除并允许重新定位/关联。任意原生指标仅在存在明确计算映射并通过数值验证后开放。

## 7. 后台 Module 与数据模型

延续单仓库、PostgreSQL 和 worker，不引入新的消息平台或独立计算服务。

| Module | 职责 |
| --- | --- |
| 告警管理 | 校验能力、创建/编辑、生命周期、版本冲突及幂等写入 |
| 行情编排 | 持久需求、共享采集、完整性、新鲜度、顺序与修订 |
| 条件判定 | 接收规则快照、状态、观察值，返回新状态和可解释事件；无网络/通知副作用 |
| 指标计算 | 规范化输入、纯算法与输出；复用图表计算能力 |
| 通知 | 复用 Outbox、发送、回执和确认，接收明确事件 |
| 图表 Adapter | 读取上下文、对象映射、编辑提交和展示，不承担持续判定 |

内部语义模型建议为：

- 告警：稳定身份、用户配置及当前生命周期。
- 规则版本：不可变条件、行情身份和生效时间。
- 运行轮次：启用时间、累计次数、上限、检查点与判定状态。
- 图表关联：工作区/图表业务身份、关联对象、几何或指标快照。
- 触发事件：事件 ID、规则版本、运行轮次、方向、观察身份、触发时证据。
- 通知及投递记录：沿用现有模型，关联事件而不是泛化地关联告警。

这是语义划分，物理表拆分在实施设计时确定。旧 `watch_id` 单信号唯一约束改为每次逻辑事件的幂等约束；可使用运行轮次、规则版本、稳定观察序号和条件事件身份组合。不能只用时间戳，也不能把数据修订号作为重发同一历史事件的理由。

判定检查点、累计次数、事件、通知及 Outbox 在同一事务提交；并发 worker 通过锁或租约串行推进同一运行。外部投递采用至少一次与通知 ID 去重，不承诺端到端恰好一次。

生命周期建议为 active / paused / completed / expired / archived；数据健康独立表示 warming / ready / stale / blocked / error。active 且数据等待时必须显示原因，不能伪装成正常运行。

## 8. 持久行情需求和通知

活跃告警持有独立于浏览器的持久需求。浏览器兴趣和告警需求可以合并采集，但生命周期分别管理；worker 重启从数据库重建需求，缓存清理保护活跃告警必要的历史及预热数据。

同来源/系列/品种/周期共享采集；同算法/参数/输入版本共享计算。最新采集与远历史请求分配资源预算，避免图表历史加载拖延监控。数据陈旧门槛按来源和交易时段确定。

通知复用现有网页和 ntfy。明确区分发送服务接受、设备接收和用户确认。确认某事件只停止该事件后续投递；暂停告警停止新事件。已有原生手机响铃无法被后台保证远程停止的限制继续保留。

自动消息包含品种、来源、周期、条件、实际值、事件时间及延迟信息。可编辑正文和使用有限占位符；指标通知分开展示指标值与市场价格，不能继续把所有阈值都标为“价格”。

## 9. 交付阶段与验收

1. **合同与探针**：核对最终集成基线；验证右键/对象事件、多图身份、斜线几何、指标数值及来源能力。先暴露难点，不把探针当正式能力。
2. **完整基础链路**：规则版本、有限次数、持久需求、价格/区间/水平线、创建编辑、侧栏/日志、通知证据与迁移。
3. **斜线及指标**：交付通过一致性验证的趋势线/射线及 SMA、EMA、RSI、MACD；收盘/盘中按能力矩阵验收。分阶段不改变总目标范围。
4. **恢复与兼容**：旧规则/事件迁移、重启与并发、多图/布局恢复、数据修订、通知回归，形成完整验收记录。

必要验收：

| 场景 | 预期 |
| --- | --- |
| 单次、2 次、3 次 | 仅有效新事件增加计数，达到上限停止 |
| 条件持续满足 | 不周期性新增信号；通知重试不增加次数 |
| 边界与往返 | 等号、双向穿越、区间跳空、同根盘中往返按合同执行 |
