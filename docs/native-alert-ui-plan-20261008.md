## 组件复用策略

优先级：公开原生组件/API → 固定版本原生组件适配 → 确实无法复用的最小自有内容。逐项记录实际来源，不把库内 CSS 类名套到自有控件视为完整原生复用。

### 第一步：真实侧栏和窗口可行性验证

使用当前私有库在 Ubuntu 隔离环境做最小验证：

1. 在现有右侧工具栏加入警报入口；使用独立告警页，不占用或伪装成自选、对象树、数据窗口。
2. 原生侧栏负责页签选中、页面切换、宽度拖动、折叠和图表可用宽度。验证多图、全屏、主题、重载与工作区切换。
3. 验证原生窗口外壳、标题栏/关闭按钮及基础菜单控件可否独立使用；不能预先承诺所有表单控件都是原生组件。
4. 形成复用清单和实际截图，明确哪些已成功、哪些不具备稳定挂载方式。

已通过的候选是为原生侧栏注册业务内容的 renderer/adapter，沿用其布局机制。探针经 `widget.widgetbar()` 返回对象上的内部 `_widgetbar` 取得侧栏，等待原始构造器配置完成，为 `widgetConfig.alerts.ctor` 提供内容构造器，并在布局状态中增加独立 alerts 页后重建侧栏。这个入口不是公开 API；正式实现须集中封装、检测版本与契约并管理销毁/重建。避免用覆盖层假装停靠或占用原有页面。

此次验证通过运行时适配完成，未修改 ZIP、库文件或压缩 bundle；正式方案优先延续这一方式。完整应用里的既有页状态恢复、跨域 API 桥接及多图切换仍须集成验证。

若需构建期补丁，集中在独立适配脚本：校验输入版本与锚点唯一性、支持重复构建、失配明确失败；保证资源内容变化进入缓存版本计算。不能提交许可库本体。

### 第二步：告警面板

- 右侧原生入口打开同一告警页；顶部为“警报 / 日志”分段标签。
- 工具行放创建、搜索、排序、更多；窄侧栏避免常驻大表单筛选。
- 列表默认显示名称/条件、品种、状态和必要的异常。次数、周期、来源、最近触发等进入提示或详情。
- 暂停、编辑、删除等行操作在悬停或键盘聚焦时出现；触摸环境提供可见的更多入口。
- 运行受阻、等待数据等状态仍清楚表达，不能因精简界面把未运行显示为运行正常。
- 原有定位、复制、画线恢复/重试等能力放入行菜单或详情，保留可达性。
- 日志按事件日期分组，详情承载触发数值、规则版本、迟到信息、通知状态与证据。

### 第三步：创建和编辑

- 标题栏包含创建/编辑、品种和关闭；主要内容采用参考图的两列布局。
- 条件对象、关系和比较目标排列紧凑；指标/区间/画线按所选类型展开。
- 触发次数、到期、消息、通知采用摘要行；消息与通知分别进入独立子页，返回时保持草稿。
- 消息子页容纳告警名称、正文与占位符；通知子页仅展示实际可用通道。
- 行情来源、判定周期/方式必须可辨识、可按既有能力调整。组合行情接缝策略等必要业务选项放在合适的高级区域，不能因截图没有而删除。
- 使用既有仅一次/有限多次语义；截图“每次”不能悄悄变成无限触发。
- 到期展示本地时区与快捷选择；不限默认值沿用既有语义。
- 创建/保存、取消、编辑删除的位置参照截图；忙碌、错误、冲突和不可用来源均有明确反馈。
- 子页应用只修改草稿；最终保存提交后台。取消子页应还原子页进入时的值，失败保留输入。

### 第四步：桥接与状态组织

告警规则、生命周期、判定 worker 和通知沿用现有实现。UI 控件不直接承担后台计算。

若内容迁入图表域，需显式设计界面状态和父页面 API 的消息边界：父页面继续鉴权/请求，图表域发送经过白名单校验的业务意图；不向图表 iframe 复制登录凭据。所有消息验证来源、窗口、通道、请求身份及工作区/图表代次。

避免同时维护父页面和图表域两份告警草稿。页面切换、主题切换、图表销毁和请求晚到时，应清理订阅、保留正确草稿、丢弃过时代次响应。侧栏筛选“当前品种”需跟随当前活动图，而创建草稿继续固定发起时上下文。
