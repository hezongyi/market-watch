## 1. 问题、目标与边界

目前专业图表的父页面、iframe、图表数据中心、图表告警面板分别维护通知位置、时效和状态；普通故障消失后难以回查，事件、网页、声音、ntfy 接受和设备回执也没有统一时间线。目标是围绕专业图表统一接收与查询、一个即时提示入口、可解释的详情，以及互不覆盖的渠道记录。

用户于 2026-10-18 明确：**专业图表是通知主入口和主动来源；原守望主页的告警、通知逐步退役。**本轮不建设“旧主页 + 专业图表”两套并行通知产品，也不把旧主页信号全量接入作为统一完成标准。通知 Module 位于应用根部是为了认证与恢复生命周期，产品入口和领域仍以专业图表为中心。

正常状态优先复用 TradingView 顶部既有通知/告警入口；确无可用入口时，通过公共按钮能力增加同高度入口。通知中心位于原生侧栏/外壳，最多一个锚定气泡，不改变图表高度。启动中、初始化失败或原生外壳不可用时，由可信父页面提供入口或就地错误区；也不在四角堆叠全局浮层。

允许修改专业图表通知接收、投影、查询/变更流、网页观察和声音调度，以及可信父页面/iframe/图表数据中心 Adapter；旧主页仅修改必要的退役、历史与手机兼容接缝。不改告警判定、Python 指标、行情与组合计算语义，不改 TradingView 许可库源码，不重做手机客户端，不增加系统通知、邮件、短信或 Webhook，不涉及交易执行。生产发布、正式 tag、Unraid 切换、破坏性迁移和生产删除不在本次范围内。

## 2. 已有事实与 W0 待测项

以下六项为原评审已经验证、且本轮源码核查仍成立的事实；原测试结果仅证明当时现状。

- `advanced-host/chart-notices.js` 的内存记录按错误文本合并，最多展示三条；无法作为持久事件身份或跨刷新消费记录。

- 旧 `/notifications/{id}/ack`、ntfy 操作和 Android 确认会设置 `ack_at`、停止后续投递；不能直接用作新网页已读动作。
- 评审时专项测试为 **29 passed、1 skipped**；跳过独立 PostgreSQL 精度项。既有浏览器证据为 web-only，无外部 Outbox，不能替代新方案的跨渠道 R2 验收。

## 3. 通知 Module 的 Interface

专业图表生产者只提交结构化发生事实；通知 Module 集中提供可靠接收、变更读取和消费观察。图表外壳和父页面负责呈现，声音负责有条件消费，手机 Adapter 读取既有投递证据；旧主页只保留退役兼容接缝。生产者不分别维护分组、持久重试、响铃去重或新旧页面状态。

应用根部只持有一个当前主体的 Module；认证主体由服务端推导。客户端维护会话代次用于拒绝退出/失效后返回的异步结果，不能用会话代次替换事件身份或变更游标。会话失效时先暂停上传、观察和声音，再沿用现有草稿保存及登录回跳；同主体重新认证后幂等续传，其他主体不能读取或上传前一主体记录。认证前故障只有明确标注的本机状态，不伪装成已接受的服务器事件。

| 对象 | 必要合同 |
| --- | --- |
| 事件 | `schema_version`、稳定 `event_id`、认证主体、`source_kind/source_id/source_version`、发生类型/故障码、严重级别、标题/摘要、上下文、关联 ID、证据引用、动作描述 |
| 身份 | 后端事件以稳定来源键唯一映射；浏览器由可信父页面在本地保存前分配事件 ID，服务端在认证主体和浏览器来源命名空间内幂等接受并沿用；不能伪造服务器告警或渠道回执 |
| 分组 | `dedupe_key` 为稳定故障分类上下文，`incident_id` 为一次事故，`event_id` 为一次发生；传输重试不生成新发生 |
| 变更 | 独立 `stream_epoch/change_seq`、事件/组/渠道版本、变更类型和负载；事件 ID、时间戳和请求 generation 都不能替代变更游标 |
| 渠道观察 | `observation_id`、事件/渠道、观察主体、页面/浏览器/设备上下文、观察种类与结果、客户端报告时间、服务器接收时间；主体和允许的观察种类由服务端验证 |
| 时间 | 原始发生时间、服务器记录/投影时间、网页收到/渲染/查看/处理时间、声音尝试/开始时间、服务接受和设备回执分别保存；缺失为未知，不补造 |
| 图表来源上下文 | 适用时保留 workspace、图格、series/provider、品种/周期、参数摘要、源 attempt ID、epoch/generation、输入/计算指纹、可见范围与原因码；上下文栅栏只校验有效性，不充当持久游标 |
| 来源归属 | 服务端依据图表告警关联/可靠来源/受控浏览器上下文确定 `source_domain`；`pro_chart` 与 `legacy_watch/legacy_unknown` 分开，浏览器不能通过自报字段伪造业务告警归属或渠道回执 |

UTC epoch 为存储基准，详情同时显示 UTC 和用户本地时区。客户端时间仅为报告，不作为全局顺序；服务端接收时间不能冒充客户端发生或渲染时间。告警详情保留实际值、阈值、规则版本、数据时间、图表代次和原始证据引用；非告警没有的字段明确不适用。

指标/快照来源优先使用 #74 已有 `calculation.visible_complete/coverage/input_evidence/execution` 等事实描述，区分可见完成与后台任务状态。短期 snapshot ID 仅作关联；必要的当时证据在接受时冻结，敏感凭据与完整行情数组不进入 16 KiB 通知负载。证据超出大小预算时通过原权限下的持久引用读取；证据不存在或不可访问时显示未知/不可用，不重新计算并冒称原证据。

拟议 HTTP Interface 为：`/api/notification-center/events` 的浏览器接收/分页，`events/{id}` 详情，`observations` 的幂等消费观察，以及 `changes` JSON 补拉和 `stream` SSE。网页已读/处理通过新观察动作记录；显式停止手机提醒继续调用原停止接口。路由最终名称在 W1 冻结，以上身份、可靠性和兼容语义不得随命名改变。

## 4. 可靠来源与持久接收

### 4.1 后端来源与投影隔离

采用“可靠源变更记录 + 异步投影”，不在告警判定或行情处理事务内同步调用投影器、网页或手机新渠道。优先复用既有 `Audit` 记录专用来源变更，在源状态事务内追加最小的来源键、版本、变更种类和不可被后续状态覆盖的必要事实；发送尝试和设备回执关联其既有可靠记录。源事务仍遵循原有提交/重试规则，投影表、投影 worker 或前端故障不阻止源事务提交。

W1 冻结来源白名单和来源版本：专业图表业务告警、关联发送尝试/停止与设备回执、明确纳入的图表操作/任务终态。先判定来源归属，再决定投影/查询/提示资格；不能因为旧信号共用 `SignalRow/Notification` 或同一 Audit 流而全量吸收旧主页来源。指标需求 heartbeat/release、行情 tick、轮询、快照续约和通知观察不默认投影为新发生；通知自身派生 Audit 不再次作为来源。一个源错误被后端和浏览器分别观察时，沿用关联来源/attempt ID 记录表现，不按错误文本生成两条独立告警。支持先本机接收、后关联服务器事实，不能丢弃已真实接收的浏览器观察。

投影器读取**已提交且尚无处理凭据**的来源变更，不能按 `Audit.id > last_seen` 丢弃后来才提交的小 ID。处理凭据以来源记录唯一键去重，和事件投影、变更日志在同一投影事务提交。进程在任一步退出后可重新领取；成功凭据防止重复计数，原始来源键防止重复事件。通知投影的重建不再次调用告警判定或手机投递。

每个来源/渠道版本只推进对应当前状态；晚处理的旧版本可以补入时间线，不能覆盖较新的状态。详情保留发送失败/未知、成功接受和之后停止等独立事实，不能用最终状态抹去先前证据。

回填仅覆盖 W0 固定的来源和留存范围，标为 `backfill`、禁止即时气泡/声音/重新投递。旧版没有存储的网页显示、声音、设备回执及瞬时状态一律未知。来源日志与处理凭据成对管理：未处理来源不得因普通留存到期丢弃，凭据不得早于仍可能重放的来源删除。

### 4.2 浏览器来源

可信父页面负责生成/校验 ID、去除敏感内容、写入 IndexedDB 待同步记录并立即呈现，接收不等待 widget ready 或服务器响应。离线保留同一事件 ID，重连指数退避加抖动补传；服务端以身份/来源键唯一接收，相同 ID 与不同负载冲突时明确拒绝。服务端确认持久接收后才移除本地待同步项；响应丢失后重复上报不多算一次。

在真实失败尝试/有效状态转换的入口分配发生身份。React render、effect 重放、轮询快照、同消息重传不能重新分配；新的实际失败尝试即使文本完全相同也必须保留。恢复和关闭事故需要相同业务对象及当前有效上下文的成功证据；错误文本消失、组件卸载或消费者释放不等于恢复。历史/指标重试沿用现有 epoch、消费者、snapshot 和参数校验，不能借通知动作恢复已取消需求。

界面区分“已保存到服务端”“仅本机待同步”“未能保存”。存储不可用、容量或期限到达时即时说明未保存数量/时间范围；不能静默声称记录完整，也不能伪造丢失事件的逐次明细。重要事件的持久承诺以成功接收和约定留存期为界。通知上报自身失败只更新一个有界传输状态，不递归生成通知。

本地数据按认证主体隔离；退出/切换账号后停止原主体上传与播放，不把其数据发给下一主体；共享记录随保留期限处理。iframe 无认证凭据，只能通过检查 origin、window、channel、session 和工作区上下文的父页面窄接口提交。原始证据引用受原授权约束，浏览器消息为文本，写入本地前已脱敏。

## 5. 变更游标、历史分页与恢复

### 5.1 提交顺序

事件创建、渠道更新、查看/处理、故障分组计数和保留期删除都产生持久变更。初版投影发布通过数据库中同一流计数行的事务锁串行推进：在锁内分配 `change_seq`、更新投影、追加变更和处理凭据，提交后释放。后续发布不能越过尚未提交的发布事务；回滚不留下被客户端误认为安全的进度。单个投影批次有上限，吞吐由 W0 取样。

`stream_epoch` 标识可重放日志代次；普通重连不换代。重建或日志不再兼容时明确换代并要求客户端重建，不复用旧游标。来源 Audit 的 ID 只用于来源去重，不能冒充此提交顺序。

### 5.2 首次加载与补拉

1. 初始请求取得已提交高水位 `H` 与 epoch；历史页限定 `first_published_seq <= H`，使用不可变的时间/事件 ID 组合键分页，组列表也使用稳定键。历史 `before` 游标与实时 `after` 游标分别编码，绑定查询条件与权限范围。
2. 同时缓冲并补拉 `seq > H` 的变更，合并每条记录版本。分页过程中较新状态可能已可读，版本检查负责丢弃倒退更新；这里承诺最终收敛，不冒充跨 HTTP 请求的历史时点数据库快照。
3. 授权范围内的变更流包含记录进入/离开当前筛选所需的信息；可变状态和关键词由消费层重新匹配，匹配转为不匹配时移除，不能由服务端只推送“目前仍匹配”的新行。切换条件新建分页基线。
4. SSE `Last-Event-ID` 和显式 `after` 使用同一 `(epoch, seq)` 合同，增量轮询重用同一读取逻辑。允许至少一次传输；客户端按身份/版本幂等应用，持久化状态及接收进度后再推进游标。

客户端不可把“已补拉”当成“已渲染、已读或已播放”。过期游标、epoch 不匹配或留存缺口返回明确 reset/重建指令（JSON 采用可识别的冲突结果，SSE 采用 reset 事件），展示覆盖范围并重取基线；不能从现存第一条悄悄继续。reset、历史翻页、回填和组计数更新均不自动响铃。

自动 received/rendered 观察使用稳定的事件/主体/profile/展示种类键，重复提交只幂等确认；显式用户动作保留其操作 ID。收到自身的回执、已读或声音状态变更不再生成一次发生、气泡、声音或相同观察，避免回执驱动渲染再上报的循环。首次快照、reset 和历史回查也不作为新气泡候选。

## 6. 阅读、处理和手机停止语义

| 动作/事实 | 新通知中心语义 | 对手机的影响 |
| --- | --- | --- |
| 网页接收 | 客户端接收并应用变更 | 无 |
| 网页渲染 | 已挂载且满足约定的可见页面/元素检查；不代表人已看见 | 无 |
| 查看/标为已读 | 用户打开详情或明确标已读；未读按认证主体保存 | 无 |
| 标为已处理 | 用户对该事件的业务处理确认，独立记录 | 无 |
| 停止此事件后续手机提醒 | 明确按钮、明确单事件范围，调用既有停止动作 | 保留旧 `ack_at`/停止后续发送语义 |
| ntfy 接受/设备回执 | 分别来自发送尝试和受认证设备报告 | 不推断网页已读或声音已播放 |

旧 `/api/notifications/{id}/ack`、`/api/notification-actions/{id}/ack` 和设备确认继续执行原停止语义。Android sync 继续使用旧确认状态；新专业图表网页的已读/已处理使用独立观察动作，旧页面过渡期保留的停止按钮必须明确手机停止含义。不得把无法识别来源的历史 `ack_at` 回填为网页已查看或已处理。

专业图表中的“通知”动作直接打开同一图表原生中心，使用 `/advanced-charts/:workspaceId?panel=notifications&event=<event_id>`（无目标事件时省略 event）保留定位/恢复；现有 `panel=alerts` 继续用于规则管理。其他应用页面的通知导航先沿现有 `chartReturn()` 回到专业图表再打开中心，经过现有离开保护。

保留 `/signals`、`/signals?signal=<id>#notification` 和登录 `next` 回跳的兼容性，但不将旧 Signals 页面升级为第二个新中心。可确定为专业图表的深链映射到新中心；旧主页/来源未知的历史深链进入明确标识的兼容详情，保留查询和显式存量手机停止。旧待确认数仅在相应兼容上下文标为“待手机确认”，专业图表中心角标明确为“未读”；查看详情不触发旧 ack。设置页 `/settings/notifications` 与 `/settings/sound` 保持手机策略/网页声音职责和草稿保护。

停止动作阻止后续新尝试，不能撤回已在途或已接受的请求；在途结果仍进入时间线，不覆盖停止事实。组级已读必须固定目标事件集合；不提供隐含“整组停止手机”的快捷确认。

规则与渠道兼容矩阵在 W1 冻结：`notify_web=false` 禁止该告警的即时气泡/声音，但仍可查历史；`notify_ntfy=false` 不创建手机投递；`late_delivery=log_only` 不得因投影/重放重新推送。既有手机静默/重试设置不被网页声音设置覆盖；可回查和可打断用户是两个独立判定。

## 7. 原生展示与启动降级

通知状态属于可信父页面及持久记录，原生侧栏只是一个展示 Adapter。W0 优先验证公共入口；私有 DOM 接入限定固定图表库版本与独立探针，禁止改许可字节。

v1.26.1 适配验收同时覆盖应用菜单、数据中心、规则管理、自选/收藏及排序，不能覆盖其 DOM/page factory、离开保护或返回路由。复用原生外壳时明确规则编辑与通知记录的挂载位置和销毁恢复合同；正常图表最多一个即时通知入口，非图表页面提供回到专业图表通知中心的导航。父页面例外入口只在启动/不可用阶段承担图表通知展示，不作为正常状态的永久固定浮层。W0 验证现有 v31.1.0 适配预期及实际库构建标识，不能仅凭源码中的版本检查宣称探针通过。

展示状态为 `parent_starting → native_ready`，失败转 `parent_fallback`；恢复切回 `native_ready`。父页面在 iframe 不可达、许可 JS/侧栏 chunk 失败和 ready 超时下始终能显示原因、打开可用记录并重试。切换仅迁移展示位置，保留事件 ID、未读和声音消费状态；同一时刻只有一个有效即时展示入口。无原生图表时允许就地错误区这一明确例外，不重新引入角落堆叠。

气泡展示去重与声音、已读和接收游标分开，按主体/profile/event_id/attention_version 持久记录；同一提醒版本的重传、刷新和外壳切换不再弹出。只有新事故/独立告警或明确严重升级可产生新的提醒版本；同事故单纯计数与渠道状态更新不升级。事件尚需排查的就地错误状态可持续显示，不将其重新生成成一次气泡。

气泡不抢焦点，悬停/键盘焦点期间暂停自动消失；入口有名称、未读状态和完整的读屏短句，普通变更集中使用一个适当的 live/status 通道。通知中心支持键盘打开、筛选、详情、Escape 关闭并返回入口；不遮挡焦点，主题和缩放下可读。需要确认的草稿恢复/破坏性操作继续使用明确确认流程；普通成功或等待不打开原生模态。

## 8. 声音消费与诚实的渠道观察

默认继续要求用户显式开启网页声音、浏览器手势解锁和规则允许网页提醒；普通异常默认只作视觉提示，额外声音需显式设置。静音、渠道关闭、回填、首次快照、历史翻页、reset 或仅状态更新均不产生新响铃。只有首次实时发生且服务端记录距估计当前服务器时间不超过 **30 秒**的事件可进入自动声音候选；手势解锁仅考虑仍在此期限的候选，不补响旧历史。服务器时钟估计与客户端单调时间用于期限判断，不能只信客户端墙上时钟。

声音去重键固定为“认证主体 + 浏览器 profile ID + event_id + 声音渠道”，不包含工作区、tab、原生容器或可随意变化的设置版本。不同设备各自消费；同一浏览器各标签页和专业图表展示 Adapter 共用一个消费 Module，旧主页独立自动播放路径退役。IndexedDB 唯一记录为最终去重依据，Web Locks 串行协调已解锁、可见页面的播放竞争；BroadcastChannel 只同步展示。能力不足时显示自动声音受限，不降级为多个页面各自播放。

持久偏好“已启用”与当前 AudioContext“已解锁”分开。现有 `mw.web-sound` 在 W1 定义一次性兼容读取；移除旧 `Shell` 按 signal 列表差异播放的第二条消费路径。图表跨源 iframe 和数据中心向可信父页面提交声音动作，不各自在不同 origin 建立去重存储。原生入口点击的用户激活能否解锁父页面音频必须在 W0 实测；失败时给明确的手动解锁动作及 blocked 原因，不假定 postMessage 等于用户手势，不补响超时历史。

在实际播放前持久预留尝试，再调用音频能力，实现自动尝试至多一次。手势未解锁的 `blocked` 候选尚未预留，可以在有效期内变为可用；预留之后失败、崩溃或结果丢失不自动重试，明确记录 `failed/unknown`。这会在少数退出时漏响，是重复抑制的取舍；如用户明确手动重播，使用新的手动动作 ID 并记录，不伪装成自动补响。

分别记录 `blocked/suppressed/expired/reserved/started/failed/unknown`、原因与时间，不用一个布尔值概括。隐藏页面收到事件不等于网页已显示；AudioContext 已开始不等于用户听到。ntfy 的接受时间来自 `DeliveryAttempt`，设备回执来自具体设备报告；没有回执能力的 ntfy 原生渠道继续标未知，不推断已送达。

## 9. 故障事故、调度与资源预算

幂等传输、单次发生、事故分组分开。分组键由稳定故障码、生产者、业务对象及必要的品种/周期/工作区身份组成，不以错误文本为身份。每次真实失败尝试或新状态转换可形成发生事件；渲染、轮询快照和重传不增加次数。同一事故保留逐次事件、首次/最近发生和准确计数；业务告警的规则/版本/触发次数始终是独立发生，不能被普通故障分组合并吞掉。

明确恢复会关闭事故；恢复后的新故障创建新 `incident_id` 并可重新提示。没有恢复证据时，静默超时只能标“未再观察/状态未知”，不能宣称恢复。严重级别升级可重新提示，组更新本身不触发同一原始事件的再次响铃。计数展示注明事故及留存窗口；已有明示缺失时给出保留次数/缺失范围，不冒充全量精确计数。

单气泡按严重级别优先，同级按发生顺序；普通成功不抢占严重消息。普通成功约三秒、故障约八秒后收起，焦点/悬停暂停；入口未读与中心记录不依赖气泡时长。超出可展示队列时显示严重级别摘要和剩余数量，原始已接收事件仍在中心。

以下为初始可配置预算，W0 以测量确认，W1 固定到验收配置清单；调整需说明实测原因和影响，不能以“合并显示”代替存储预算：

| 资源 | 初始预算与到限行为 |
| --- | --- |
| 浏览器单事件 | 16 KiB；完整后台证据按引用读取；超限明确拒绝并提示精简 |
| 本机待同步 | 每主体最多 1,000 条或 10 MiB，保留七天；到限/过期明示未保存范围，不静默声称完整 |
| 浏览器入口 | 每主体/profile 每分钟 60 个新事件，突发 120；重复 ID 不重复计数；限流返回重试时间，本机保留待同步；不限制后台已提交告警 |
| 呈现 | 内存最多 200 个摘要、按需详情；气泡队列 20 个引用，溢出作摘要，不丢服务器事件 |
| 投影/补拉 | 每批/页最多 100 条，API 允许上限 500；批间让出资源，SSE 与轮询使用同一有界补拉 |
| 服务端留存 | 投影/逐次发生默认 30 天，变更日志七天；到期明确 tombstone/reset；原始告警证据按既有策略保留，不被中心清理 |

通知上报失败不产生递归事件；连续自动重试采用退避。源变更处理凭据与来源日志的安全清理优先于普通留存预算。验收记录实际吞吐、积压/恢复耗时、DB 增长、浏览器内存与交互延迟；W0 固定测试机/负载和可接受阈值，不能只证明有限样本“没有崩溃”。

量化预算至少包含真实多图/多指标、快照反复恢复、标签页/路由切换和行情持续更新下的稳态空闲、正常流量与故障积压三类。来源日志和投影保留分别核算；需求 heartbeat、快照刷新和自选 DOM 更新不能造成与行情频率成比例的通知写入。投影 worker 停止/积压/恢复应有可观察的健康状态，但其故障上报不能反过来依赖正在故障的投影器。
