# 交易日历维护

FX/黄金保持纽约 17:00 切日，BTC 保持 UTC 00:00。休市覆盖改变是否有交易机会，不改变 K 线分桶边界。当前每周基础时段与明确配置的休市区间共同判断；没有数据不会自动生成休市日期。

## 配置格式

配置文件是 JSON，包含 `revision` 和 `closures`。每个闭市区间包含：

- `start`、`end`：带时区、整分钟的 ISO 时间，区间为 `[start,end)`。
- `reason`：提前收市、公共假日、临时维护等原因。
- `source`：能验证该品种、平台和适用实体的公告 URL。

日期必须来自可核验的一手公告。官方核验现状见 [OANDA 日历证据](oanda-calendar-sources.md)。已应用 deploy/calendar-xauusd-2026.json：五个已核验黄金假日的明确休市内部区间，不代表完整常规维护/重开时段表。空 profile 代表只有周常规则，不代表全年假日已覆盖。

## 应用步骤

1. 安排维护窗口，取消该品种活动监控，停止 API、实时和历史 worker；保留数据库备份。
2. 将核验后的 JSON 保存为例如 `deploy/calendar-eurusd.json`。确认所有区间不重叠、没有价格观测与闭市区间冲突。
3. 在仓库根目录执行预检：

```bash
.venv/bin/python -m alerts.calendar_admin --instrument EURUSD --file deploy/calendar-eurusd.json
```

4. 核对报告后添加 `--apply` 执行。命令会保存旧/新版本审计，将受影响的已合成 K 线标为待核查，并建立高优先级重取任务。旧信号记录不改动。
5. 重启服务，等待受影响任务完成、K 线完整，再新建监控。图表标题可查看日历版本和来源。

相同版本不得改内容；修改时使用新 revision。存在活动监控时拒绝应用。行情之后若返回与配置休市区间冲突的 M1，会报错并停止本批写入，应核对公告而非强行忽略行情。

## 判断规则

- 完整闭市的交易日会被“前一交易日”查询跳过。
- 提前收市但仍有交易分钟的日期仍算前一交易日；日 K 线必须达到完整性要求。
- 全部间隔均为明确休市时，监控不误报数据缺口。未知的空区间仍保守暂停。
- 明确休市区间与 H4 相交，或夏令时造成尾段不足四小时，该 H4 不参与触发；清除准备状态，待正常 H4 重新积累。页面可显示“已跳过休市缩短的 H4”。
- 演练创建时保存完整日历快照，定位产生的新分支继承快照。之后修改品种日历不会改变旧演练。旧演练默认空快照，继续使用原来的周常规则。
- 日历证据来源、变更审计、信号快照用于追溯；不是保证供应商每个营业分钟都报价的承诺。
