# 原生图表完整接入：功能清单与实施方案

日期：2026-09-29
基线：feature/advanced-charts / d5d3bea，授权 TT v31.1.0。
状态：需求已确认，正在独立开发与本机 Docker 验收；本文件定义范围，不表示所有条目已完成。当前证据见 advanced-charts-capability-inventory.md 与 advanced-charts-delivery-gaps.md；未切换生产。

## 1. 已确定的方向

- 使用库原生 UI、菜单、工具栏、面板和布局，保留原生中文及深浅色。
- 图表分析、指标、工作区/设置尽可能完整接入；行情复用公开 Datafeed 协议与适配机制。
- 交易终端、策略执行/回测本轮不接入。现有 market-watch 后台预警、演练和 ntfy 继续运行。
- 不把 TradingView 网站独有产品当作本库能力，不添加仿制 Pine Editor/策略测试器/回放按钮。
- 未接入功能通过公开接口显示不可用及原因，不能用假数据、假成功、空白面板冒充接入。
- 独立开发页面与表；保留 Lightweight Charts 入口，不覆盖原工作区、不改生产默认入口。

## 2. 原生UI原则及不可用入口

移除当前验证版自制的顶部工作区按钮条，改用库原生保存、加载、重命名、另存等流程。桌面页面由原生图表填满，不嵌入守望侧栏，不重排工具位置。现有登录由可信父页面处理。

保持原生外观不等于把所有feature flag设为true：有些开关改变数据语义、禁用互相冲突，或依赖外部服务。按能力表配置。

不可用状态：

1. 原生API支持disabled：置灰，使用原生提示或可访问的原因说明。真正disabled控件不会收到普通点击事件，不能同时承诺“原生禁用且点击弹窗”。
2. 有公开动作拦截但无disabled：保留入口，点击原生通知对话框说明“暂未接入”，阻止业务执行。
3. 只有隐藏开关、无公开禁用/动作拦截：按用户明确要求保留入口，不自行隐藏。逐项记录原生位置、现有点击行为、未接入原因及接口限制，供用户验收后决定是否隐藏；不能把不可控入口写成已经实现置灰/提示。不修改压缩包、不跨iframe硬改DOM、不覆盖原生工具栏造同款按钮。后台和消息桥不提供未授权操作；若入口本身依赖缺失模块而无法呈现，应列为未能保留的技术阻碍，不伪造原生功能。
4. 缺少模块文件：提示组件缺失/待补包，而非行情加载失败；阻止反复请求。资源修复须来自同版本完整包，不给其他hash文件改名冒充。

每个入口验收记录：原生位置、能力状态、依赖、公开控制API、点击结果、保存方式。交易相关已有入口同样以保留可见为目标，呈现未连接/未接入状态；不注入演示经纪商虚构资金或订单。无法通过公开接口保留的入口单独列出，不宣称已完整实现。

### E. 暂不接入

交易终端/Broker执行、账户资金、下单改单撤单、订单簿；库内交互式策略/回测/Bar Replay；图上创建预警；新闻和经济日历等未备好数据的服务。

现有守望策略、历史演练、通知继续从原工作台使用。多空盈亏比绘图属于A08，不能因“不接交易终端”而一并关闭。

## 4. 实施结构

授权静态库独立来源 → 官方公开Datafeed/存储/设置适配器 → 白名单消息桥 → 已鉴权market-watch API → 原行情与新增图表存储。

新增适配器按职责拆分：capabilities（可用性）、datafeed、quotes、save-load、settings、python-studies。跨来源桥只传明确操作和有限数据；不把任意URL、SQL或通用HTTP代理能力交给第三方库。

库文件只安装不修改；现有采集/分桶/策略不重构。适配器由TypeScript类型约束。第三方示例仅作参考，核心库哈希清单用于升级比对。

存储建议：复用advanced_chart_workspaces；新增用户级advanced_chart_templates（kind区分study/drawing/chart，drawing附tool）、advanced_chart_settings、按需要新增advanced_chart_drawings。新表独立迁移，验证开发库后再进入生产流程。工作区、模板、设置各自版本控制，处理多窗口覆盖；数据库备份清单包含新增表。

## 5. 实施顺序与交付

**顺序调整（2026-09-29）**：根据试用发现的历史供数问题，实际执行以[行情服务专项方案第10节](market-data-on-demand-plan.md#10-本次总体实施顺序)为准：先性能基准、批量补数与Datafeed闭环，再动态品种，随后完成下列原生UI/存储/全量工具工作。原P0–P4保留为工作包说明，不再代表原先的先UI后行情顺序。

### P0 能力与包完整性核对
- 固定授权包/版本/hash；清点实际原生菜单和动态资源。
- 为所有入口形成可用/未接入/缺文件/不适用记录；逐一验证禁用或提示的公开控制点。
- 产物：菜单矩阵、缺文件清单、原生UI例外清单。不以大量未经验证的开关作为“完整接入”。

### P1 原生界面与存储
- 移除验证版额外顶部条；恢复原生保存加载、对象树、数据窗口、比较、模板等。
- 实现D01-D07，迁移旧tv31保存数据；设置服务准备好后再开放依赖它的收藏/模板入口。
- 产物：原生界面可以完成工作区日常管理，刷新/重新登录恢复。

### P2 行情与指标补齐
- 重构现有桥接为类型明确的适配器，补Quotes；完善分页、修订、缓存和8图负载。
- 验证图表类型/指标真实数据条件；补Python精度、输出样式及口径测试。
- 产物：三品种九周期、多图、比较、自选与指标可用；未具备数据的功能说明原因。

### P3 工具全量验收
- 画线分类逐一检查，不只测最初八类；对象树、分组、模板、跨周期和删除恢复。
- 验证全部实际布局、同步、图表设置、快捷键、截图；数据导出按用户确认的自研CSV方案验收，不再等待完整包。
- 产物：逐项验收表+已知限制，桌面与手机只读体验。

### P4 回归与切换准备
- 原行情、预警、演练、ntfy回归；不以真实下单或无授权外发作为测试手段。
- 开发机供用户验收；准备独立HTTPS静态来源、CSP、安全桥验证、新表备份、旧入口回退。
- 正式切换是后续部署步骤，本方案本身不执行部署或推送远端。

## 6. 验收门槛

1. 无自制第二套顶部工具栏、侧栏或原生组件DOM补丁。
2. 原生菜单每项有明确状态；未接入动作不会悄悄执行、发外部请求或返回假成功。
3. 工作区新建/改名/另存/删除/切换/恢复；模板三类及收藏/设置跨会话保存；多窗口冲突及手机只读验证。
4. 同工作区同品种跨周期绘图一致、不同工作区独立；复制不串改。
5. 三品种九周期OHLC、时区标签与原后台对照；节假日、夏令时、历史缺口/修订覆盖；合成图单独验证，不能与普通K线混为一谈。
6. 8图及多指标持续使用不会无限增长请求/内存；一次底层请求尽可能服务多个订阅；原监控链路不受影响。
7. Python指标输出逐值对照后台，包含预热、缺失、多输出和参数修改；内置指标按其自身口径工作。
8. 截图成功、导出资源完整或明确不可用；没有第三方成功外连，库尝试外连与CSP拦截分别记录。
9. 未通过项目保留具体限制，不以“图表能打开”代替完整验收。

## 7. 当前已知限制与默认决策

- 当前包缺少原生导出及样式保存对话框的部分动态文件。用户已确认自行实现替代：顶部“导出 CSV”和“保存样式”已接入；原生缺件入口保留并在“使用说明”解释。CSV包含行情及所选Python指标，不含原生内置指标值。不再以补包作为交付前置条件。
- 暂无官方原始包作真实性比对；授权已由用户确认，运行隔离继续保留。
- 原生UI尽量完整；自选/详情作为行情显示配套纳入；布局按原生最多8图验收。
- 实际画线按工作区隔离；模板和个人偏好按用户共享。
- 用户已明确：原生待实现入口保留，便于掌握待办范围；隐藏只能在后续验收明确同意后进行。无法公开禁用/拦截的入口记录实际行为与限制，后台仍不执行未接入操作。
- 当前剩余工作以[当前交付核对](advanced-charts-current-acceptance.md)为准；用户操作与数据边界见[图表使用与限制](advanced-charts-user-guide.md)。

## 8. 用户最终澄清（2026-09-29）

1. 未接入原生入口保留，不自动隐藏；后续验收认为不需要时再隐藏。
2. 开放最多8图。
3. 接入右侧原生自选列表、报价详情、数据窗口，先支持现有三品种。
4. 实际画线按工作区隔离；指标模板、绘图样式模板、图表样式模板、收藏和个人偏好跨工作区共用。
5. 手机继续只读；允许临时切换品种/周期和缩放，不保存这些修改，不覆盖电脑工作区或共用偏好。

以上明确答复优先于早期最小范围清单及方案原先的隐藏建议。
