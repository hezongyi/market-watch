# 图表对照验证与指标维护建议

日期：2026-09-29。独立原型验证，尚未开发正式工作区、未部署、未修改既有监控/预警/演练功能。

## 结论

**不建议直接使用原版 KLineChart Pro 作为新模块基础。当前优先推荐独立模块使用 Lightweight Charts 5.2.1＋固定版本的 Line Tools 插件；KLineChart 10核心为保留方案。** 这调整了纯资料调研时优先KLineChart的倾向，依据是用户把十字线/时间范围同步、完整八类工具列为刚需，且自定义指标希望长期使用Python维护。

这不是宣称Lightweight Charts全方面优于KLineChart，也不表示原型已达到生产验收标准。社区绘图插件新增了7个仓库的维护责任，必须固定提交、保存许可证并针对更新进行验证。未来若更重视前端内置指标体系和较少的外部绘图依赖，KLineChart核心仍有价值。

## 指标长期维护方案

### 推荐：Python计算，图表显示

当前系统`backend/alerts/indicators.py`基于TA-Lib、版本化注册，输出最新的Reading用于预警。图表需要完整历史序列，不能直接复用最新Reading当作一条曲线。正式实现新增历史序列输出层，保留当前预警协议。

建议每个指标声明：

- `id`、`version`、参数schema及默认值、warmup需求。
- 输入数据与价格口径：品种、周期、Bid/Last、NY17/UTC0、完整性。
- 输出图层：线/柱/区域、主图/副图、颜色/精度/参考水平线。
- 计算函数：使用numpy/TA-Lib或自定义Python，返回timestamp对齐的序列；warmup不足返回null，不补零。

常规新增指标只添加Python计算与元数据，通用前端渲染器按图层定义展示，无需针对每个指标修改图表组件。复杂形态、交互热图或特殊绘图仍需要前端TypeScript扩展；不能承诺任何Python算法自动得到完整图形界面。

同一指标用于预警和图表时应共享算法版本、参数及历史初始化规则。现有SMA可从相同计算函数派生最新Reading；EMA/RSI等递推指标必须固定预热和缓存策略，避免图表长历史与预警短窗口造成数值不一致。复盘不能读入未来数据。

### 不依赖Pine Script

这两种开源路线都不提供完整Pine Script运行环境。本项目以Python作为长期自定义指标语言；前端内置指标可作显示工具，但未经数值口径校验不能直接当作后台预警的真值。

现有行情模型没有统一真实交易量字段，外汇/黄金也不是集中交易所成交量。第一版不能将缺失volume填0后宣称支持可靠的VWAP/OBV等成交量指标。

### 维护与升级

- 图表适配器包住引擎，业务工作区/绘图规范与指标算法分离。
- 插件只安装所需7个固定版本；MPL/Apache的LICENSE/NOTICE保留；不将上游分支自动拉入生产。
- 工作区与画线格式带schemaVersion；插件专用样式允许存原始字段，但保存稳定的id/time/price及来源版本，升级前验证恢复。
- 行情与指标请求跨分屏去重；缓存按品种/周期/指标版本/参数/行情修订区分。将Python计算放后台，浏览器不重复计算所有图表。
- 本地Git保留原型实验和版本证据。正式模块另开开发分支，不把这份演示代码直接部署。
