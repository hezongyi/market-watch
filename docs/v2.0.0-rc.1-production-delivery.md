## 每日备份的既有问题

每日自动数据库备份在本次升级前已连续发生 `TimeoutExpired`。`alerts.backup.pg_tool()` 为 pg_dump/pg_restore 固定设置 900 秒超时；此次发布初次走同一入口也超时。之后独立完成未压缩发布备份及完整恢复验证，因此本次发布有可恢复的数据备份，但自动备份健康状态仍为 failed。

独立发布备份脚本没有写入 `backup_completed` 审计；本次不手工覆盖失败状态，也不将其描述为每日自动备份已修复。后续任务见 [自动备份超时排查](issues/automatic-backup-timeout-20261028.md)。压缩成本、存储吞吐和数据增长各占多少耗时尚未分别测量。

每日 cron 仍在 Unraid 主机时间 03:00 调用原 `deploy/unraid-backup.sh`，入口现已通过 `deploy/active-release` 选择新发布的 `compose.sh`，使用固定候选 backup 镜像。配置归档入口兼容 `-rc.1` 发布目录，并排除镜像传输包。旧入口脚本及旧 active-release 保存在新发布的 `rollback/`。下一次每日数据库备份的成功尚未验证；更新入口并不改变 900 秒限制。

更新后的配置归档已生成并核验 SHA256，Ubuntu 恢复了所选配置文件并与在线文件逐字节比较。详见 [配置恢复记录](verification/v2.0.0-rc.1-production/configuration-restore.json)。私有 env、数据库、完整浏览器状态和未脱敏日志不入库。
