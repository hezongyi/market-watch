# 原生视窗历史储备实施与验收要求

基线 v1.5.2（5dd196e），分支 `feat/native-viewport-history-buffer`。本方案承接
2026-10-03 的隔离实验及用户“体验优先”的选择，修订旧平台缓冲方案中
“不接入连续视窗检查、不修改许可图库、四图非焦点不提供任何储备”的范围。
旧协议的真实需求、覆盖、新鲜度、容量和供应商额度规则继续有效。

## 必须交付的行为

1. 用每个可见图表的原生视窗变化事件检查左侧储备，不依赖焦点；按 RAF 合并。
   默认低于两屏补充一屏；快速向历史侧拖动或读取超过约 800ms 时使用三屏阈值、
   两屏批量，保持十秒后再根据活动决定是否降档。屏数按实际宽度/柱距计算，
   一屏最多 2000 根，储备批量最多 4000 根。
2. 优先将原生适配器已有缓存加入主序列和时间轴；PG 新数据返回后通过同一
   原生路径补入，不等松手，不 reset、不微调间距、不主动裁剪已加载历史。
   不新建重复前端历史缓存。可选预取深度不等于整个主序列内存上限。
3. 新的储备读取是显式 PG-only 协议，不扩大 mandatory countBack 来绕过旧多图
   政策。每个可见图都可读取连续缓存；缺缓存只激活已有有限预热，不能直接
   调供应商。普通原生 getBars 仍完成真实必需需求，并按动态屏数限制额外返回。
   保留现有 PG basic1000/depth4000 目标，不改变供应商额度/新鲜度规则。
4. 同品种周期共享适配器缓存与一个储备进行中请求；宿主最多两个储备请求，
   总请求上限仍为四个，可视必需需求优先排队。图表/线程销毁或切换后，旧
   回调不能注入新线程；旧版本储备响应必须丢弃。
5. 指标计算前缀与拖动屏数分开。根据公开原生指标输入中的 Length/Period
   为常见计算窗口预留缓存前缀，最多 2000 根。此值只是可选 PG 储备预算，
   不能替代原生对递归/复合指标真实 countBack 的计算，任何真实必需请求仍
   完整满足。预留原生引擎的两根对齐余量及按前柱着色的额外前缀。
6. 空缓存/部分覆盖不能返回 noData；只有供应商确认的历史终点可以停止。
   一次视窗需求最多四次失败重试或空缓存复查，采用退避/等待；停止后需
   真实视窗移动至少四分之一屏才重新启用。历史终点补完缓存即停止，不循环。
7. 许可 bundle 只在本地/私有镜像内安装最小钩子，原始 SHA256 固定为
   `114428b8dde6eb137fd7ef3bc20ef35882189186c4bd092bb743b64d11682be1`。
   不匹配或钩子锚点不唯一时构建失败；Git 中不存许可文件。必须提供关闭
   开关及逐字节恢复原始 bundle 的方法。

## 验收范围

- 真实许可图库、产品 bridge/网页、实际 HTTP API、独立 PostgreSQL、实际 OANDA
  原始 OHLC，覆盖 1/2/4/8 图、M5/D1、MA200 与画线；逐次原生绘制检查历史
  索引与左侧 K 线像素。非焦点移动不得激活图表，其他图视窗和指标画线保持。
- 实际储备响应 mandatory=0、供应商 HTTP attempts=0，D1 cursor 使用平台交易日
  标签；检验共享请求、预算、边界、错误停止和缓存缺口。
- 人工延迟用于隔离原型补充，必须区分真实产品网络验收与合成数据；证明
  自适应行为时不得把静态升档结果冒充动态切换结果。
- 回归已有布局保存刷新、原生历史观察/修订、周期生命周期、provider 数据与
  service、工作区测试；前端构建、代码检查、许可哈希与回退校验。
- 多图分别及组合验收十字线、时间、时间范围同步，覆盖 2/4/8 图、M5/M15
  跨周期、真实鼠标、焦点切换、同步开启时切换周期、保存刷新。验收实际
  十字线时间标签、时间定位、可视范围及逐绘制历史；不能只检查同步开关。
  原生范围同步按整数柱拟合时允许调整 peer 柱距，时间边界须按周期对齐。
- 完成后提交独立分支，交付验收证据、构建/回退方法和可审查 PR。

## 体验边界

首屏仍优先显示，储备在后台建立。刚加载、刚新增长周期指标、远历史未预热
或突然长延迟时，在储备建立前不能保证任意快速拖动无缺口。连续拖动实验的
通过范围需要记录储备是否已就绪。瞬间跨越有限储备、供应商限流/失败和数据
实际终点同样不能保证无限无感。不要因此延迟首屏或制造虚假 K 线。

正式交付记录见后续验收报告；本文件定义要求，不单独声称已验收。
