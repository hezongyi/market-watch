先把定时简报链路做稳，用涨跌概览作为第一个真实栏目。以后逐步增加指标判断，复用同一套分组、报告与推送能力。

## A 已确认的范围

| 项目 | 当前决定 |
| --- | --- |
| 品种范围 | 你指定的自选分组，跟随成员增删 |
| 发送时间 | 北京时间每天 08:00，Asia/Shanghai |
| 阅读方式 | 手机推送摘要，点击进入 App 看全文 |
| 首期内容 | 最近交易日涨跌概览 |
| 后续扩展 | 按需要逐步增加指标栏目 |
| 四周突破 | 只是设想，暂不实现，也不要求现在定义 |

目前仍是需求分析，尚未启动应用实现。

## B 从第一性原理看框架边界

简报的长期作用，是帮你定期筛选值得查看的品种。观察方法会变化，分组、报告保存和投递始终需要。

因此，公共链路应稳定，具体分析内容可以逐步增加。

```flow LR
定时到点 -> 固定当期分组名单
固定当期分组名单 -> 按需读取行情
按需读取行情 -> 运行已接入栏目
运行已接入栏目 -> 保存当期报告
保存当期报告 -> 推送摘要
推送摘要 -> App查看全文
```

首期使用普通函数和简单栏目注册表即可。新增栏目时，接入计算与输出，复用已有链路。

无需先建设动态插件加载、任意脚本执行或复杂规则编辑器。

## C 一个栏目需要提供什么

| 内容 | 用途 |
| --- | --- |
| 所需行情周期与参数 | 明确读取和计算要求 |
| 本期计算函数 | 得到该栏目的结构化结果 |
| 标题与条目 | 供 App 展示和摘要选取 |
| 行情截至时间与覆盖情况 | 解释结果有效范围 |
| 不可用原因 | 区分失败、缺历史和未命中 |

框架统一提供成员名单、报告窗口和截止时间。行情读取复用缓存与来源请求限制。

一个栏目失败，不应阻止其他栏目正常出报。新增栏目也不应要求重写定时和推送。

## D 首个栏目如何计算

默认使用同源、同口径的最近两根确认日线：

`涨跌幅 =（最近交易日收盘 / 前交易日收盘 - 1）× 100%`

界面写“最近交易日”，并显示实际日期。周一晨报可能采用周五收盘。

不同市场分别展示交易日与行情来源。股票复权和期货换月口径需要保留。

新加入品种，从下一期展示最近交易日涨跌。移出品种，不再进入后续报告。

每期开始时固定成员，期间增删从下期生效。旧报告保留发布时的名单与结果。

没有新行情时，明确显示日期和状态。数据缺失不能被写成没有变化。

## E 以后如何添加指标栏目

新增内容可以按以下顺序接入：

1. 选择已有指标，或补充所需指标。
2. 确定参数、周期和筛选条件。
3. 增加栏目函数，输出统一结构。
4. 注册栏目，验证计算和展示。

四周突破以后可以由指标提供区间或信号。栏目再判断哪些品种命中，并生成简明说明。

指标有数值，不一定已有可直接汇报的事件。仍需明确显示当前状态，还是报告期间新事件。

算法和参数应与图表一致。事件去重与扫描进度，在实际接入事件栏目时增加。

四周突破的定义和参数，目前均不需要决定。

## F 首期完成意味着什么

| 检查点 | 用户应看到的结果 |
| --- | --- |
| 动态分组 | 增删品种后，下一期正确跟随 |
| 定时生成 | 手机关闭时，后台仍可生成晨报 |
| 行情口径 | 显示最近交易日和数据截至时间 |
| 部分失败 | 其他品种照常出报，并显示覆盖情况 |
| 历史保存 | 再次打开，仍是当时发布的内容 |
| 手机通知 | 一份摘要，点击打开对应报告 |
| 投递语义 | 失败有限重试，成功后不反复催促 |
| 扩展边界 | 新增栏目可复用整条公共链路 |

首期每日晨报跑通即可。周报、每四小时简报和具体指标，按后续需要扩展。

代码静态核查表明，行情读取、缓存、指标算法和 ntfy 有基础可复用。简报调度、栏目入口、报告历史与专用投递语义仍需补充。
