```callout warn 已发现重复后台工作
三分钟采样显示，持续占用包含失败重试和元数据写入放大。
实时行情订阅也在运行，本次并非纯空闲测量。
```

## C 已生效候选为何反复失败

```flow
候选已经启用 -> 使用相同请求编号: 后台继续检查
使用相同请求编号 -> 父修订参数已改变
父修订参数已改变 -> 幂等校验拒绝
幂等校验拒绝 -> 保存失败报告
保存失败报告 -> 使用相同请求编号: 仅等待半秒
```

三条任务均出现请求参数冲突。
每条累计重试超过十万次。
另一个十五秒窗口，每条又重试十三次。

## D 元数据如何放大工作量

```flow
再次观测旧分钟线 -> 更新时间戳
更新时间戳 -> 聚合任务
聚合任务 -> 发布已有柱
发布已有柱 -> 增加发布修订
```

十六秒内新增两根 K 线，483 根已有柱发生更新。
其中 397 根严格只改变观测时间。
观测时间是有效证据，修复时必须保留新鲜度语义。

## E 证据边界与优先级

先修复已启用候选的失败重试循环。
再缩小观测元数据更新触发的工作范围。
现场另有十八个实时共享任务，须单独测量订阅成本。

本轮未修改运行配置或业务数据。
线程采样存在读取错误，只用于定位热点。
修复后的 CPU 降幅仍需同负载对照验证。
